# MCP 命令：Codex rust-v0.161.0 的 `/mcp login <name>`、Qoder `/mcp-config` 与五家会话内 OAuth 入口

Codex 官方 Release [rust-v0.161.0](https://github.com/openai/codex/releases/tag/rust-v0.161.0)（2026-10-07T15:58:45Z）在 “New Features” 下逐字写明 “Sign in to MCP servers from an active terminal session with `/mcp login <name>`.”（PR #49290）。固定到该标签提交 `979011409de0a60b52f179721948e65531d26144` 的 `codex-rs/tui/src/slash_command.rs` 里 `SlashCommand::Mcp` 的描述是 “list MCP tools; use /mcp verbose or /mcp login <name>”，该变体在 `supports_inline_args` 分支中，没有为 MCP 子命令单独设枚举项。本仓库 `cmd-mcp` 字段的 Codex 列此前只记 `/mcp [verbose]`，完全没有会话内 MCP OAuth 登录入口。

顺着这条新功能核对五家 `/mcp` 时又发现三处矩阵尚未记录的差异。其一，Qoder CLI 官方 Slash 命令参考在 “Built-in Skills” 分组列出 `/mcp-config`（描述 “Manage MCP server configurations.”），与 “Extensions and Tools” 分组、描述为 “Manage MCP servers.” 的 `/mcp` 并列；本仓库的 Qoder 命令目录与 `cmd-mcp` 列都没有它。其二，Qwen Code 的 `/mcp auth`、`/mcp noauth` 已经不再执行认证，命令源码只返回一条警告把用户导向对话框内的 Auth 动作，而 `cmd-mcp` 的 Qwen 列此前只写 `desc|nodesc|schema`。其三，Claude Code 官方命令表给出的 `/mcp` synopsis 与面板动作比本仓库记录的更完整，包含 **Re-authenticate**、**Clear authentication** 与 `-p` 下的文本状态摘要（需 v2.1.205 及以上）。

因此本次只处理 `cmd-mcp` 一个字段：补录 Codex 的 `/mcp login <name>`，并按同一口径把五家 `/mcp` 的子命令、参数、可用模式、保存范围与会话内 OAuth 登录入口对齐。Server 配置的作用域、传输集合与文件位置仍归 `extension-mcp`，本次没有改动那个字段。

Codex 的行为细节取自源码与 PR 说明。`codex-rs/tui/src/chatwidget/slash_dispatch.rs` 中不带参数的 `/mcp` 走 `add_mcp_output(McpServerStatusDetail::ToolsAndAuthOnly)`；带参数时先对整串做 `eq_ignore_ascii_case("verbose")` 比较后走 `McpServerStatusDetail::Full`，否则按第一个空格 `split_once(' ')` 解析 `login <name>`（`login` 大小写不敏感、Server 名 `trim()` 后不能为空），有 `thread_id` 时发 `AppEvent::StartMcpLogin { name, thread_id }`，没有活动会话报 `MCP sign-in requires an active session.`，其余形状报 `Usage: /mcp [verbose | login <name>]`。PR #49290 说明该命令经 app server 请求登录、在浏览器打开授权 URL、把成功或失败显示在发起命令的 thread，并守卫重叠启动请求、按 Server 跟踪登录尝试以免过期的重试完成覆盖当前结果、已完成的尝试不再打开浏览器、结果跨线程切换与会话刷新保留。测试快照给出用户可见文案 `MCP sign-in is starting. Wait for it to finish before trying again.`、`Signed in to <name>.` 与 `Unknown MCP server <name>`。TUI 没有 `/mcp logout`；枚举里的顶层 `Logout` 描述是 “log out of Codex”，与 MCP 无关，退出 MCP 授权仍走 CLI 的 `codex mcp logout <name>`。

同时核出一处官方资料不一致：Codex 官方 Slash 命令参考页把 `/mcp` 写成 “Open MCP status to view connected servers.”，既不列 `verbose` 也不列 `login`；`/mcp verbose` 与 `/mcp login <name>` 只出现在源码、Release 说明与 CLI 命令参考里。本仓库按已发布的 Release 与固定 SHA 源码记为“官方确认”，并在条件里写明参考页尚未同步。

其余四家的本次核对结论：Claude Code 最新 Release 为 v2.1.293（更新日志提交 `79babc372d64`），其中没有 `/mcp` 或 MCP 认证入口的变化，同版新增的 Claude Haiku 5.5 默认 Haiku 模型、`subagentStatusLine` 的 `agentType` 与 mods `$.tool.register` 的 `isDeferred` 属其他能力字段，本次未处理；Qwen Code 最新发布为 v0.25.1-preview.0（2026-10-06），发布说明只有 `/context detail` 的 MCP 行归属修复与 MCP Server 规则不得授权同名冲突 Server 的修复，`mcpCommand.ts` 在 v0.24.7 与 v0.25.1-preview.0 逐字节相同；Kimi Code 仓库最新提交仍停在 2026-09-30 的 `21406fb4c805`、最新 Release 仍为 2.1.1（2026-09-24），`/mcp` 与 `/mcp-config` 的文档表述没有变化；Qoder CLI 公开 Release Notes 最新三条仍为 CLI 1.1.63（2026-09-24）、1.1.62、1.1.61，都没有 MCP 或认证相关条目。
