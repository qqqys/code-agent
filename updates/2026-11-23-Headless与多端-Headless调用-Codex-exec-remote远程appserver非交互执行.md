### 1. Codex：`codex exec --remote <ADDR>` 随 rust-v0.171.0 进入正式 Release

发布坐标：rust-v0.171.0 于 2026-11-20T00:44:47Z 发布（附注标签对象 `295eca93394bb83a6ec8e0841033f3997f97fcbd`、指向提交 `ccf9be8cc458bd6b8336fe84d68d8893f2691a5e`），New Features 段逐字为 “Added `codex exec --remote <ADDR>` to start or resume noninteractive sessions on an existing app server. (#61707)”。功能由 PR #61707（标题 “Support remote app servers in `codex exec`”）实现，2026-11-16 合入 main，合并提交 `e51c551fb406486afb7ef5c3d43387f1be3c09e8`（作者时间 2026-11-15T23:39:49Z、提交时间 2026-11-16T00:02:00Z，内部 RevId `d4c3b16fb80eb6e8c523aff92110eaa878cbd3ee`），9 个文件改动、新增 `codex-rs/exec/src/remote.rs`（+148 行）。PR 说明逐字为 “Allow `codex exec --remote <ADDR>` to run a noninteractive turn using an existing app server's configuration and credentials. Support starting a new thread or resuming one by UUID, with human-readable or JSON output and optional bearer-token authentication through `--remote-auth-token-env`.” 与 “Accept remote options before or after `exec`, and reject conflicting endpoints. Reject unsupported agent configuration overrides and active threads, and report an error if the server disconnects before the turn completes.”

旗标定义（`codex-rs/exec/src/cli.rs`，11,470 字节）：`--remote` 与 `--remote-auth-token-env` 直接定义在 exec 的顶层 `Cli` 结构上，`#[arg(id = "exec_remote", long = "remote", value_name = "ADDR", global = true)]` 与 `#[arg(id = "exec_remote_auth_token_env", long = "remote-auth-token-env", value_name = "ENV_VAR", global = true)]`，doc comment 逐字为 “Connect to an existing app server.” 与 “Environment variable containing the remote WebSocket bearer token.”；`global = true` 即两个旗标写在 `exec` 之前或之后都被接受，帮助文本快照（`exec_args_tests.rs`）逐字为 “--remote <ADDR> / Connect to an existing app server”。该文件内没有这两个旗标的冲突校验（`conflicts_with_all` 只出现在 `ReviewArgs`）。

端点合并与冲突（`codex-rs/cli/src/main.rs`，181,740 字节）：`Subcommand::Exec` 分支先比较根级（`codex --remote … exec`，来自交互侧 `InteractiveRemoteOptions`）与 exec 级两处取值，都给且不同时逐字报 “`codex exec` received conflicting remote server endpoints”，随后 `exec_cli.remote = exec_cli.remote.or(root_remote)`、token 环境变量同理合并，并继承根级 `-c` 配置覆盖与 `strict_config` 后进入 `codex_exec::run_main`。交互侧 `--remote` 的 doc comment 逐字为 “Connect the TUI to a remote app server endpoint. Accepted forms: `ws://host:port`, `wss://host:port`, `unix://`, or `unix://PATH`.”；不支持远程模式的子命令仍经 `reject_remote_mode_for_subcommand` 报 “`--remote {remote}` is only supported for interactive TUI commands, not `codex {subcommand}`”。

远程分支入口（`codex-rs/exec/src/lib.rs`，97,496 字节）：`run_main` 开头逐字为 `if let Some(endpoint) = codex_app_server_client::resolve_remote_endpoint(cli.remote.clone(), cli.remote_auth_token_env.clone())? { return remote::run(cli, endpoint).await; }`，即带 `--remote` 时整个非交互运行改走远程分支；本地路径的 `Cli` 解构以 `remote: _`、`remote_auth_token_env: _` 丢弃这两个字段。

地址与 token 解析（`codex-rs/app-server-client/src/remote_addr.rs`，4,782 字节）：`resolve_remote_addr` 只接受四种形式——`unix://`（空路径）经 `find_codex_home()` 与 `app_server_control_socket_path()` 解析为 CODEX_HOME 下的默认控制 socket（解析失败报 “failed to resolve CODEX_HOME”）、`unix://PATH` 相对当前目录解析为绝对路径、`ws://host:port` 与 `wss://host:port`（要求有 host、显式端口（含显式默认端口 80/443）、路径恰为 `/` 且无 query 与 fragment），其余一律报 “invalid remote address `{addr}`; expected `ws://host:port`, `wss://host:port`, `unix://`, or `unix://PATH`”。`resolve_remote_endpoint` 的 token 规则：给了 `--remote-auth-token-env` 而没有 `--remote` 报 “`--remote-auth-token-env` requires `--remote`.”；端点是 Unix socket 或非 `wss://`、非回环 `ws://` 的 WebSocket 报 “`--remote-auth-token-env` requires a `wss://` or loopback `ws://` remote.”；token 按环境变量名读取并 trim，未设置报 “environment variable `{env_var_name}` is not set”、trim 后为空报 “environment variable `{env_var_name}` is empty”。

远程回合实现（`codex-rs/exec/src/remote.rs`，5,479 字节）：文件头注释逐字为 “Execute a noninteractive turn on an existing app server, using its configuration and credentials.”。入口 `anyhow::ensure!` 一次拒绝 21 项本地覆盖——`--trust`、`--ignore-user-config`、`--ignore-rules`、`strict_config`、`--ephemeral`、`--thread-source`、`--cyber-access-program`、`--output-schema`、`-c` 配置覆盖（`raw_overrides` 非空）、`--image`、`--model`、`--oss`、`--local-provider`、config profile v2、`--sandbox`、`--approve-for-me`、`--dangerously-bypass-approvals-and-sandbox`、`--dangerously-bypass-hook-trust`、`--cd`、`--worktree`、`--add-dir`——违反时逐字报 “--remote currently supports only prompt, resume by UUID, and output options; configure the agent on the server”，即远程模式下模型、沙箱、目录、Worktree 等 agent 配置只能在服务端改。命令形状只有两种：不带子命令时发 `ThreadStart`（`approval_policy: Some(AskForApproval::Never)`）新建线程；`exec resume` 要求 `!args.last && !args.all && args.images.is_empty()` 且 `session_id` 能按 UUID 解析，否则报 “remote resume requires a thread UUID”，`ThreadResume` 带 `exclude_turns: true`；其他子命令报 “--remote supports exec and exec resume”。目标线程状态为 `ThreadStatus::Active` 时报 “remote thread already has an active turn” 拒绝启动。随后 `processor.print_thread_started(&thread.id)`：人类可读输出实现逐字为 `eprintln!("thread id: {thread_id}")`（stderr 头行），JSONL 输出发出带 `thread_id` 的 `ThreadEvent::ThreadStarted` 事件；`TurnStart` 带 `turn_trigger: Some("exec")`、`approval_policy: Some(AskForApproval::Never)`、输入只有一条 `UserInput::Text`，收尾走 `finish_turn` 并挂 Ctrl+C 中断通道。连接参数为 `client_name: "codex_exec"`、`required_human_approval: false`、`experimental_api: true`，即远程 exec 不会停下来等人批准。可用的输出选项是 `--json`、`--color` 与 `--output-last-message`（`BoundOutput::open`）；线程的 `ephemeral` 与 `history_mode` 由服务端返回。

传输层（`codex-rs/app-server-client/src/remote.rs`，45,434 字节）：`RemoteAppServerEndpoint` 分 `WebSocket { websocket_url, auth_token }` 与 `UnixSocket { socket_path }`；Bearer token 只在 `wss://` 任意主机或 `ws://` 回环主机（`localhost` 大小写不敏感、IPv4 与 IPv6 loopback）时允许，允许时握手请求加 `Authorization: Bearer <token>` 头（头值非法报 “invalid remote authorization header value: {err}”），不允许时报 “remote auth tokens require `wss://` or loopback `ws://` URLs; got `{websocket_url}`”；UDS 上的 WebSocket 握手固定用 URL “ws://localhost/rpc”；连接与 initialize 超时各 10 秒（`CONNECT_TIMEOUT`、`INITIALIZE_TIMEOUT`）、WebSocket 消息与帧上限 `128 << 20`（128 MiB）、请求总带 zstd 压缩头；服务器在回合完成前断开时按 “remote app server at `{endpoint}` disconnected: {reason}” 一类错误回报（PR 说明的 “report an error if the server disconnects before the turn completes”）。

集成测试（合并提交内 `codex-rs/cli/tests/queue.rs` +76/−2）：断言人类可读输出 stderr 含以 “thread id: ” 开头的头行（快照 “thread id: [thread-id]”）、JSONL 事件流含 `turn.completed`、新建线程的 `thread_id` 与被恢复线程不同、resume 后线程共有 2 个 turns，端点冲突时 stderr 含 “conflicting remote server endpoints”。

文档缺口（2026-11-23 核对）：官方 CLI 命令参考 `.md` 变体（`https://learn.chatgpt.com/docs/cli/reference.md`，56,114 字节）的 `globalFlagOptions` `--remote` 行仍逐字为 “Connect to a remote app-server endpoint over WebSocket or a Unix socket. Supported for `codex`, `codex agents`, `codex queue`, `codex resume`, `codex fork`, `codex archive`, `codex delete`, and `codex unarchive`; other subcommands reject remote mode.”，`codex exec` 的旗标表（`execOptions`）没有 `--remote` 也没有 `--remote-auth-token-env`，即 “other subcommands reject remote mode” 与 rust-v0.171.0 已发布行为不一致；官方 Non-interactive mode 页（HTML 464,282 字节）全页没有 `exec --remote` 条目，唯一涉及 remote 的句子逐字为 “You can use `CODEX_API_KEY` with `codex exec`, `codex review`, the TypeScript SDK, and `codex exec-server --remote`.”，其中 `exec-server` 是 `main.rs` 枚举里另一独立子命令（“[EXPERIMENTAL] Run the standalone exec-server service.”）、与 `codex exec --remote` 无关。故本条按「Release 与源码已确认、官方文档未同步」记录。

Surface 边界：`codex exec --remote` 的回合在 app server 所在进程与主机执行，文件与命令发生在服务端工作区，这与本地 `codex exec`「文件与命令仍发生在调用进程的工作区」不同；它也不是 Codex Cloud。目标服务端可以是 `codex app-server --listen ws://IP:PORT` 监听的端点、`unix://` 指向的本地后台 daemon（`app-server-daemon` 的默认控制 socket）或带 Bearer token 的远程 `wss://` 端点。同版发布说明的 TUI workspace 默认开启（“Enabled the TUI workspace by default…”）与 `/statusline` 的 MCP 状态行提供器（已由 2026-11-17 的 `extension-status-line` 单元处理）不属本字段。
