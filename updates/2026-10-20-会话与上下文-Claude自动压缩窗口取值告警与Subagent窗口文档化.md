# 手动压缩：Claude Code v2.1.304 让 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 接受 `k`/`M` 后缀并公布三行越界告警，Subagent `autoCompactWindow` 由官方文档化

Claude Code 官方仓库 `CHANGELOG.md`（main 分支，固定到提交 `772c6bee5c36f58be43bbb2b182862aeb22aceff`，2026-10-19T21:34:21Z，只改 `CHANGELOG.md` 与 `feed.xml`）在 `## 2.1.304` 段下逐字写明 “Fixed `CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` silently setting a 100K window: the variable now accepts `k` and `M` suffixes like `--autocompact`, and warns when a value is out of range or ignored”。对应 Release [v2.1.304](https://github.com/anthropics/claude-code/releases/tag/v2.1.304) 发布于 2026-10-19T21:34:39Z。官方两页都已跟进：环境变量页（167,567 字节）的该行现在写 “Set the auto-compact window, how full the context gets before compaction, from `100000` to `1000000` tokens. Suffixed values such as `200k` require v2.1.304 or later.”，模型配置页（120,859 字节）新增了独立小节 “Values and warnings for `CLAUDE_CODE_AUTO_COMPACT_WINDOW`”，用一张三行表把告警文案、会话实际使用的窗口与改法一一对应。这直接推翻了本字段此前记录的一句结论——原记录写「环境变量只接受纯 token 数——`500k` 会被读成 `500` 并夹到 100K 下限」，该说法只在 v2.1.304 之前成立。

同一轮复核还解决了本字段挂着的一处「未确认」。2026-10-09 记录 Subagent `autoCompactWindow` 时，官方 Subagents 页的 frontmatter 字段表还没有这个键，因此把取值范围与它同每模型窗口之间的优先级记为未确认。2026-10-20 复核时该页（108,779 字节）既有字段表行 “Lower the auto-compact window for this subagent to a token count from `100000` to `1000000`. Requires Claude Code v2.1.296 or later”，也有专节 “Set the auto-compact window for one subagent”，并逐字写明环境变量会整个接管该字段、frontmatter 只认纯整数（`200k` 被读成 200 因而超范围、Subagent 仍加载并按字段缺失压缩）、可用 `claude --debug` 搜 `invalid autoCompactWindow` 自查，以及两条「取值在范围内却看不到效果」的原因。模型配置页的设置位置清单也补上了第五项 “**For one subagent**”。剩下仍未确认的只有一点：官方没有逐项列出 frontmatter 窗口与 `--autocompact`、每模型 `modelSettings` 或顶层 `autoCompactWindow` 的组合顺序，只写取值必须低于该 Subagent 本来会继承的窗口才有效果。

顺着「阈值取值怎么写、写错了会怎样」这一层核对其余四家：Codex 配置参考（1,456,078 字节）把 `model_auto_compact_token_limit` 的类型记为 `number`、`model_auto_compact_token_limit_scope` 记为 `total | body_after_prefix`，四行压缩键都没有后缀写法、取值范围或越界告警；Qwen Code 的 `context.autoCompactThreshold` 是大于 0 且不超过 1 的窗口占比，Kimi Code 的 `loop_control.reserved_context_size` 是为模型输出预留的 token 数，两者都只有一种写法；Qoder CLI 没有公开阈值键。也就是说，只有 Claude Code 公布了「同一个阈值可以用几种文本形式写、写错时按哪种规则回落并如何告知用户」。本次只处理 `session-compress` 一个能力字段，能力字段总数维持 115。
