# 会话与上下文：新增定时任务与循环能力字段，四家 CLI 一等入口与 Codex 的 Surface 边界

本次核对发现矩阵此前完全没有字段区分「按时间重复注入提示词」与既有字段覆盖的后台执行、目标推进、跨会话消息与渠道循环，而这一能力在四家 CLI 里都已是官方记录的一等入口：Claude Code 有专页 `Run prompts on a schedule`（`/loop` 与 `CronCreate`/`CronList`/`CronDelete`/`ScheduleWakeup`），Qwen Code 有 `docs/users/features/scheduled-tasks.md` 与 bundled Skill `loop`，Kimi Code 官方工具文档有「定时任务」章节，Qoder CLI 的 Slash 命令参考列出 `/loop` 与 `/crontab` 并另有三份参考页。因此新增 `session-schedule`（定时任务与循环）字段并覆盖五家产品。Codex 是唯一在 CLI 里没有入口的一家：官方 Automations 页在 CLI 与 IDE 分节逐字写明 “Codex CLI doesn't provide the Scheduled management interface. Use ChatGPT web or the desktop app to create and manage scheduled tasks.”，Scheduled 属于 ChatGPT 桌面 App 与 Web Surface，因此按条件项记录而不算作 CLI 能力。五家核对日期保持 2026-10-03。

## 修正

- 新增能力字段 `session-schedule`（会话与上下文域）：在会话内登记一个未来触发条件，到点把一段提示词重新注入对话；触发条件可以是 5 段 cron 表达式、`/loop` 换算出的固定间隔，或模型每轮自己挑选的下次唤醒时刻。矩阵结论分别为 Claude Code “`/loop [interval] [prompt]`（bundled Skill，别名 `/proactive`）· `CronCreate`/`CronList`/`CronDelete`/`ScheduleWakeup` · `.claude/loop.md` 与 `~/.claude/loop.md` · 单会话上限 50 个、周期任务 7 天后末次触发再自删 · `CLAUDE_CODE_DISABLE_CRON=1` 关闭 · 条件：`/schedule`（别名 `/routines`）创建云端 Routines、桌面端另有独立定时任务”、Codex “CLI 与 IDE 扩展都不提供 Scheduled 管理界面；条件：ChatGPT 桌面 App 的 Scheduled（RFC 5545 RRULE、`codex://automations` 深链接、`features.in_app_local_automation` 开关、在本地项目或独立 Worktree 执行）与 ChatGPT Web/移动端的 Scheduled（可按 Gmail、Slack、GitHub 事件触发）”、Qwen Code “`/loop [interval] [prompt] | list | clear`（bundled Skill）· `cron_create`/`cron_list`/`cron_delete`/`loop_wakeup` · `.qwen/loop.md` 与 `~/.qwen/loop.md` · 默认只在内存，`durable: true` 才写入 `~/.qwen/tmp/<project-hash>/scheduled_tasks.json` · 上限 50 个、默认 7 天过期（`experimental.cronRecurringMaxAgeDays`，`0` 关闭过期）· `experimental.cron: false` 或 `QWEN_CODE_DISABLE_CRON=1` 关闭”、Kimi Code “`CronCreate`/`CronList`/`CronDelete`（无 Slash 命令，官方工具说明明确用户没有 `/cron` 自助入口）· 单会话上限 50 个、`prompt` ≤8 KiB、周期任务满 7 天以 `stale` 末次触发后自删 · `[cron]` 配置节与 `KIMI_DISABLE_CRON=1`”、Qoder CLI “`/loop [interval] [flags] <prompt>` · `/crontab` 管理面板 · `.qoder/loop.md` · 持久任务写入 `<project>/.qoder/scheduled_tasks.json`、会话内任务只在内存 · 上限 50 个、周期任务 7 天过期 · `--durable`/`--permanent` 免自动过期 · `--max-turns`/`--max-credits` 预算上限”。
- 能力定义写明触发条件的三种来源，并在“本页不包含”排除厂商云端与桌面端的独立排程 Surface（Claude Routines、Claude Desktop scheduled tasks、Codex Scheduled、Qoder Cloud Mode）、后台 Shell 与后台 Subagent、`/goal` 的目标推进与花费窗口、消息平台渠道自己的循环排程、以及 Hooks 的事件触发与 CI 的 `schedule:` 触发器，避免与 `execution-background`、`agent-background`、`cmd-goal`、`surface-channels`、`execution-ci` 重复。
- 跨产品事实新增七条：只有 Codex 在 CLI 里没有一等入口；Claude、Qwen、Kimi 三家的会话内调度器参数高度一致（5 段 cron、本地时区、上限 50、周期任务 7 天过期、按任务 ID 派生的确定性抖动、只在空闲时触发、错过的触发只补一次）；抖动上限不同（Claude 周期任务最多晚 30 分钟或半个间隔，其余三家最多晚间隔 10% 且封顶 15 分钟，四家一次性任务落在整点半点时都最多提前 90 秒）；默认持久化策略不同（Qoder 与 Claude 写项目内文件、Qwen 默认只在内存需显式 `durable: true`、Kimi 以 durable 事件随会话记录保存）；用户自助程度不同（只有 Qoder 有 `/crontab` 面板，Kimi 明确没有自助入口）；三家提供上下限同为 60–3600 秒的模型自定节奏唤醒而 Kimi 没有；三家支持默认提示词文件而 Kimi 没有。
