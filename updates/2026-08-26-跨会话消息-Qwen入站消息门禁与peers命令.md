# 跨会话消息：Qwen Code 入站跨会话消息门禁与 `/peers`（v0.22.2）

Qwen Code 跨会话消息字段补录 2026-08-26 发布的新能力。PR #9576（“feat(core): accept cross-session messages behind an inbound gate”，追踪 issue #8724 的接收侧步骤）于 2026-08-26T11:51:49Z 合入 main（合并提交 `f9470f570a215616aa364aa174a565d3373df7b8`），随当日 12:57 UTC 发布的 v0.22.2 进入正式通道，发布说明对应条目 “feat(core): accept cross-session messages behind an inbound gate”（GitHub 比较显示 v0.22.2 包含该合并提交且领先 7 个提交）。开启 `agents.crossSessionMessaging`（默认 `false`、标注 Experimental、需重启）后，会话绑定每会话一个的 UNIX domain socket 收件箱（优先 `$XDG_RUNTIME_DIR/qwen-socks/<pid>.sock`，回退临时目录随机 `qwen-socks-<hex>` 目录，目录 0700、套接字 0600，访问控制仅依赖文件系统权限），绑定成功后地址写入实时会话登记表 `~/.qwen/sessions/` 记录的 `ipcPath` 字段，同一台机器上的其他 Qwen Code 会话即以 NDJSON 帧（每行一帧，单行上限 1 MiB）投递消息。入站门禁按 `agents.crossSessionInbound`（`accept`/`hold`/`refuse`，默认未设置）或审批模式对等裁决：逐动作仍需人工审查的接收会话直接投递；YOLO、AUTO_EDIT 或 AUTO 接收会话仅当发送方自述 `fromMode: "bypass"` 才投递，否则保留；审批模式未知或设置不可读时保留（fail-closed）。保留消息模型不可见，由新增内置命令 `/peers` 审查（`/peers accept <id|all>` 放行、`/peers deny <id|all>` 丢弃）；投递的消息包 `<cross_session_message>` 信封（正文 `<` 全部转义）并附固定权限通知。发送侧未接入：`send_message` 不能寻址对等会话，本侧只收不发。v0.22.2 时点的官方命令与设置文档均未列出 `/peers` 与这两个设置键，证据以发布说明与合并提交处源码为准。

Each session binds a UNIX domain socket, accepts newline-delimited JSON frames from its siblings, and — when policy allows — feeds the message into its own input queue as a marked, non-user turn."、"The whole feature is off by default behind `agents.crossSessionMessaging`."、"`send_message` still cannot address a peer, so this side is receive-only"。GitHub API 记录 `merged_at` 为 2026-08-26T11:51:49Z；GitHub 比较 `f9470f570a21...v0.22.2` 状态 `ahead`（v0.22.2 领先 7 个提交、不落后），确认进入 v0.22.2 标签。

- 合并提交处的 `packages/cli/src/config/settingsSchema.ts`：`agents.crossSessionMessaging` 为布尔、默认 `false`、`requiresRestart: true`、类别 Advanced，描述原文 "Experimental.
