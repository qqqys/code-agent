# 交互审批：Kimi Code 三条内置 guard 确认策略与 `[permission] dangerous_command_guard` 总开关

Kimi Code 官方仓库于 2026-10-16 合入 “feat(agent-core-v2): let dangerous_command_guard=false disable all built-in guard ask policies”（[PR #4250](https://github.com/MoonshotAI/kimi-code/pull/4250)，提交 `6e7cc909da9084a424f822dd5a9aae5b98070b73`，2026-10-16T05:23:18Z），把 `config.toml` 里既有的 `[permission] dangerous_command_guard` 从「只关危险命令一项」扩宽为「一次关掉全部三条内置 guard 确认策略」。新增的 changeset `.changeset/dangerous-guard-off-allow-all.md` 标 `"@moonshot-ai/kimi-code": patch`，正文逐字为 “Setting `[permission] dangerous_command_guard = false` now turns off every built-in confirmation guard — dangerous commands, sensitive-file access, and git control-path access — instead of only the dangerous-command guard.”

这条改动暴露出本仓库 `security-approval` 字段的一个实质性缺口：矩阵此前把 Kimi 的交互审批只记成「副作用工具弹出审批面板 + `[[permission.rules]]` 静态规则」，完全没有记录 Kimi 其实有三条具名的内置 guard 询问策略——`dangerous-command-ask`、`sensitive-file-access-ask` 与 `git-control-path-access-ask`，也没有记录那个能整体关掉它们的布尔键。旧记录的证据坐标还固定在提交 `086769bfadf1c86ba0569f16315010ffc77344f0`（2026-07-27T08:47:43Z），比该键进入代码库的 `4b9888b73db5`（2026-08-31）还早一个月，因此这三条策略与开关在任何版本上都不可能被当时的证据覆盖到。旧记录里的模式名也还是 `manual`/`yolo`/`auto`，而官方交互文档现在把三种模式写作 "Always Ask"（原 Manual）、"Ask When Needed"（原 YOLO）与 "Never Ask"（原 Auto），全仓库此前没有任何一处出现 "Always Ask" 字样。

本次把 Kimi 列的证据坐标整体推进到提交 `6e7cc909da90`，并按源码逐条补录三条 guard 的触发面、13 条策略的固定顺序、开关的读取时机与环境变量解析规则、guard 关闭后仍然保留的工具层硬阻断，以及非交互宿主下 `dangerous-command-ask` 整条不入链这一行为。

其余四家本次只核对了与本字段直接相关的官方更新条目：Claude Code 的 v2.1.300（2026-10-14）与 v2.1.301（2026-10-15）里与权限有关的几条分别是 “Changed hooks: `updatedInput` from PreToolUse and PermissionRequest hooks is now validated like Claude's own input: unknown keys are dropped, and input the tool rejects denies the call”、“Changed `PermissionRequest` hooks in Cowork cloud sessions: a `setMode` update in a hook's allow is now ignored; the rest of the approval still applies”、“Changed the `/sandbox` mode options to read "Sandbox commands" instead of "Sandbox BashTool"”、“Removed the `--sandbox` and `--no-sandbox` flags from `claude remote-control`, which had no effect; passing either now exits with an error.” 与 “Fixed the permission prompt for a plugin or skill hook's `ask` decision not showing which plugin or skill the hook comes from”，分别属生命周期 Hooks、Cowork 云会话、`/sandbox` 文案与 Remote Control 入口，都不改变 CLI 交互审批的既有记录；Codex rust-v0.163.0（2026-10-15T21:30:38Z）的 “Resuming a saved thread restores its permissions and network approvals, while respecting explicit overrides and current managed policy.”（#53150、#53419、#53424）属会话恢复对权限状态的还原，本次未展开核对，留作后续研究单元；Qwen Code 稳定 Release 最新是 v0.25.2（2026-10-15T15:41:15Z），Qoder CLI 文档站的 Permissions 页没有同类变化，两家结论不变。

本次只处理 `security-approval` 一个字段，能力字段总数维持 115。五行的核对日期都更新到 2026-10-16，但只有 Kimi 列的结论与证据发生实质变化。
