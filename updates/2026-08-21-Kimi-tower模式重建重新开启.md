# Kimi Code `/tower` 重建为与 plan 并列的模式重新开启

Kimi Code 官方仓库在 2026-08-21 合入 PR #3099（`feat(agent-core-v2): turn /tower into a mode parallel to plan mode`，合并提交 `0f44537c13e7c32b9189e20af7c894c34704be5b`），把 2026-08-18 整体禁用的 `/tower` 多代理 Tower 编排重建为与 plan 模式并列的一等模式重新开启。内置 tower Skill 及其测试删除，编排手册移入新的 `tower_mode` 上下文注入（`features/tower/injection/` 的 full、sparse、exit 三类提醒，去重策略与 plan 模式相同）；十一个 `Tower*` 编排工具改为在进入模式时以工具覆盖层启用、会话恢复时重新应用；`tower_mode.enter`/`tower_mode.exit` 作为可重放 wire 记录持久化，恢复会话不再出现“状态在、工具不在”的分裂。`/tower` 成为内置命令：不带参数或带 `status` 报告状态，`on|off` 显式切换，`teardown` 发送拆除指令（由模型的 `TowerTeardown` 退出模式），其余输入作为目标（先幂等确保模式开启、首次开启提示 `Tower mode: ON`，再把目标作为普通输入发送），v2 引擎无会话时惰性创建会话。关键变化是 `tower` 实验标志（`KIMI_CODE_EXPERIMENTAL_TOWER`，标题 `Tower mode`，`surface: 'both'`，默认关闭）现经 `registerFlagDefinition` 注册进实验功能登记册，`/experiments` 列出该标志，环境变量、`[experimental] tower = true` 或 master 开关都可开启；功能在 App 启动时组装，运行中翻动标志需要重启。协议侧 `AgentStatusUpdatedEvent` 增加 `towerMode`，SDK 增加 `Session.setTowerMode()` 与 `SessionStatus.towerMode`（v1 基座抛 `not_implemented`），kap-server 接受 `agent_config.tower_mode` 并在 `/status` 报告，写入路径会复核模式实际生效、未生效抛 `session.tower_mode_invalid`；TUI 页脚显示 `tower` 徽标。同一仓库的 tower 只允许一个在世持有者会话，其他在世会话持有时进入被拒绝，只能经 `TowerInit` 接管已死持有者的陈旧 tower；fork 出的会话无论标志状态都校验所有权。标志关闭时专门的 `onBeforeExecuteTool` 钩子否决全部 tower 工具；worker 写隔离按 `tower-worker` 身份判定，实验关闭后已派生的 worker 仍不能写主检出或其他 worktree。该提交合入 main 尚未发布：最新 Release 0.38.0（2026-08-20）不含该提交，changeset `.changeset/tower-mode-command.md` 为 minor，0.39.0 发布 PR 尚未合入。官方 Slash 命令文档仍未列出 `/tower`。
