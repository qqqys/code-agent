# 自定义状态行：新增 `extension-status-line` 字段，能力字段总数由 118 增至 119——四家能把整行交给用户命令，Codex 已发布版本只能挑内置条目

日期：2026-11-17
能力字段：`extension-status-line`（扩展系统 · 自定义状态行，新增字段）

## 本次改动

本次先按流程核对五家一手资料找新功能，Codex 在核对日期当天（2026-11-17）有六个提交把「MCP Server 提供状态行内容」推进到可在 TUI 页脚渲染：`46f5a1df9f2a` #61979 “Render selected MCP statusline providers in the TUI footer”、`10a3126a030f` #61981 “Poll MCP statusline providers with fresh state and bounded reads”、`47d9cde20e96` #61985 “Refresh status line providers on config and connection changes”、`7fb4014d52b5` #61986 “Preserve statusline provider selections across thread startup”、`568cccd4f557` #61988 “Add a status line provider picker to `/statusline`” 与 main HEAD `a3fc418fb29d` #61990 “Classify status line provider failures and shorten error messages”（SHA 与标题均按 GitHub commits API 逐个核对，`46f5a1df9f2a` 另按 commit API 取到完整说明与 17 个改动文件清单）。顺着这条线索逐家复核后发现，「终端底部那条常驻状态行能不能自定义」根本不是 Codex 一家的孤立新功能，而是五家早就各自落地、路线明显分岔的同一类扩展能力，而矩阵此前没有任何字段承载它：`cmd-keymap` 记的是 TUI 快捷键，`extension-output-styles` 记的是模型输出风格，`session-context-usage` 记的是上下文占用怎么算，`cmd-status`／`cmd-config` 记的是会话信息与设置面板，几处只是顺带提到状态行（`extension-custom-commands` 里 Codex 的 `/statusline <item…>` 与 `--colors`／`--no-colors`、`extension-presets` 里 “Current status line” 这个预设槽位来源），没有记录状态行本身的内容来源、输入契约、刷新时机、失败回退与作用域。因此本次新增 `extension-status-line` 字段，放在扩展系统分类末尾。
