# 跨会话消息能力字段

Claude Code v2.1.224（2026-08-07 发布）引入跨会话 `SendMessage`/`ListAgents`，v2.1.225（2026-08-08 发布）支持按名称主动发起对其他机器 Remote Control 会话的对话，官方文档单列 cross-session-messaging 页面。矩阵此前没有任何字段记录会话之间的相互消息，本次新增 `session-messaging`（跨会话消息）字段并覆盖五家产品：Qoder CLI 的 Agent Teams 用 `SendMessage` 在主 Agent 与队友之间通信（beta，单会话内），Qwen Code 的 `send_message`/`list_agents` 限于当前会话内的后台 Agent，Codex 与 Kimi Code 的官方命令表和文档未列出会话间消息。

## 修正

- 新增能力字段 `session-messaging`（会话与上下文域）：定义为发现其他会话、后台 Agent 或队友并互相发送消息；矩阵结论分别为 Claude Code "`/list-agents` · `/peers` · `SendMessage`/`ListAgents` · `crossSessionInbound`"、Codex "官方命令与文档未列出会话间消息"、Qwen Code "`send_message` · `list_agents`；限当前会话后台 Agent"、Kimi Code "官方命令表未列出会话间消息"、Qoder CLI "条件：`QODER_AGENT_TEAMS=1` Agent Teams `SendMessage`（beta，单会话内）"。
- Claude Code 详情：`/list-agents`（别名 `/peers`）列出可达会话、Subagent 与 Remote Control 会话；消息在活跃回合工具调用之间送达、空闲时启动新回合；纯文本，不携带历史或文件，文本命令不执行；本地走每会话 Unix socket，跨机器经 Remote Control 由 Anthropic 服务器中转；支持 macOS、Linux（含 WSL 2），原生 Windows 与 Bedrock、Claude Platform on AWS、Google Agent Platform、Foundry 不支持；`crossSessionInbound` 的 `accept`/`hold`/`refuse` 与未设置时按收发双方权限模式的默认规则、`dialogExpiry` 默认 5 分钟、`isolatePeerMachines` 跨机器批准、保留 100 条与已接受未读 50 条上限、`CLAUDE_CODE_MESSAGING_SOCKET` 导出、`claude -p` 绑定 inbox 但无法弹批准对话框、feature flag 环境变量与 `deny` 规则的停用路径均记入条件。
- Qwen Code 详情：`send_message` 携 `task_id` 对运行中 Agent 入队、暂停 Agent 恢复、已完成 Agent 继续（优先复用常驻运行时，否则从保留 transcript 恢复）；`list_agents` 返回 `task_id`、状态和是否可接收消息，含随恢复会话还原的兼容 Agent；明确边界为当前会话内，官方文档未列出独立并行会话之间的消息。
- Kimi Code 详情：命令表未列出会话间消息；`/swarm` 是多 Agent 任务模式、`/btw` 是与派生子 Agent 的旁路问答，均不计入；保留为未确认。
- Codex 详情：官方 CLI 命令表与文档目录未列出会话间消息；Subagent 委派、`codex exec` 会话分支与把 Codex 作为 MCP server 的多 Agent 工作流不计入；保留为未确认。
- Qoder CLI 详情：Agent Teams 为 beta，需 `QODER_AGENT_TEAMS=1`（CLI 环境变量或用户级 `.env`，修改后重启）；主 Agent 动态创建命名队友，`SendMessage` 为唯一共享通道（普通输出不自动发送），共享任务列表记录负责人与依赖；团队仅存在于单个 TUI 会话，退出即清空，`resume` 不恢复队友。
- 新增来源：`claude-cross-session-messaging`（官方文档页）、`claude-messaging-v224`（更新日志，固定提交 SHA `66edf5358349`）、`claude-messaging-v225`（更新日志，固定提交 SHA `53f9910f6ef0`）、`qwen-agent-messaging`（固定提交 SHA `412eae24b48ff16f54166c2b17eb4d4a9cdcdd1e` 的 Subagent 文档）、`kimi-commands-messaging-current`（固定提交 SHA `8db7d42f23472a692eb389a0e0e5a3e18aa1b94d` 的命令表）、`qoder-agent-teams`（官方 Agent Teams 文档）。
- `README.md` 能力字段数由 108 改为 109，会话与上下文详情数由 8 改为 9；`scripts/generate-session-docs.mjs` 生成的 `docs/capabilities/README.md` 中 sessions 计数同步改为 9。
- `docs/09-版本与证据.md`：Claude Code 主要材料补充跨会话消息；Qwen Code 核对日期更新为 2026-08-08 并补充后台 Agent 消息；Qoder CLI 核对日期更新为 2026-08-08 并补充 Agent Teams；官方来源表四家会话列补充对应链接。
- Qoder 官方文档站路径已由 `/en/cli/...` 迁移到 `/cli/...`（旧路径返回 404），新增来源使用新路径 `https://docs.qoder.com/cli/agent-teams`；其余既有 Qoder 链接本次不改。

## 证据版本

- Claude Code 官方更新日志 v2.1.224（提交 `66edf5358349`，2026-08-07T04:00:52Z）原文："Added cross-session `SendMessage`: Claude Code sessions can now message each other, on any of your machines, with `ListAgents` to discover them (macOS and Linux)" 与 "Added `crossSessionInbound` and `dialogExpiry` settings: cross-session messages sent to a session running with bypassed permissions are held for your approval, and messages to other sessions auto-deliver"。
- Claude Code 官方更新日志 v2.1.225（提交 `53f9910f6ef0`，2026-08-08T01:09:19Z）原文："SendMessage can now start a conversation with your Remote Control sessions on other machines by name (`ListAgents` shows them as `name [ref]`), instead of only replying after they message you first"。
- Claude Code 官方文档 [Message your other Claude Code sessions](https://code.claude.com/docs/en/cross-session-messaging)：最低版本 v2.1.224；支持 macOS、Linux（含 WSL 2），原生 Windows 不支持；Amazon Bedrock、Claude Platform on AWS、Google Agent Platform、Microsoft Foundry 不支持；`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`、`DISABLE_TELEMETRY`、`DO_NOT_TRACK`、`DISABLE_GROWTHBOOK` 关闭 feature flag 求值时停用；`crossSessionInbound` 取 `accept`/`hold`/`refuse`，未设置时按收发双方权限模式决定（bypass 分类含 `bypassPermissions` 与可用的 `plan`，prompting 分类含 `auto`、`acceptEdits`、`dontAsk`）；`isolatePeerMachines` 任一作用域为 `true` 即要求跨机器批准且在 `bypassPermissions` 下同样适用；`dialogExpiry` 默认 5 分钟；`"deny": ["SendMessage", "ListAgents"]` 整体移除工具且 deny `SendMessage` 同时阻断 Subagent 与团队消息；本地投递为每会话 Unix socket、不经 Anthropic 服务器，跨机器经 Remote Control、Web 直达云会话；消息为纯文本、命令不执行、不能批准权限或改配置；保留消息上限 100、已接受未读上限 50、按发送方限速并丢弃重复；`CLAUDE_CODE_MESSAGING_SOCKET` 在 Hook 执行前导出；`claude -p` 绑定 inbox 但无法弹批准对话框，bare 模式不绑定；沙箱命令 socket 访问受 `sandbox.network.allowAllUnixSockets`/`allowUnixSockets` 控制；Limitations 一节仍记录跨机器会话为 reply-only。
- Qwen Code 官方 Subagent 文档（提交 `412eae24b48ff16f54166c2b17eb4d4a9cdcdd1e`）：`send_message` 按 `task_id` "queues a message for a running agent"、"resumes a paused agent"、"continues a completed agent"；"Completed agents reuse their resident runtime when available and otherwise revive from their retained transcript"；`list_agents` "returns the addressable background agents in the current session, including compatible agents restored with a resumed session"，条目含 `task_id`、状态与是否可接收消息；状态缺失或不兼容时报告原因。
- Kimi Code 官方 Slash 命令表（提交 `8db7d42f23472a692eb389a0e0e5a3e18aa1b94d`）：命令表无会话间消息命令；`/swarm on|off` 与 `/swarm <task>` 为多 Agent 任务模式，`/btw [question]` 为派生子 Agent 旁路问答。
- Qoder CLI 官方 Agent Teams 文档（https://docs.qoder.com/cli/agent-teams）：beta，需 `QODER_AGENT_TEAMS=1`（CLI 环境变量或用户级 `.env`：macOS/Linux `$HOME/.qoder/.env`、Windows `%USERPROFILE%\.qoder\.env`，修改后重启）；"SendMessage: The primary mechanism for communication between the Main Agent and teammates, or between teammates"，普通输出不自动发送；共享任务列表记录 owner、状态与依赖；队友在 running/idle 间循环；团队只存在于当前 TUI 会话，退出即清空，`resume` 恢复历史但不恢复队友；单窗口切换视图。
- Codex 官方文档目录（https://learn.chatgpt.com/docs/llms.txt，2026-08-08 抓取）与 CLI 命令表：未列出会话间消息命令或工具。
