# 手动压缩：Claude Code v2.1.299 的空闲压缩 `idleCompaction`，五家「空闲与缓存过期」处理逐项核对

Claude Code 官方仓库 `CHANGELOG.md`（main 分支，固定到提交 `db93774d73e8fdbaf315a6f4c175ae99ad3d515a`，2026-10-14T02:49:24Z，只改 `CHANGELOG.md` 与 `feed.xml`）在 `## 2.1.299` 段下逐字写明 “Added idle compaction in the terminal: a 200K+ token conversation left idle for about 54 minutes is compacted before its one-hour prompt cache expires, so your next message doesn't reprocess it all” 与 “Added `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` to change idle compaction's 200K-token minimum; `"idleCompaction": false` in settings.json turns it off. Both need v2.1.290 or later”。对应 Release [v2.1.299](https://github.com/anthropics/claude-code/releases/tag/v2.1.299) 发布于 2026-10-14T02:49:42Z。官方设置参考、环境变量、模型配置、Context window 与 Prompt caching 五页都已经跟进，其中设置参考新增了独立的 `idleCompaction` 一节。这是本仓库尚未记录的一手确认新功能：Claude Code 第一次会在会话空闲时主动压缩，触发条件与 token 阈值无关，而是绑在一小时提示词缓存的过期时间上。

顺着这条核对五个产品后发现，「会话空闲一段时间后会发生什么」这一层在五家都存在但形态完全不同，而本仓库此前只有一句 Qwen Code 的备注：`session-compress` 详情的 Qwen 条件里写过「`context.clearContextOnIdle.*` 是空闲时清理旧工具结果的另一种机制，不属于摘要压缩」，没有键名、默认值与官方理由；Kimi Code 的 `tui.toml` 里同样针对空闲与缓存过期的 `cache_expiry_hint` 完全没有记录；Codex 与 Qoder CLI 也没有把「没有空闲触发」这一层核对结果写进字段。本次只处理 `session-compress` 一个字段，补录 Claude Code 的空闲压缩全套条件、阈值与关闭方式，并把其余四家在同一层的机制、默认值与边界逐项核对到当前一手资料。
