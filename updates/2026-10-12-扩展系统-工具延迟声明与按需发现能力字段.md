# 扩展系统：新增「工具延迟声明与按需发现」能力字段，五家的发现工具、开关、默认值与豁免入口逐项核对

Qwen Code v0.25.1（2026-10-11T10:20:36Z 发布）的 Features 段有一条本仓库尚未记录的一手确认新功能，逐字为 “Agent and Goal coordination tools are now deferred by default and discovered on demand, reducing unnecessary tool declarations in ordinary tool-call sessions.”（[#13033](https://github.com/QwenLM/qwen-code/pull/13033)，标题逐字为 “feat(core): defer agent and goal declarations by default”，2026-10-06T04:13:29Z 合入 main，合并提交 `8e3f3923b8c85d9c59e755b1846b4d87949d00dd`）。

顺着这条核对五个产品后发现，同类机制五家都已经有，但矩阵里没有任何字段记录它：Claude Code 官方 MCP 页有 “Scale with MCP tool search” 与 “Configure tool search” 两节，Codex main 分支有内置 `tool_search` 工具且两个特性开关都已移除，Kimi Code 官方 MCP 文档有「按需加载工具」段与 Server 级 `deferred` 字段加内置 `select_tools`，Qoder CLI 官方 MCP reference 有 “Lazy Loading Mode” 段（`mcp.lazyLoad: true` 或 `QODER_MCP_LAZY=1` 时只暴露 `mcp_list`／`mcp_get`／`mcp_call` 三个 Meta Tools）、设置参考另有 `mcp.lazyLoad` 一行。仓库里此前只有 `session-schedule` 的证据段顺带写过 Qwen `cron_create` 的 `shouldDefer`/`alwaysLoad`/关键词，没有独立字段，`extension-mcp` 也完全没有提到工具搜索。

因此本次按新增能力处理，只处理 `extension-tool-discovery` 一个字段，归入扩展系统，能力字段总数由 114 增至 115。五行的核对日期都改为 2026-10-12，因为五个产品在这个字段上的证据都是本次新取得的。Claude Code 没有新的更新日志（最新仍是 v2.1.296，2026-10-09T19:28:59Z），Codex 与 Kimi Code 的证据坐标是 2026-10-12 的 main 分支（两者最新 Release 分别仍是 rust-v0.162.1 与 2026-09-24 的 2.1.1），Qwen Code 固定到标签 v0.25.1，Qoder CLI 是文档站核对日期。
