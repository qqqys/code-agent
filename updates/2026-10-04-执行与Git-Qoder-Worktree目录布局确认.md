# 任务执行与 Git：Qoder CLI 并行 Worktree 目录布局、临时分支与清理行为由官方 Parallel Tasks 页确认

上一次核对（2026-10-03 消息平台渠道字段）在证据版本里留下一个待办：Qoder 官方 `/cli/parallel-tasks` 页记录的 Worktree 落点是仓库内 `<repo>/.qoder/worktrees/<sanitized-name>`，与矩阵 `execution-worktree`（并行 Worktree）字段 Qoder 列此前"`~/.qoder/worktrees/<job-id>` 与 Concurrent Job 布局未确认"的表述不一致，当时未改动该字段。本次以官方 Parallel Tasks 页（`https://docs.qoder.com/cli/parallel-tasks`，2026-10-04 复核）与 CLI 命令行参考页（`https://docs.qoder.com/cli/cli-reference`，2026-10-04 复核）为一手来源，把 Qoder 列此前多处"未确认"补足为已确认事实：命名 Worktree 落在仓库内 `.qoder/worktrees/<sanitized-name>`、配套临时分支按手工清理命令为 `worktree-<processed-name>`、同名 Worktree 直接复用不重建、仓库根 `.worktreeinclude` 声明要复制进干净检出的文件、交互式退出按未提交文件与新提交决定自动删除或提示保留、Subagent `isolation: worktree` 的干净 worktree 完成即删而有改动保留、并回主分支是手工提交或合并而非自动命令，且现行 CLI 参考可执行名为 `qoder`、子命令表不含 `jobs`/`rm`/`worktree`/`parallel-tasks`。此前引用的 `en/cli/using-cli` 页核对时仍返回 404。其余四家（Claude Code、Codex、Qwen Code、Kimi Code）的 Worktree 记录在 2026-09-30 已逐产品核对到源码与官方文档，本次复核未发现一手资料变化，矩阵结论保持不变；仅 Qoder 列证据发生变化，故只把 Qoder CLI 的核对日期更新为 2026-10-04。

## 证据版本

- Qoder 官方 Parallel Tasks 页 `https://docs.qoder.com/cli/parallel-tasks`（2026-10-04 复核）逐字记录：`New named worktrees are placed under <repo>/.qoder/worktrees/<sanitized-name>, and a corresponding temporary branch is created.`；`When no name is provided, Qoder automatically generates a worktree name.`；`If a worktree with the same name already exists, it is reused directly instead of being recreated.`；`To copy files like .env, declare them using .worktreeinclude at the repository root.`；`A new worktree is a clean checkout and does not include untracked files by default.`；`each task has its own workspace and context, preventing multiple sessions from sharing the same directory and overwriting each other's changes.`；`Each session has its own working tree and branch, keeping changes isolated from one another.`；`When a session ends, Qoder prints the worktree path and the command to resume the session. When exiting interactively, it checks for uncommitted files and new commits in the worktree: clean worktrees can be automatically deleted, while those with local files or commits will prompt you to choose whether to keep or delete them.`；`Clean Subagent worktrees are automatically deleted upon completion, while those with changes are retained.`；`Once completed, they can be committed or merged separately.`；`Delete unnecessary worktrees and temporary branches after tasks are completed and merged to keep the repository tidy.`；`One task per worktree`；`Use /tasks to view currently running background tasks`；手工清理命令 `git worktree remove <worktree-path>` 与 `git branch -d worktree-<processed-name>`。该页没有出现 `jobs` 或 `rm` 子命令。
