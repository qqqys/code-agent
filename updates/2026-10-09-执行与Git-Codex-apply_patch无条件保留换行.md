# 文件读写：Codex `apply_patch` 自 rust-v0.162.0 起无条件保留原换行，opt-in 开关与 LF 归一模式移除

Codex 官方 Release [rust-v0.162.0](https://github.com/openai/codex/releases/tag/rust-v0.162.0)（2026-10-08T18:55:59Z）在 “Bug Fixes” 下逐字写明 “Preserve existing CRLF line endings in `apply_patch` updates without requiring an opt-in. ([#51203](https://github.com/openai/codex/pull/51203))”。对应 PR #51203 “Make apply_patch preserve line endings unconditionally”（合并提交 `685270a56a96c76ae5b0853373a19d6ed5bc6fd4`，2026-10-05T23:52:20Z 合入 main）把换行保留从需要 opt-in 的实验功能改成默认且唯一的行为：对工具调用与独立 `apply_patch` 都使用保留换行的更新、移除 legacy 归一模式、把 `apply_patch_preserve_line_endings` 标记为 removed，并总在子进程环境注入 `CODEX_APPLY_PATCH_PRESERVE_LINE_ENDINGS=1` 以兼容旧版 patch 可执行文件。

本仓库 `execution-files`（文件读写）字段的 Codex 列此前记的是 2026-08-10 合入 main、尚未发布的 opt-in 开关状态（矩阵结论 “`apply_patch_preserve_line_endings` 换行保留（条件：main 分支，尚未发布）”、详情核心机制写 “`apply_patch` 默认 `NormalizeToLf`……main 分支新增 `PreserveLineEndings` 模式”、条件写 “`[features]` 下 `apply_patch_preserve_line_endings` 开关（默认关闭、UnderDevelopment 阶段）启用换行保留……尚未进入 Release”），已随该 Release 过期。本次只处理 `execution-files` 一个字段，把 Codex 的换行行为更正为已发布的无条件保留，并改正证据状态与来源。其余四家本次复核无同类变化：Claude Code、Kimi Code 与 Qoder CLI 的官方工具文档仍未列换行保留或规范化配置，Qwen Code `edit` 默认检测并保留原换行风格的记录不变。
