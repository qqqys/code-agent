# 生命周期 Hooks：Claude Code v2.1.295 的 `onFailure: "block"`，并补齐五家失败与超时语义、改正 Qoder CLI `/hooks` 漏记

Claude Code v2.1.295（2026-10-08 发布，更新日志提交 `602df92bf481ed904533e95c09f740f40aab5aed`）新增一条 Hook 失败处理开关，逐字为 “Added `onFailure: "block"` for command and HTTP hooks: a hook that can't start, times out, or exits with an unexpected code blocks the action instead of letting it through”。这条改动落在矩阵已有的 `extension-hooks`（生命周期 Hooks）字段里：该字段的跨产品事实本来就写明“超时、退出码和失败时是否放行是比较中的核心边界”，但五个产品的详情此前只零星记了退出码，没有系统记录失败与超时的放行/阻断语义，也没有任何一家有失败开关。本次以这条新功能为入口，把五家的失败语义按一手资料补齐：Claude Code 官方 Hooks 参考与 Hooks 指南在核对日期都还没有出现 `onFailure`（该键目前只有更新日志这一处一手记录），因此除 `"block"` 外的取值集合、默认值与能否按事件或作用域覆盖记为未确认；其余四家的一手文档都把非 0 非 2 退出码、超时与响应畸形记为非阻断错误并让主流程继续，也都没有等价配置键，其中 Kimi Code 是唯一在文档里直接给这套语义命名（fail-open）并写出使用边界的一家。核对 Qoder CLI 时还发现一处矩阵漏记：官方 Slash 命令参考一直列出 `/hooks`（描述 “Manage Hooks.”），Release Notes 记 CLI 1.0.8（2026-05-28）“Made /hooks command generally available for all users”，而 `cmd-hooks` 字段的 Qoder 列此前写成“Agent 配置支持；无独立命令”，`extension-hooks` 详情的 Qoder 入口也只写配置。本次一并改正。
