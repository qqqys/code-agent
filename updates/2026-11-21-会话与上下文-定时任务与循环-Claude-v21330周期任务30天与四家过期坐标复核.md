# 定时任务与循环：Claude Code v2.1.330 把周期任务与 `/loop` 的最长运行时间由 7 天改为 30 天（官方文档仍写 “Seven-day expiry”），同版之前的 v2.1.329 收紧已保存任务重载口径并让 `Exit and stop tasks` 结束本会话任务，另补录 `CLAUDE_CODE_LOOP_KEEPALIVE`；四家过期坐标同步前移复核

日期：2026-11-21
能力字段：`session-schedule`（会话与上下文 · 定时任务与循环）

## 为什么选这个字段

官方来源快照里 Claude Code 在上一轮研究（提交 `ce74a84`，2026-11-20T18:02:41Z）之后发布了 v2.1.330（2026-11-20T22:32:56Z）。逐条核对更新日志后，`## 2.1.330` 段里有一条直接推翻本仓库既有记录的数值：

> Changed recurring scheduled tasks and `/loop` to run up to 30 days instead of 7 while their session keeps running, and say when they end; tasks made before this release still end at 7 days

本仓库 `session-schedule` 的 Claude 单元格与详情页此前都写「周期任务 7 天后末次触发再自删」，跨产品事实里还写着「Claude Code、Qwen Code 与 Kimi Code ……都是……周期任务 7 天过期」。这条结论在 v2.1.330 之后已经过期，因此本次研究单元定为 `session-schedule`，并按同一口径复核其余四家的过期坐标。

同段还发现 v2.1.329（2026-11-19T22:14:41Z 发布）有两条同样属于本字段、上一轮只按 `/tasks` 字段登记过一条的变化，本次一并补全；上一轮的 `cmd-tasks` 研究单元引用的正是同一个更新日志提交，但只取了任务列表相关的三条，没有处理排程语义本身。

## 本次改动

### 1. Claude Code：过期上限 7 天 → 30 天

一手证据是官方更新日志，固定到 `CHANGELOG.md` 提交 `e791a1c41eee7504672a109fd6eb66b11566b8a1`（2026-11-20T22:32:35Z，1,382,549 字节，与 Release v2.1.330 同一时点）。逐字条目见上。

官方文档没有同步：`https://code.claude.com/docs/en/scheduled-tasks.md` 在 2026-11-21 仍是 **20,380 字节**（与 2026-11-20 核对时字节数相同），`### Seven-day expiry` 一节仍逐字为

> Recurring tasks automatically expire 7 days after creation. The task fires one final time, then deletes itself. This bounds how long a forgotten loop can run. If you need a recurring task to last longer, cancel and recreate it before it expires, or use [cloud scheduled tasks](https://code.claude.com/docs/en/routines.md) or [Desktop scheduled tasks](https://code.claude.com/docs/en/desktop-scheduled-tasks.md) for durable scheduling.

同页另有 “A loop you don't cancel ends when [seven days elapse](#seven-day-expiry).” 与 “The [seven-day expiry](#seven-day-expiry) applies to the loop too.”。全页对 “30 days” 的命中数为 **0**，也没有任何「任务结束时告知用户」的表述。

因此本次按「更新日志已确认、官方文档未同步」的既有口径记录（与 `CLAUDE_CODE_SUBAGENT_EFFORT`、`autoCompactWindow` 等条目同类），并把三点明确记为未确认：

- 「最长 30 天」按自然日计还是按会话累计存活时间计（条目只写 “while their session keeps running”）；
- 结束时告知用户的具体文案与出现位置；
- v2.1.330 之前创建的任务在升级到该版之后是否严格停在 7 天（条目写 “tasks made before this release still end at 7 days”，但没有说明判定依据是 `createdAt` 还是任务文件格式）。

矩阵单元格改写为「周期任务 v2.1.330 起最长 30 天（此前 7 天，该版之前创建的任务仍在 7 天结束）后末次触发再自删并告知结束」，并加一条条件「官方 scheduled-tasks 页仍写 “Seven-day expiry”、未同步 30 天且过期天数没有设置键」。详情页 `behavior` 与 `automation`（自定节奏循环的过期适用）两处同步改写。

### 2. Claude Code：过期天数没有任何可调开关（负面检索）

为了确认 30 天是否可配置，本次核对了两份官方参考：

- **设置参考**（`https://code.claude.com/docs/en/settings-reference.md`，460,908 字节）：与天数或寿命相关的键只有 `cleanupPeriodDays`（transcript 保留天数）、`desktopSessionCleanupPeriodDays`（桌面端与 Cowork transcript 保留天数）、`dialogExpiry`（Remote Control 或 SDK 宿主应答转发对话框的等待时长）、`promptCacheTtl` 与 `subagentPromptCacheTtl`（提示词缓存寿命）。没有任何 cron、scheduled task、`/loop` 或周期任务过期键。
- **环境变量页**（`https://code.claude.com/docs/en/env-vars.md`，194,269 字节）：命中 cron／scheduled task／loop／wakeup／过期寿命的只有两条，逐字为

  | 变量 | 官方描述 |
  | --- | --- |
  | `CLAUDE_CODE_DISABLE_CRON` | Set to `1` to disable [session-scoped scheduled tasks](https://code.claude.com/docs/en/scheduled-tasks.md#disable-scheduled-tasks). The `/loop` skill and `CronCreate` become unavailable and any already-scheduled tasks stop firing, including tasks that are already running mid-session |
  | `CLAUDE_CODE_LOOP_KEEPALIVE` | Set to `1` to run one extra iteration of an interactive [self-paced `/loop`](https://code.claude.com/docs/en/scheduled-tasks#stop-a-loop) when its second or later iteration ends with nothing scheduled |

  两条都没有最低版本要求。

`CLAUDE_CODE_LOOP_KEEPALIVE` 是本仓库此前完全没有记录过的第二个开关（全仓检索 `LOOP_KEEPALIVE` 命中数为 0），本次补进详情页 `conditions` 与矩阵单元格。它与既有的「一轮既没重新排程也没停止时补约 20 分钟兜底唤醒」是什么关系，官方没有说明，因此两者是否叠加记为未确认。

### 3. Claude Code：v2.1.329 的两条排程语义变化

同一个更新日志提交 `f9e4d1e5753ccffcffdd832f047d72be000396a6`（1,363,204 字节）的 `## 2.1.329` 段里有两条属于本字段：

- **已保存任务的重载口径收紧**，逐字为 “Changed saved scheduled tasks: in new signed-in sessions, most saved by earlier versions need scheduling again, though `--resume` of their own session still runs them”。写进详情页 `storage`：旧版本保存下来的任务在新开的已登录会话里多数要重新排程，只有 `--resume` 回到它自己的会话才照旧运行。官方没有给出「多数」与例外之间的判据，也没有说明这次变化是否改写 `.claude/scheduled_tasks.json` 的字段，两点记为未确认。
- **`Exit and stop tasks` 一并结束本会话定时任务**，逐字为 “Changed 'Exit and stop tasks' to end this session's scheduled tasks so they don't run again on resume, unless you exit while Claude is responding”。写进详情页 `persistence`。官方页 Limitations 的对应条目仍写 “You also lose session-scoped tasks if you exit between turns by choosing `Exit and stop tasks`.”，方向一致但没有写出「Claude 正在应答时退出」这个例外，该差异一并记录。

另把 v2.1.328 的两条定时任务修复补进版本时间线（保存一个任务时擦掉项目里其他已保存任务、任务文件里写错的任务在下次保存时被删除），时间线由止于 v2.1.281 延长到 v2.1.330。

### 4. Qwen Code：坐标前移到 v0.28.3，结论不变

`packages/core/src/services/cronScheduler.ts` 在标签 `v0.28.3`（2026-11-21T01:45:48Z 发布）下为 **97,448 字节**，四个关键常量逐字未变：

```typescript
export const MAX_JOBS = 50;
export const DEFAULT_RECURRING_MAX_AGE_DAYS = 7;
const MAX_RECURRING_JITTER_MS = 15 * 60 * 1000;
const MAX_ONESHOT_JITTER_MS = 90 * 1000;
```

本次补录三处此前没有记录的源码原文：

- 过期契约集中在一个函数里，注释逐字为 “Single owner of the recurring-expiry contract, shared with the config layer: `0` and `Infinity` both disable expiry, positive values pass through, and negative or NaN input falls back to `fallback`.”：

  ```typescript
  export function normalizeRecurringMaxAge(value: number, fallback: number): number {
    if (value === 0) return Infinity;
    return value > 0 ? value : fallback;
  }
  ```

- 构造函数以毫秒接收上限（`recurringMaxAgeMs: number = DEFAULT_RECURRING_MAX_AGE_MS`），创建任务时写 `expiresAt: recurring ? now + this.recurringMaxAgeMs : Infinity`，触发时用 `const expired = job.recurring && currentMs >= job.expiresAt;` 判定；紧邻注释说明过期在触发时刻评估而不是在 `expiresAt` 硬切，理由是硬切会静默吞掉任务的待触发窗口并与 `cron_create` 承诺的「最后触发一次」矛盾。
- `DEFAULT_RECURRING_MAX_AGE_DAYS` 的注释标注这是 “claw-code parity”，用途是覆盖「这周每小时查一次我的 PR」这类用法同时限制被遗忘的排程持续触发的时间。

本仓库此前的源码坐标是 `612a55295993` 与标签 `v0.24.7`。本次只前移了调度器源码，没有重新比对定时任务文档与 loop Skill 正文，因此这两份材料的坐标仍停在 `v0.24.7`／`612a55295993`，这一点在详情页 `conditions` 里写明。
