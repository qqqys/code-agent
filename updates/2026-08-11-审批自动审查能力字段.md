# 审批自动审查能力字段

Codex rust-v0.147.0（2026-08-07 发布）新增 `--approve-for-me` 标志（PR #36373，合并提交 `b7a610660816`），官方审批文档与配置参考同时记录 `approvals_reviewer = "auto_review"`：由独立审查代理裁决原本需要用户确认的审批请求。核对五家后发现，Claude Code 的 `auto` 权限模式（独立 classifier 审查动作）、Qwen Code 的 Auto 审批模式（LLM 分类器评估 shell 命令、网络调用与工作区外编辑）和 Qoder CLI 的 `auto` 权限模式（AI 分类器评估风险操作）是同类机制，矩阵此前均未设立字段记录（`security-bypass` 字段只把“Auto 分类器模式”列为排除项）。本次新增 `security-auto-review`（审批自动审查）字段并覆盖五家产品：Kimi Code 无同类机制，其 `/auto` 是全部审批自动放行的无人值守模式，不做基于操作内容的安全评估。

## 修正

- 新增能力字段 `security-auto-review`（权限与沙箱域）：定义为需审批的操作由产品内置的分类器或审查代理自动裁决，裁决可放行也可拒绝，与全部放行的 bypass 不同；矩阵结论分别为 Claude Code "`auto` 权限模式 · classifier 审查"、Codex "`approvals_reviewer = "auto_review"` · `--approve-for-me`"、Qwen Code "Auto 审批模式 · LLM 分类器"、Kimi Code "无同类机制；`/auto` 为全部审批自动放行"、Qoder CLI "`auto` 权限模式 · AI 分类器"。
- Claude Code 详情：`Shift+Tab` 循环到 `auto`、`--permission-mode auto`（含 `-p`）、`permissions.defaultMode: "auto"`；classifier 在执行前审查动作，阻断超出请求、未知基础设施或敌意内容驱动的操作，可见用户消息、工具调用与 CLAUDE.md（工具结果剥离），并审查 Subagent 三阶段与 `SendMessage` 消息、裁决根目录/Home 删除；被拒动作进入 `/permissions` Recently denied 可按 `r` 重试；连续 3 次或累计 20 次阻断暂停回退询问，`-p` 下连续阻断中止会话；计划、模型、Provider 条件与 `permissions.disableAutoMode`、v2.1.142 起项目 settings 忽略 `auto`、文档注明 2026-08-14 起 Pro/Max/Team 新会话默认 auto 均记入条件。
- Codex 详情：`approvals_reviewer` 默认 `"user"`，仅 `on-request`/granular 等交互审批策略下有可审查对象；审查代理处理沙箱升级、被阻网络、`request_permissions`、副作用 app/MCP 工具调用与 Computer Use 新域名，沙箱内已允许动作不审查；默认 guardian 策略检查数据外泄、凭据探测、持久性安全削弱与破坏性动作，critical 拒绝、高风险需足够用户授权；`[auto_review].policy` 与托管 `guardian_policy_config` 均为替换而非合并且托管优先；`apps.*.approvals_reviewer` 按 app 配置、`allowed_approvals_reviewers` 组织限定；失败关闭、超时不执行；同 turn 连续 3 次或最近 50 次审查滚动窗口 10 次拒绝中断回合；`/approve` 对每任务最多 10 条近期拒绝单项重试一次；`--approve-for-me` 搭配 `on-request` 与 `workspace-write` 并传播到 root/exec/resume/fork；明确 auto-review 是审查者替换而非权限放大。
- Qwen Code 详情：`/approval-mode auto`、`Shift+Tab` 循环（plan → default → auto-edit → auto → yolo）、`--approval-mode` 与 `tools.approvalMode`；分类器评估 shell 命令、网络调用与工作区外编辑，放行与阻断示例按文档记录；多数只读与工作区内编辑跳过分类器；不确定偏向阻断、API 不可达失败关闭、连续两次不可用或连续三次策略阻断回退人工审批；`permissions.autoMode.hints.allow/deny`、`environment`、`classifyAllShell` 记入规则；文档中“default out-of-the-box experience”与“初始模式为 Ask Permissions”两处表述并存照实记录；未信任目录阻断 Auto 等高权限路径记入条件。
- Kimi Code 详情：官方交互文档无分类器或审查代理；`/yolo` 自动批准普通工具调用但敏感文件与退出 Plan 仍可询问；`/auto` 自动处理全部审批且 Agent 不再提问，记录为全部放行而非自动审查。
- Qoder CLI 详情：`--permission-mode auto`、`Shift+Tab` 循环、`general.defaultPermissionMode` 与 `/goal set` 自动切换；安全读取与工作区编辑自动批准，危险 shell 与受保护路径直接拒绝，其余风险操作交 AI 分类器；`autoMode.allow`/`soft_deny`/`environment` 为注入分类器提示的软指引；`autoMode` 只从用户全局与 localSettings 等受信任来源读取；`dont_ask` 拒绝所有需审批操作、不使用自动审查。
- 新增来源：`codex-auto-review`（官方 Auto-review 文档页）、`codex-approve-for-me`（rust-v0.147.0 Release 页）、`codex-approve-for-me-commit`（固定到合并提交 SHA `b7a61066081644e0d8b2c0b4dbfd7408ac1514df`）；复用既有 `codex-approvals`、`codex-config-reference`、`claude-permissions`、`claude-permission-modes`、`qwen-approval`、`qwen-settings`、`kimi-interaction`、`kimi-config`、`qoder-permissions`。
- `README.md` 能力字段数由 109 改为 110，权限与沙箱详情数由 9 改为 10，核对日期更新为 2026-08-11。
- `docs/09-版本与证据.md`：五家核对日期更新为 2026-08-11；Claude Code 主要材料补充 auto 权限模式 classifier 自动审查，Codex 补充审批自动审查（`approvals_reviewer`/`auto_review`、guardian 策略、`/approve`、`--approve-for-me`），Qwen Code 补充 Auto 审批模式 LLM 分类器，Kimi Code 补充无审批自动审查机制，Qoder CLI 补充 auto 权限模式 AI 分类器；官方来源表 Codex 权限与沙箱列新增 Auto-review 文档、配置参考、v0.147.0 发布说明与固定 SHA 的提交链接。

- Codex PR #36373（`Add an --approve-for-me CLI flag`，2026-07-31T18:28:24Z 合入，合并提交 `b7a61066081644e0d8b2c0b4dbfd7408ac1514df`）：描述原文 "Add `--approve-for-me` to interactive and exec commands to route approval requests through automatic review."、"Configure the mode with `approval_policy="on-request"` and the `workspace-write` sandbox."、"Propagate the option across root, `exec`, `resume`, and `fork` argument handling while preserving later subcommand permission overrides."。
- Codex 官方审批文档（https://learn.chatgpt.com/docs/agent-approvals-security，2026-08-11 抓取）："Set `approvals_reviewer = \"auto_review\"` to route eligible approval requests through a reviewer agent before Codex runs the request"；"The reviewer evaluates only actions that already need approval, such as sandbox escalations, blocked network requests, `request_permissions` prompts, or side-effecting app and MCP tool calls."；"The reviewer policy checks for data exfiltration, credential probing, persistent security weakening, and destructive actions."；"Prompt-build, review-session, and parse failures fail closed. - Codex 官方 Auto-review 文档（https://learn.chatgpt.com/docs/sandboxing/auto-review，2026-08-11 抓取）："Auto-review replaces manual approval at the sandbox boundary with a separate reviewer agent."、"Auto-review is a reviewer swap, not a permission grant.
