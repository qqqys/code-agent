# 工具延迟声明与按需发现：Kimi Code `default_deferred` 全局默认与 `select_tools` 失败语义，Claude Code v2.1.299 第一方 MCP 描述不再截断

Kimi Code 官方仓库于 2026-10-14 合入 “feat(agent-core-v2): add global default for deferred MCP tool disclosure”（[PR #4210](https://github.com/MoonshotAI/kimi-code/pull/4210)，提交 `f28c51c01f025bba9f0d0f58f6309e7517a8cd02`，2026-10-14T09:19:29Z），为 `config.toml` 的 `[mcp]` 节新增 `default_deferred`：官方配置文档字段表逐字为「按需加载工具的全局默认：设为 `true` 时所有 MCP server 的工具按需加载，除非 server 自行排除；`mcp.json` 中单个 server 的 `deferred` 字段优先于本节」，类型 `boolean`、默认 `false`，与同节的 `startup_timeout_ms`（默认 `30000`）、`tool_timeout_ms`（默认 `60000`）并列。这是本仓库 `extension-tool-discovery` 字段此前没有记录的一手确认新功能：原矩阵结论只有「Server 条目 `deferred: true`」这一条逐 Server 入口，原跨产品事实还写着「Kimi Code 靠『不写 `deferred` 即始终内联』的逐 Server 选择」。

同一字段另有一处 Kimi 变更尚未记录：2026-10-13 合入的 “feat(agent-core-v2): distinguish session-unavailable tools and explain select_tools failures”（[PR #4190](https://github.com/MoonshotAI/kimi-code/pull/4190)，提交 `e4c99a3bad19b00bd1939b1cf254f427b50061f0`，2026-10-13T11:39:31Z）重写了 `select_tools` 的失败语义，原详情里记录的 “Unknown tool: <name>. Did you mean: <candidates>?”、“No tools can be loaded in this session — use the tools you already have.”、“Pick from the latest announced tools list.” 三条文案都已被替换，并新增了「曾加载但已不再注册」与「被工具策略拒绝」两类独立回话和两级劝退计数。

顺着这条复核其余四家：Claude Code v2.1.299（2026-10-14T02:49:42Z 发布）有一条同字段变更，更新日志逐字为 “Changed MCP tool descriptions and server instructions from Anthropic's first-party MCP servers at `api.anthropic.com` to reach Claude in full instead of being cut at 4,096 characters”；同时官方环境变量页的 `CLAUDE_CODE_MAX_MCP_DESCRIPTION_LENGTH` 一行已改写为 “The value you set replaces both default limits: 4096, and 16384 for the description of a tool that Claude loads through tool search.”，因此 2026-10-12 记录的「MCP 页与环境变量页都写默认 2,048 字符、两个文档页在核对日期都没有跟进」这一冲突在环境变量页已经不成立，本次改正。Codex 官方最新稳定 Release 仍是 rust-v0.162.1（2026-10-09T19:44:51Z，rust-v0.163.0 仍全是 alpha 预发布），Qwen Code 证据坐标仍是标签 v0.25.1（v0.25.2-preview.0 是 2026-10-13 的预发布、条目集中在 managed-agent 与 Web Shell），Qoder CLI 文档站的 `mcp.lazyLoad` 与三个 Meta Tools 没有变化，三家本次不改结论。

本次只处理 `extension-tool-discovery` 一个字段，能力字段总数维持 115。Kimi 与 Claude 两列的证据坐标更新到 2026-10-14，其余三列结论与坐标不变。

## 修正

- `extension-tool-discovery`（工具延迟声明与按需发现）矩阵 Kimi 列由 “条件：Server 条目 `deferred: true` + `tool-select` 实验标志 + 模型声明 `dynamically_loaded_tools` · 内置 `select_tools` 按精确名加载” 改为 “条件：`tool-select` 实验标志 + 模型声明 `dynamically_loaded_tools` · Server 条目 `deferred` 或全局 `[mcp] default_deferred`（默认 `false`、Server 字段优先、连接时固化）· 内置 `select_tools` 按精确名加载”。证据状态仍是「条件项」，因为两个前提没有取消。Claude、Codex、Qwen、Qoder 四列矩阵结论不变。
- Kimi 详情补录：入口新增 `config.toml` 的 `[mcp] default_deferred = true` 这条全局入口，并写明两个前提对全局默认同样适用；文件与目录补 `[mcp]` 节字段表的三行与 `packages/agent-core-v2/docs/config-manifest.toml` 里新增的 `# default_deferred: boolean`；执行行为补官方中文两段逐字引文（含「该值在 server 连接时固化，之后修改不会改动运行中会话的工具形态——重连该 server 或重启进程后才会应用。」）；作用域补源码判定式 `config.deferred ?? this.options.resolveDefaults?.().defaultDeferred ?? false` 与「写 `deferred: false` 即可把自己从全局默认里排除」；扩展构成加入 `[mcp] default_deferred` 与可加载集为空时的专门公告；加载与刷新补 `entry.deferred` 在 `connect`/`connectAllNow` 建条目时赋值并在每次 `connectOne` 开头重算、`deferredOf(name)` 查不到条目时回落 `false`、全局值经 `McpTunables.defaultDeferred` 由 `tunables()` 从配置服务的 `mcp` 节取出后交给 `resolveDefaults`、`mergedConnectionView.deferredOf(name)` 转发给拥有该 Server 的 base 或 overlay 管理器；适用界面补 `default_deferred`。
- Kimi 详情按 PR #4190 重写 `select_tools` 的失败语义：名字去重后分 `policyDenied`、`alreadyAvailable`、`toLoad`、`alreadyCallable`、`staleLoaded`、`unknown` 六类，逐类补录文案（含新加的 “was previously selected or loaded but is no longer registered. select_tools cannot restore it.” 与 “is disabled by the current tool policy. select_tools cannot enable it.”），`unknown` 的统一前缀改为 “Unknown tool: <name>.
