# Slash 命令 · 跨工具导入：新增能力字段 `cmd-import`，能力字段总数由 116 增至 117

日期：2026-11-11
能力字段：`cmd-import`（Slash 命令 · 跨工具导入，新增字段）；连带把 `/import` 补进 `docs/01` 的 Claude Code 命令目录、把 `/import-sessions` 补进 Kimi Code 命令目录

## 本次改动

本次从 2026-11-11 上一单元留存的两条待办出发——「Kimi 2.4.0 的 `/import-sessions`（导入 Claude Code／Codex 会话）是尚未入库的新能力，需跨五家核对后再决定新增字段或并入现有字段」与 2026-10-28 单元记下的「Codex rust-v0.165.0 的 external-agent memory import 与 Kimi 的 `/import-sessions` 构成一条跨工具导入轴，需要独立研究单元」——把这条轴拉直后跨五家核对，结论是：**四个产品都有从其他 Agent 产品导入本机数据的入口，且没有任何一个现有能力字段能容纳它**，因此新增 `cmd-import`。

选择新增而不是并入的判断依据：`cmd-config` 的 Qwen 单元格此前只把 `/import-config` 当作配置命令的一个附带入口，`session-resume`／`session-export` 只覆盖本产品自己的会话，`extension-*` 各字段按机制拆分且都以本产品自有目录为边界；而跨工具导入的对象横跨指令文件、设置、Skills、插件、MCP、Subagent、Hooks、命令、记忆与会话十类，落点分散在多个既有字段，任何一处并入都会让另一处失真。`cmd-import` 的「本页不包含」因此明确排除同产品旧版本数据迁移（Kimi 的 `kimi migrate`、Qwen 的 `command-migration-tool.ts` 与 `config/migration/`）、产品内部配置格式升级、安装原生格式扩展，以及把其他产品当后端 Agent 驱动的互操作（Qwen 的 `serve/session-agents/adapters/claude-cli.ts` 与 `codex-app-server.ts`）。
