# 手动压缩：Claude Code v2.1.312 让 Subagent `autoCompactWindow` 可以下调 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 设的窗口（官方 Subagents 页仍写「字段无效」），Kimi Code 源码钉住触发公式 `min(0.85W, W − 50000)` 与文档未列的 `compaction_trigger_ratio`，Qwen Code v0.26.3-preview.0 增加压缩触发线前的工具结果收缩

本次只处理 `session-compress`（手动压缩／自动压缩）一个能力字段，能力字段总数维持 115。这一轮同时带来一处旧结论作废（Claude 列此前写「设了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 时 Subagent 的 `autoCompactWindow` 无效」，v2.1.312 之后该字段可以下调变量的窗口）、一处官方文档未同步（Subagents 页、模型配置页与环境变量页在 2026-10-27 复核时都还没有按 v2.1.312 改写）、两处此前只有一句话的浅描述被换成源码级口径（Kimi 的触发公式与选取规则、Qwen 的 warn/auto/hard 三级阈值算式），以及一条矩阵尚未记录的新机制（Qwen 在压缩触发线之前按余量收缩整批工具结果，随预览通道 v0.26.3-preview.0 发布）。Codex 与 Qoder 两列结论不变，只更新了发布与发布说明坐标。

主线是「自动压缩什么时候触发、谁能单独改这个触发点」这两件事，五家此前都只记到配置键名，没有记到判定式；而这一天正好有三家给出新的一手材料：Claude 发了 v2.1.312，Kimi 在 main 上修了一个由触发点与预裁剪预算错位引起的提示词缓存问题（PR 说明里直接写出了触发点公式），Qwen 把工具输出预算挂到了 auto 触发线上（设计文档给出了 1M 窗口的 auto 与 hard 数值）。

## Kimi Code：触发公式、未公开的触发比例键与 main 上的预裁剪修正

main 分支上还有两个尚未发布的压缩修正。[PR #4456](https://github.com/MoonshotAI/kimi-code/commit/68a283894163204e93b072cef20db164015a5cad)（2026-10-27T10:59:19Z 合入，15 个文件、+614/−121，提交里没有任何 `.changeset` 文件）的提交说明第一段逐字为 “The pre-shrink budget (~0.74 of the window) sat below the auto-compaction trigger (min(0.85W, W-50k)), so every auto compaction on windows above ~195k dropped the oldest messages and broke the prompt-cache prefix. ## Qwen Code：warn/auto/hard 三级算式与压缩触发线前的工具结果收缩

阈值算式这次落到常量上。[`packages/core/src/services/chatCompressionService.ts`](https://github.com/QwenLM/qwen-code/blob/a325af5791ac470f3a71b942a5fe20b8b13d52f9/packages/core/src/services/chatCompressionService.ts)（68,053 字节）里 `COMPACT_MAX_OUTPUT_TOKENS = 20_000`、`DEFAULT_PCT = 0.85`、`SUMMARY_RESERVE = COMPACT_MAX_OUTPUT_TOKENS`、`AUTOCOMPACT_BUFFER = 13_000`、`WARN_BUFFER = 20_000`、`HARD_BUFFER = 3_000`，`computeThresholds(window, pct)` 逐字算 `effectiveWindow = Math.max(0, window - SUMMARY_RESERVE)`、`auto = absoluteCeiling > 0 ? Math.min(proportional, absoluteCeiling) : proportional`（`proportional = effectivePct * window`、`absoluteCeiling = effectiveWindow - AUTOCOMPACT_BUFFER`）、`warn = Math.max(0, auto - WARN_BUFFER)` 与 `hard = Math.min(window, Math.max(hardEdge, auto + HARD_BUFFER))`（`hardEdge = effectiveWindow - HARD_BUFFER`），1,000,000 窗口因此得 auto 850,000、hard 977,000；源码注释把三个缓冲量写成对齐 claude-code 的 `AUTOCOMPACT_BUFFER_TOKENS`（autoCompact.ts:62）、`WARNING_THRESHOLD_BUFFER_TOKENS`（autoCompact.ts:63）与 `MANUAL_COMPACT_BUFFER`。

新机制来自 [PR #13599](https://github.com/QwenLM/qwen-code/commit/a325af5791ac470f3a71b942a5fe20b8b13d52f9)（“feat(core): shrink tool results to the headroom left before auto-compaction”，2026-10-27T14:08:55Z 合入 main，24 个文件、+2,551/−210），它新增 [`docs/design/pressure-aware-tool-output.md`](https://github.com/QwenLM/qwen-code/blob/a325af5791ac470f3a71b942a5fe20b8b13d52f9/docs/design/pressure-aware-tool-output.md)（7,430 字节）与中文版（6,490 字节）。余量口径逐字为 “The headroom is measured against the auto-compaction trigger, not the hard ceiling: remaining tokens = (auto − reported prompt+output tokens − conservatively estimated new input the budget cannot shorten) / the existing new-content safety factor.”，并给出 “On the default 1M window the band between auto (850k) and hard (977k) is about 127k tokens, so a hard-ceiling anchor only shrank results after compaction had already been triggered.”；字符预算为 “remaining tokens × 4, rounded down, and applies only when it is below the batch's static capacity — the per-tool threshold times the number of results the budget can shorten. There is no 4,000-character minimum.”；范围与限制一节写 “The static defaults stay at 25,000 characters / 1,000 lines; this change does not raise them.” 与 “This is a complement to compaction, not a replacement, and it does not guarantee exact token admission.”（中文版为「这是对压缩的补充而不是替代，也不保证精确的 token 准入。」）。

源码侧的判定全在 [`llm-chat.ts`](https://github.com/QwenLM/qwen-code/blob/a325af5791ac470f3a71b942a5fe20b8b13d52f9/packages/core/src/core/llm-chat.ts)（339,399 字节）的 `pressureToolOutputBudget()`：缺少同路由的用量锚点、锚点历史不是当前历史的逐项全等前缀、本次内容没有 `functionResponse`、窗口不是有限正数，或用户显式设置了 `truncateToolOutputThreshold`（`isTruncateToolOutputThresholdExplicit()`）时都返回 `undefined`；否则 `remainingTokens = (auto - projectedTokens) / CONSERVATIVE_NEW_CONTENT_SAFETY_FACTOR`（该系数在 `tokenEstimation.ts` 为 1.5）、`chars = Math.floor(remainingTokens * TOKEN_TO_CHAR_RATIO) + minimumContent.budgetedChars`（`compactionInputSlimming.ts` 里 `TOKEN_TO_CHAR_RATIO = 4`），且只在 `chars < baseChars * shrinkableParts.length` 时返回；调用处注释写 “A non-finite aggregate budget disables the whole send guard. Both candidates below start from the original parts, so a result is never cut twice.”，最终预算与 `DEFAULT_TOOL_OUTPUT_BATCH_BUDGET = 200_000` 的聚合发送保护取较紧的一个。三个静态默认值在 `packages/core/src/config/config.ts`（520,225 字节）第 1006–1013 行：`DEFAULT_TRUNCATE_TOOL_OUTPUT_THRESHOLD = 25_000`、`DEFAULT_TRUNCATE_TOOL_OUTPUT_LINES = 1000`、`DEFAULT_TOOL_OUTPUT_BATCH_BUDGET = 200_000`。

发布通道要说清楚：该提交随预览通道 [v0.26.3-preview.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.26.3-preview.0)（2026-10-27T19:08:34Z，标签提交 `a2f7419d2f4327e450064907fb5ce09d52601269`）发布，发布说明逐字列出 “feat(core): shrink tool results to the headroom left before auto-compaction by @yiliang114 in #13599”；当天稍早发布的稳定版 v0.26.2（2026-10-27T15:32:11Z，标签提交 `402911146f6b2a80cb97423309faf1956f6defe4`）的完整变更清单里没有这一条，其压缩相关条目只有 Bug Fixes 里的 “UserPromptSubmit hook context is no longer duplicated on the next turn after automatic compaction, and compression checkpoints are protected from later rescue mutations. (#15575)”。用户文档也没有跟进：这条机制只写在 `docs/design/` 下，`docs/users/` 没有对应条目，`tools.toolOutputBatchBudget` 没有写进 `docs/users/configuration/settings.md`（390,187 字节），也没有为它新增开关或环境变量。

## Codex 与 Qoder：结论不变，只更新坐标

Codex 官方 [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference) 以 `.md` 形式复核（136,297 字节）：压缩相关仍只有 `model_auto_compact_token_limit`（`number`，“Token threshold that triggers automatic history compaction (unset uses model defaults).”）、`model_auto_compact_token_limit_scope`（`total` 或 `body_after_prefix`）、`compact_prompt` 与 `experimental_compact_prompt_file` 四个键，加 Provider 侧 `model_providers.<id>.capabilities.remote_compaction` 与只防机器休眠的 `features.prevent_idle_sleep`，逐字未变。最新 stable Release 是 [rust-v0.165.0](https://github.com/openai/codex/releases/tag/rust-v0.165.0)（2026-10-27T20:09:38Z，发布说明正文 6,551 字节），What's Changed 全表没有压缩、上下文窗口或 token 阈值条目，含 cache／token 字样的四条都属认证、沙箱测试与模型目录。

Qoder CLI [Release Notes](https://docs.qoder.com/release-notes/qoder-cli) 最新条目已推进到 CLI 1.1.79（October 26, 2026），其 “Stability Fixes and Context Loading Improvements” 一节里与压缩相关的一条逐字为 “Rules in directories added via --add-dir, /add-dir, or additionalDirectories are no longer automatically loaded into context at startup or after context compaction”，说的是压缩后不再自动加载附加目录里的规则而不是阈值；CLI 1.1.78（October 23, 2026）有 “Fixed SessionStart Hook context being lost after compaction”，1.1.75 至 1.1.77 三节没有压缩条目。全页压缩条目仍只有失败重试、速度、上下文窗口取错、压缩后状态与显示修复一类，触发阈值继续记为未确认。
