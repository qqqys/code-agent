# Claude Code v2.1.224 沙箱凭据打码扩展

Claude Code v2.1.224（2026-08-07 发布）的官方更新日志与 Sandboxing 文档为 `sandbox.credentials` 增加了一组打码选项：`extract`/`onExtractNoMatch` 结构化值打码、`decode: "jwt"`/`maskClaims` JWT 打码、`credentials.awsPairs`/`credentials.sigv4` AWS SigV4 重签名。这些选项已由一手资料确认，但矩阵尚未记录；本次更新 `security-credentials` 字段的 Claude Code 结论与详情。其余四家核对无变化：Codex 仍是 `[shell_environment_policy]` 过滤子进程环境变量，Qwen Code、Kimi Code 与 Qoder CLI 的公开沙箱或权限文档仍未列同类凭据保护字段。

## 修正

- `security-credentials`（凭据保护）矩阵 Claude Code 列由"`sandbox.credentials.files` · `envVars` `deny`/`mask` · 出站代理注入"更新为"`sandbox.credentials.files` · `envVars` `deny`/`mask` · `extract`/`decode: "jwt"` 打码 · `awsPairs`/`sigv4` SigV4 重签名 · 出站代理注入"。
- Claude Code 详情入口补充 `credentials.awsPairs` 与 `credentials.sigv4` 声明位置。
- Claude Code 详情具体行为补充：`extract` 只替换正则第 1 捕获组；`decode: "jwt"` 替换为结构有效的假令牌，`maskClaims` 按顶层 payload 声明打码，校验失败或无声明命中时按未打码放行并警告；代理按访问密钥哨兵值识别并重签 SigV4 请求。
- Claude Code 详情规则能力补充：`extract` 必须含捕获组且不能与 `decode` 同用；`onExtractNoMatch` 默认 `warn`，可选 `deny`/`error`；`awsPairs` 条目必须整值 `mask` 且不带 `extract`/`decode`，在 access key ID 条目 `injectHosts` 主机上重签名，`sessionTokenVar` 附带真实 `x-amz-security-token`；常规 AWS 变量整值打码时自动配对，`awsPairs` 列出常规变量会替换自动配对；只打码 secret 不配对时启动警告且请求会在 AWS 端失败。
- Claude Code 详情保存与作用域补充：仓库项目设置中的 `credentials.awsPairs`、`credentials.sigv4` 同样被忽略。
- Claude Code 详情条件与边界补充：v2.1.224 起新增上述选项，均需 `network.tlsTerminate` 且只在用户、Managed 或 `--settings` 设置中生效；`credentials.sigv4` 的 `streaming`/`presigned`/`sigv4a` 可设 `passthrough`，默认无法重签名的占位签名请求由代理直接失败。
- 跨产品事实更新为包含 v2.1.224 打码扩展。
- 新增来源 `claude-credential-mask-v224`（固定到提交 SHA `66edf5358349` 的更新日志）；Claude Code 核对日期更新为 2026-08-08。

## 证据版本

- Claude Code 官方更新日志 v2.1.224（提交 `66edf5358349`，2026-08-07T04:00:52Z；Release v2.1.224 于 2026-08-07T04:00:59Z 发布）原文：“Added sandbox credential-masking options: `extract` and `onExtractNoMatch` for structured env values, `decode: "jwt"` with `maskClaims` for JWT-aware masking, and `awsPairs`/`sigv4` for AWS SigV4 re-signing; these need `network.tlsTerminate` and are honored only from user, managed, or `--settings` settings”。
- Claude Code 官方 Sandboxing 文档（https://code.claude.com/docs/en/sandboxing）：`extract` 为作用于整个值的正则，只替换每个匹配第 1 捕获组的文本，模式必须含至少一个捕获组；`onExtractNoMatch` 取值 `warn`（默认，警告并按未打码放行；文件条目则跳过，沙箱命令可读取真实文件）、`deny`（沙箱内 unset 变量）、`error`（中止沙箱初始化直到修复配置）。`decode: "jwt"` 校验值为 JWT 后替换为结构有效的假令牌，`maskClaims` 列出顶层 payload 声明逐个打码、其余声明保持可读；值未通过 JWT 校验或无声明命中时按未打码放行并警告；`decode` 不能与 `extract` 同用；两类条目均支持 `credentials.envVars` 与 `credentials.files`。
- 同一文档：`credentials.awsPairs`（v2.1.224+）以 `accessKeyIdVar`、`secretAccessKeyVar`、可选 `sessionTokenVar` 组合非标准 AWS 凭据变量名，各变量必须是整值 `mask` 条目且不带 `extract`/`decode`，代理在 access key ID 条目的 `injectHosts` 主机上重签名，设置 `sessionTokenVar` 时重签请求附带真实 `x-amz-security-token`；整体打码 `AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`、`AWS_SESSION_TOKEN` 时自动合并为一份凭据（文档未标注该自动行为的起始版本），`awsPairs` 中列出常规变量会替换自动配对；只打码 secret 而不配对时请求携带占位签名在 AWS 端失败，启动时警告。`credentials.sigv4`（v2.1.224+）针对代理无法重签名的三种形态：aws-chunked 流式上传（`streaming`）、预签名 URL（`presigned`）、SigV4A 非对称签名（`sigv4a`），默认此类占位签名请求由代理失败而非转发破损签名，设为 `passthrough` 时转发占位签名请求，由调用工具收到 AWS 自身的拒绝响应；`awsPairs` 与 `sigv4` 只在用户设置、Managed 设置与 `--settings` CLI 参数中生效。
