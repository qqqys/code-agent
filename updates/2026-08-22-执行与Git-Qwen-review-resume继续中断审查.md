# Qwen Code `/review --resume` 继续中断的 PR 审查

Qwen Code v0.21.15（2026-08-20 发布）随 PR #9153（合并提交 `1eb8a0c7f8126de179b4c80b932d915983ce51f1`，2026-08-19 合入 main）把 `--resume` 接入 `/review` 与 Headless 包装 `qwen review run`：长时间 PR 审查因断连、超时或终端被杀中断后，中断尝试已把 worktree、捕获的 diff 与每个已运行 Agent 的 harness 记录留在磁盘上，`--resume` 从这些磁盘状态继续而不是重新开始。续跑不依赖专门检查点文件：`fetch-pr --resume` 直接裁决磁盘状态（worktree 仍停在 `fetchedSha` 且干净、diff 字节未变、PR head 未移动、续跑上限未用完、effort 一致），成功返回 `{"resumed": true, ...}` 复用上一次尝试的报告、worktree、计划与 diff，失败返回 `{"resumed": false, "resumeRefused": "<原因>"}` 并在同一次命令内回退为全新抓取。续跑固定在被中断运行记录的 effort，显式传不同 `--effort` 以 `effort-mismatch` 拒绝并按新级别全新运行；`head-moved` 拒绝消耗本次审查的一次 head 移动重启配额。该能力只对 PR 目标有效，仓库自身 CI 审查工作流不续跑（临时沙箱退出即删除 worktree，每次重试全新运行）。其余四家当前一手资料未列出同类恢复中断 Review 的内置入口。

- PR #9153 标题 "feat(review): wire --resume through /review, review run and the CI retry"，2026-08-19T05:13:27Z 合入 main，合并提交 `1eb8a0c7f8126de179b4c80b932d915983ce51f1`。PR 说明：`/review` 参数语法对 PR 目标接受 `--resume`，非 PR 目标触发警告并忽略（与 `--comment` 门禁相同）；`review run` 获得同名标志并透传进子进程 `/review` 提示；原计划的 CI 重试接线在评审中被移除，因为临时沙箱退出即删除 worktree、无可恢复状态，CI 重试保持全新运行并有场景测试固定该缺失。
- 提交 `1eb8a0c7f812` 的 `docs/users/features/code-review.md` 新增 "Resuming an interrupted review (`--resume`)" 一节，原文要点："A long review that dies part-way — a dropped connection, a timeout, a killed terminal — leaves everything it had done on disk: the worktree, the captured diff, and the harness's own record of every agent that ran. `--resume` continues from there instead of starting over"；"It applies to PR targets only … and it is safe to pass whenever you are unsure"；"A continuation keeps the interrupted run's effort: passing a different `--effort` refuses the resume and runs fresh at the level you asked for"；"if the PR head moved while the review was down, the resume refuses (`head-moved`) and the fresh run reviews the new commits"；Headless 一节列出 `qwen review run [target] [--json] [--fail-on request-changes] [--comment] [--resume] [--quiet]`，并注明 "Resume is a local convenience: the repository's own CI review workflow does not resume — each retry re-runs fresh"。
- 同一提交的内置 Review Skill `SKILL.md`：参数提示 `[pr-number|file-path] [--effort low|medium|high] [--severity_floor critical|suggestion] [--comment] [--fix] [--resume]`；`fetch-pr` 探测条件为 "worktree still at fetchedSha and clean, diff bytes unchanged, PR head unmoved, resume cap unspent"；`resumed: true` 时 `--out` 路径上的旧报告 "deliberately left untouched"，只读取其中的 worktree、plan 与 diff；`head-moved` 拒绝 "IS this review's one head-movement restart"，`restartsSpent >= 1` 后 Step 7 "must submit at the reviewed SHA, never restart again"；`recover-findings` 命令形如 `qwen review recover-findings --plan .qwen/tmp/qwen-review-pr-<pr_number>-fetch.json --out .qwen/tmp/qwen-review-pr-<pr_number>-recovered.md`，"certifies the interrupted attempt's agents against the harness transcripts — the same two-author proof check-coverage runs on"；`check-coverage` 读取上一次尝试证据，"name exactly the agents still owed and nothing already covered"；反向审计 "If latestReverseAuditRound is k, Step 5 resumes at round k+1"；续跑披露 "coverage counts recoveredAgents and the composed body carries a continuity line"；跨仓轻量模式 "`--resume` has no effect in lightweight mode — there is no fetch-pr, no worktree and no plan to continue"；续跑不再进入增量检查的 `upToDate: true` 停止/清理分支，以免 `cleanup pr-<n>` 摧毁刚救回的 worktree 与租约。
