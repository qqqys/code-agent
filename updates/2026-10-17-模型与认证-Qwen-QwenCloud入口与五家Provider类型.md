Qwen Code 于 2026-10-16 合入 “feat(providers): add QwenCloud as the first /auth entry”（[PR #14073](https://github.com/QwenLM/qwen-code/pull/14073)，2026-10-16T13:34:44Z 合并，合并提交 `a84dbff23e6d31212f22b4998831c5ceb7dae160`，改动 48 个文件），并随 [v0.25.3-preview.0](https://github.com/QwenLM/qwen-code/releases/tag/v0.25.3-preview.0)（2026-10-16T18:28:53Z，GitHub API 标记 `prerelease: true`）发布。这是本仓库 `model-provider` 字段此前完全没有记录的一手确认新入口：官方认证文档现在逐字写 “Qwen Code's first-run `/auth` menu has four top-level options.”，第一项就是 **QwenCloud**，其后是 **Alibaba ModelStudio**、**Third-party Providers** 与 **Custom Provider**。旧记录的 Qwen 列只写了协议名「OpenAI · Anthropic · Gemini · Vertex · 自定义」，既没有写 `/auth` 的四组入口，也没有写 15 个内置 Provider 预设。

顺着这条新入口复核 main HEAD `428f686adec24ea26725ce86071ad9b0a5282120`（2026-10-17T18:09:38Z）下的认证文档（29,030 字节）、Model Providers 文档（66,889 字节）、Provider 注册表与两个 QwenCloud 预设源码后发现，Qwen 列还有一整块机制从未记录：QwenCloud 下分 `qwencloud-token-plan` 与 `qwencloud-standard` 两个预设，每个预设再把 **China — 千问AI平台** 与 **International — QwenCloud** 作为显式平台步骤，因此四个端点由「访问方式 + 平台」两步决定，官方逐字写 “so the UI language never decides your endpoint”；两个预设各自有独立环境变量（`QWENCLOUD_API_KEY`、`QWENCLOUD_TOKEN_PLAN_API_KEY`）与 Key 前缀校验（按量付费要求 `sk-` 且不能是 `sk-sp-`，Token Plan 要求 `sk-sp-`，两条错误提示互相指向另一个入口）；`ALL_PROVIDERS` 的显示顺序与 `uiGroup` 三分组、模型目录发现、`webSearch` 后端与 `capabilities` 对 `/effort` 档位的影响也都只在源码和文档里。发布状态需要标条件：v0.25.3-preview.0 标签（指向提交 `d407c0bb3823118281fbfc178494f4525a2241b8`）下 `packages/core/src/providers/presets/` 有 15 个文件并出现两个 `qwencloud-*` 预设，而最新 stable v0.25.2（标签指向提交 `8a415cb628db88844e0196bdfdcce83b4f88d812`）同一目录只有 13 个文件、没有任何 QwenCloud 预设，发布说明也只是自动生成的 PR 列表。

复核另外四家时发现 Claude Code 列同样缺了两个官方部署位置。官方 Enterprise deployment overview 页的部署选项对比表列出六列，其中 **Claude Platform on AWS** 与表头逐字为 “Google Cloud's Agent Platform, formerly Vertex AI” 的一列都不在旧记录里；Amazon Bedrock 页另有 “Use the Mantle endpoint” 一节，逐字为 “Mantle is an Amazon Bedrock endpoint that serves Claude models through the native Anthropic API shape rather than the Amazon Bedrock Invoke API.”，由 `CLAUDE_CODE_USE_MANTLE=1` 开启、`/status` 的 provider 行显示 `Amazon Bedrock (Mantle)`、模型 ID 形如 `anthropic.claude-sonnet-5`，Model configuration 页把这类条目单列为 “Mantle model IDs”。环境变量页的 Provider 选择项因此是五个 `CLAUDE_CODE_USE_*` 变量而不是旧记的四个部署名。

Codex 与 Kimi 两列本次改正表述并补细节。Codex 旧记写「内置 OpenAI、Amazon Bedrock、Ollama、LM Studio」，把两类不同的东西并列了：官方配置参考逐字写 “Built-in provider IDs (`openai`, `ollama`, and `lmstudio`) are reserved and cannot be overridden.”，而 `amazon-bedrock` 是另一个内置 Provider，“unlike custom providers, this built-in provider supports only the nested AWS profile and region overrides”。同节还给出 `--oss` 与 `--local-provider`/`oss_provider` 的本地 Provider 语义（都没设时交互式 CLI 提示选择而 `codex exec` 报错退出）、命令式认证 `[model_providers.<id>.auth]` 的完整字段与互斥限制、Azure 只作为自定义 Provider 示例存在、以及项目级 `.codex/config.toml` 会忽略 `model_provider` 与 `model_providers` 并告警。Kimi 列旧记写「Kimi · Anthropic · OpenAI · Gemini · Vertex」，漏了 `openai` 与 `openai_responses` 是两个不同 `type`，也没有写第三方厂商不是内置预设而是从 models.dev 目录或自定义 registry `api.json` 导入；本次固定的 main HEAD `18c6d64272952503baccf706bff455bb6a2c488e` 文档比仓库此前固定的 `77618e38c35a81e26134b3f83eb7f2b460c0ee05` 版本多了 2,591 字节，差异是实质性的：凭证优先级新增 `api_key_env`（与 `api_key` 互斥，2.0.1 于 2026-09-18 引入）、models.dev 不可达时回退内置目录快照（0.32.0）、registry 条目声明的 `env` 变量名只作提示而绑定永不自动发生、以及 registry 模型的 `upgrade`/`migration_markdown`/`retirement_at` 迁移元数据与启动时的迁移提示。Qoder 列结论不变，补录三个页签结构、BYOK 向导流程、两个官方页面对「支持哪些厂商」的不同口径，以及 0.1.31 到 1.1.63 的 BYOK 时间线。
