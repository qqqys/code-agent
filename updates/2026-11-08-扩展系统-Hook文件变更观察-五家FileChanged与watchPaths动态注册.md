# 扩展系统 · 生命周期 Hooks：Qwen v0.27.0 新增 `FileChanged`，Claude 同名事件与 Qoder 注册方式补录，Codex 与 Kimi 确认没有

日期：2026-11-08
能力字段：`extension-hooks`（扩展系统 · 生命周期 Hooks）

## 本次改动

本次以 Qwen Code v0.27.0（2026-11-07T20:45:25Z 发布）的一个新 Hook 事件为起点，把「能不能观察工具调用之外的文件写入」在五家全部核对了一遍。结果是一条新能力（Qwen `FileChanged`）、两条此前被本矩阵漏记的既有能力（Claude `FileChanged` 与 Qoder `FileChanged` 的字段与注册方式），以及两条负结论（Codex 与 Kimi 都没有这一类事件）。

**Qwen Code v0.27.0 新增 `FileChanged` 事件与 `hookSpecificOutput.watchPaths` 注册键**：

- 版本边界是硬的。`docs/users/features/hooks.md` 在标签 v0.27.0（提交 `03b0c2435be1890a21b117860eaf389076787275`）下为 105,235 字节、事件表 **23 行**；在此前记录的提交 `1dc74d58384ca1fe8c29730970f1f7c60d1e5265`（96,533 字节）与 `35aa4b76ae10a458632d23c9b0052af5a31b3885`（98,620 字节）下都是 **22 行**，`FileChanged` 与 `watchPaths` 均 0 次命中。专页 `docs/users/features/file-changed-hooks.md`（7,621 字节）与实现 `packages/core/src/hooks/file-changed-watcher.ts`（9,585 字节）在上一稳定版 v0.26.9（提交 `600aff0592bcfc21668ca4aba95a5b20c6491b86`）下都返回 **HTTP 404**。v0.27.0 发布说明 Complete Change List 的 Features 首条逐字为 “Added FileChanged hooks for local non-managed sessions, reporting add, change, and unlink events for watched files and directories. (#13969) by @samuelhsin”，Breaking Changes 一节写 “No known breaking changes.”
- 事件表行逐字为 “| `FileChanged` | After an explicitly watched file is added, modified, or deleted | Basename of the changed file |”；`### Matcher Patterns` 表新增 “File Events” 一行并标 “✅ Regex”，表后专段逐字为 “For `FileChanged`, registering static paths uses literal filenames in cwd; filtering events uses the basename and the rules below.”，即**注册用字面文件名、过滤用正则**是两件事。
- 专节 Purpose 逐字为 “Observes additions, modifications, and deletions of explicitly watched files in local, non-managed sessions. Changes may come from Qwen Code, shell commands, editors, or other processes. The common input fields identify the listening session, including when another session writes a shared directory.”，输入是 `{ "file_path": "/home/me/work/demo/.envrc", "event": "change" }`，`file_path` 为绝对路径、`event` 取 `add`／`change`／`unlink`。专页另写 “The common `session_id` and `cwd` belong to the listening session; they do not identify the writer. Multiple sessions watching a shared directory can each receive its changes. File content is not included.” 与 “Only file events are delivered. Directory-self `addDir` and `unlinkDir` events are not delivered.”
- **静态注册**只认 cwd 内的裸字面文件名：“Static roots accept only bare literal filenames, including dotfiles. Regex/glob metacharacters and path separators do not create static roots.”、“Static registration does not expand globs or scan directories recursively.”、“Regex patterns filter already watched paths; register their files or directories explicitly through `watchPaths`.”，另有 “missing files may be watched for creation” 与 “Changing the session working directory relocates static roots before relocation finishes; explicit absolute dynamic roots stay unchanged.”
- **动态注册**逐字为 “A successful synchronous `SessionStart` hook can register absolute files or directories through `hookSpecificOutput.watchPaths`. Directories are watched recursively, including children created later. Recursive discovery skips `.git` and `node_modules` subtrees. To observe a path inside them, register that file or directory explicitly. Special file types are ignored, and ordinary directories have no depth limit. Initial registration waits for watcher readiness before `SessionStart` returns.”；替换语义表四行为 “A list of absolute files or directories | Replaces the previous dynamic list”、“`[]` | Clears the dynamic list”、“Omitted or invalid `watchPaths` | Keeps the previous dynamic list”、“Output from an async hook | Does not register or change paths”，并要求 “All entries must be absolute paths; one invalid entry makes the list invalid.”
- **不能阻断**：专节写 “Hook output cannot veto or undo a write or add model context.”，专页写 “`FileChanged` cannot veto or undo a write or add model context.” 与 “Watcher or hook failures are logged and leave the originating file operation unchanged.”；自触发风险有专门提醒 “A hook that writes a watched file can trigger itself; avoid those writes or deduplicate the work.”
- **Surface 条件**逐字为 “SSH execution environments, shell sandbox workers, and managed dispatchers do not start a local filesystem watcher. Normal hook enablement and trust rules still apply. Watching stops when its owning session shuts down.”，跨机器另有 “Roots in another container or remote instance need a watcher in that filesystem owner; registering their paths on the host does not observe them.”
- 文档只写 “Events are reported after writes settle.”，**「settle」的两个数字要到源码才看得到**：`file-changed-watcher.ts` 用 `import { watch, type FSWatcher } from 'chokidar'`，`watch()` 选项为 `ignoreInitial: true`（对应 “The initial directory scan is not replayed”）、`followSymlinks: false`（对应 “Symbolic links discovered inside a recursive root are not traversed”）与 **`awaitWriteFinish: { stabilityThreshold: 200, pollInterval: 50 }`**；`ignored` 回调里有 `/\.[0-9a-f]{12}\.tmp$/` 的原子写临时文件判断、动态根内 `.git`／`node_modules` 分量跳过与 “// Only ancestors of requested paths may lead discovery downward.”，并且**没有传 `depth` 选项**，与 “ordinary directories have no depth limit” 一致。
- 仍记为未确认：该事件能否用 prompt 与 HTTP Handler（prompt 一节写 “Prompt hooks can be used with most hook events, including:” 后只列 `PreToolUse`、`PostToolUse`、`Stop`、`SubagentStop`、`UserPromptSubmit`，既没列入也没排除 `FileChanged`）、观察路径数量上限与单会话 watcher 数量上限。

**Claude Code 的 `FileChanged` 此前被本矩阵完全漏记**（官方 Hooks 参考页 2026-11-08 以 `.md` 形式复核，289,929 字节，比 2026-11-04 记录的 286,102 字节增加）：

- 事件汇总表行逐字为 “`FileChanged` | When a watched file changes on disk. The `matcher` field specifies which filenames to watch”；整节开头逐字为 “Runs when a watched file changes on disk. **Claude Code detects changes with a filesystem watcher, not by inspecting tool calls**, so it runs the hook no matter what changed the file: an `Edit` or `Write` tool call, a script Claude runs with `Bash`, or a process outside Claude Code entirely. A common use is reloading environment variables when project configuration files change.”
- 官方两处把它定位成工具匹配的替代品：`### PreToolUse` 写 “To run a hook when a specific file changes on disk, whatever wrote it, use FileChanged instead of matching file-editing tools by name. Unlike PreToolUse, Claude Code runs FileChanged hooks after the change, and they have no decision control, so they can't block the write.”，`### PostToolUse` 写 “Claude Code doesn't run a `PostToolUse` hook matching `Edit|Write` when a `Bash` command or a process outside Claude Code rewrites the same file.”
- **`matcher` 在这一个事件上承担两个角色**：“**Build the watch list**: the value is split on `|` and each segment is registered as a literal filename in the working directory, so `".envrc|.env"` watches exactly those two files. Regex patterns are not useful here: a value like `^\.env` would watch a file literally named `^\.env`.” 与 “**Filter which hooks run**: … against the changed file's basename.”；`### Matcher patterns` 另有两句例外 “`FileChanged` and `StopFailure` use a narrower exact-match set of letters, digits, `_`, and `|` only.” 与 “The `FileChanged` event doesn't follow these rules when building its watch list.”
- **watcher 是懒启动的**：“Claude Code starts the watcher only when something names a file to watch, so seed the list with a FileChanged group whose matcher names at least one file, or with a SessionStart or CwdChanged hook that returns `watchPaths`.”，三个注册入口的字段说明分别是 `SessionStart` 的 “Array of absolute paths to watch for FileChanged events during this session”、`CwdChanged` 的 “Returning an empty array clears the dynamic list, which is typical when entering a new directory” 与 `FileChanged` 的 “Use this when your hook script discovers additional files to watch based on the changed file”；`"*"` matcher 会被当成字面文件名注册（“Claude Code registers it in the watch list like any other value, as a literal file named `*`”）。
- **没有决策控制**：“FileChanged hooks have no decision control. They can't block the file change from occurring.”、“Claude Code reads `watchPaths` and `systemMessage` from their JSON output and discards `continue`. In interactive sessions, it shows the `systemMessage` as a brief terminal notification. The message doesn't reach the SDK message stream.”，“Exit code 2 behavior per event” 表对应行为 “| `FileChanged` | No | Shows stderr to user only |”，Decision control 表把它与 `Setup`、`Notification`、`SessionEnd`、`PostCompact`、`InstructionsLoaded`、`StopFailure`、`CwdChanged`、`DirectoryAdded` 并列为 “None | No decision control. Used for side effects like logging or cleanup”。
- **Handler 类型受限**：它属官方列出的 18 个 “Events that support `command`, `http`, and `mcp_tool` hooks but not `prompt` or `agent`” 之一；`FileChanged` 与 `CwdChanged` 另可用 `CLAUDE_ENV_FILE`（“Other hook events don't have access to this variable, and neither does a hook that runs in PowerShell”），写入的变量保留到后续 Bash 命令、直到下一次 `CwdChanged` 时被清除。
- **自触发是官方点名的失败模式**：“A looser guard loops forever, because `perl -i` rewrites the file even when it substitutes nothing and Claude Code runs the hook again after every rewrite.”
- 版本坐标：`CHANGELOG.md`（2026-11-08 复核 main，1,176,779 字节、最新段 `## 2.1.319`）里 `FileChanged`、`DirectoryAdded` 与 `watchPaths` 一共只有两条命中——v2.1.83 的 “Added `CwdChanged` and `FileChanged` hook events for reactive environment management (e.g., direnv)”（固定到标签提交 `cada21c89dc76cb0355fdeee659806674abfd38c`）与 v2.1.219 的 “Added `DirectoryAdded` hook that fires after `/add-dir` or the SDK `register_repo_root` control request registers a new working directory mid-session”（固定到 `0c188278cdf9b8b717c2740550bdb0f69c02f6b5`）；`watchPaths` 一词从未出现在更新日志里。顺带补录 `DirectoryAdded`：不等待 Hook（“the add completes immediately, and the hook runs in the background with the 600-second default timeout”）、在沙箱与权限状态刷新之后触发但 Hook 命令自身不进沙箱、matcher 只取 `slash_command` 与 `register_repo_root`，三种情况不触发（`--add-dir` 启动旗标由 `SessionStart` 覆盖、`/permissions` 的 Workspace 页签、已是工作目录或在其内部）。
- 仍记为未确认：观察路径数量上限、目录递归深度、写入稳定判定间隔、符号链接处理规则，以及哪些 Surface 不启动 watcher。

**Qoder CLI 的 `FileChanged` 此前只作为事件名记在 23 个事件的清单里，本次补录字段与注册方式**（Hooks 页 2026-11-08 复核，HTML 1,268,339 字节、去标签后正文 32,243 字符）：

- `FileChanged` 与 `CwdChanged` 同属官方 “Working Directory and Files” 分组。事件总览表两行逐字为 “| CwdChanged | — | — | old_cwd, new_cwd |” 与 “| FileChanged | filename basename | — | file_path, event |”，即 matcher 匹配 basename、**退出码 2 不阻断**。
- `FileChanged` 一节逐字为 “Triggered when a watched file changes.”、“**matcher field:** Basename of the changed file (supports exact match, `|` multi-value, regex)”、输入 `{ "file_path": "/abs/path/file.ts", "event": "change" }` 加 “`event` values: `change` / `add` / `unlink`.”，输出为 “**hookSpecificOutput:** `additionalContext`, `watchPaths` (same as CwdChanged)”；`watchPaths` 的定义只挂在 `CwdChanged` 一节，逐字为 “Absolute paths to register with the `FileChanged` watcher”。
- **注册入口比另两家窄**：全页 `watchPaths` 只出现 2 次、`watcher` 与 `watched` 各 1 次，`SessionStart` 的 `hookSpecificOutput` 只有 “`additionalContext` (context injected into the conversation)”、`UserPromptSubmit` 的是 `additionalContext` 与 `sessionTitle`，因此只有 `CwdChanged` 与 `FileChanged` 能注册观察路径。由此产生的缺口是官方没有说明冷启动时第一个被观察的文件从哪里点名——`SessionStart` 不能注册，而 `FileChanged` 又要先有被观察文件才会触发；matcher 是否像 Claude 那样同时充当静态注册清单也没有任何一手说明。
- 同样记为未确认的还有 watcher 实现与依赖、目录是否递归、是否跳过 `.git`／`node_modules`、写入稳定判定间隔、符号链接与原子写临时文件处理、观察路径或深度上限、哪些 Surface 不启动 watcher，以及自触发风险的提醒。
- 发行版坐标定不下来：更新日志 `https://changelog.qoder.com/cli`（2026-11-08 复核，HTML 782,358 字节、正文 69,863 字符）最新条目为 CLI 1.1.84（November 6, 2026），其前为 CLI 1.1.83（November 4, 2026）与 1.1.82（November 3, 2026），全文对 `FileChanged`、`watchPaths`、`watcher` 与 `CwdChanged` 均为 **0 次命中**。1.1.83 里唯一带 “change detection” 字样的一条是 “Improved change detection for read files to prevent compaction from being triggered directly when content reaches the limit without any conversation”，指读取内容的变更检测、与 Hook 的文件观察无关。

**Codex 与 Kimi Code 都没有这一类事件**：

- Codex 官方 Hooks 页（2026-11-08 复核，HTML 541,305 字节、去标签后正文 49,797 字符）14 个事件里 `watch`、`Watch`、`watcher`、`FileChanged`、`file changed`、`CwdChanged`、`ConfigChange` 与 `watchPaths` 全部 **0 次命中**，`filesystem` 只有 3 次且都在 MCP 工具名 matcher 示例里（`mcp__filesystem__read_file`、`mcp__filesystem__.*` 与 “Match the MCP tool name, such as `mcp__filesystem__read_file`.”）；分组表五行（“During a turn”／“For each model request attempt”／“When you interrupt an active turn”／“When a session or subagent starts”／“When the main thread ends”）没有一组按文件系统状态触发。Codex 侧因此只有按工具调用触发的路径：`PreToolUse` “can intercept Bash, file edits performed through `apply_patch`, MCP tool calls, and other local function tools”，`PostToolUse` “runs after supported tools produce output … It can't undo side effects from a tool that already ran.”，两者都不覆盖 Codex 之外的进程写文件。
- Kimi Code `docs/zh/customization/hooks.md`（标签 `@moonshot-ai/kimi-code@2.5.2`，提交 `1c142a007c10e881602690def96057c23a2baa12`，9,523 字节）`## 事件一览` 仍是 **20 行**，全文对 `watch`、`FileChanged`、`监听` 与 `变更` 均为 0 次命中；`文件` 的 3 次命中没有一次指文件系统观察（两处说明 Hook 的执行位置、一处是“多写会导致配置文件加载失败”），写成 `变化` 的 2 次都指 `Notification` 的“后台任务状态变化时触发”。唯一按时间而非按动作触发的是 `SessionHeartbeat`（“会话存活期间每 60 秒触发一次，仅配置本事件时计时器才运行”），与文件系统无关。配置面也不给注册观察路径留余地：`[[hooks]]` 只允许 `event`／`matcher`／`command`／`timeout` 四个字段、多写会导致配置文件加载失败。
