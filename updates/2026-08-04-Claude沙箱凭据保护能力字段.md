# Claude Code 沙箱凭据保护能力字段

Claude Code 官方 Sandboxing 文档已记录 `sandbox.credentials` 凭据保护块（v2.1.187+ 的 files/envVars `deny`，v2.1.199+ 的 envVars `mask`），且 2026-08-04 发布的 v2.1.221 更新日志新增 Linux 与 WSL 凭据文件的 `mode: "mask"`。矩阵此前没有任何字段记录产品对沙箱命令读取凭据文件与敏感环境变量的保护能力，本次新增 `security-credentials`（凭据保护）字段，覆盖五家产品，并区分文件/变量保护、打码与出站注入。

## 修正

- 新增能力字段 `security-credentials`（权限与沙箱域）：Claude Code 提供凭据文件与环境变量的 `deny` 及 `mask`，并可由沙箱代理在出站请求中替换真实值；Codex 只在环境变量继承层提供 `[shell_environment_policy]` 过滤；Qwen Code、Kimi Code、Qoder CLI 公开文档未列同类凭据保护字段。
- Claude Code 详情：`sandbox.credentials.files` 仅支持 `deny`（等同 `filesystem.denyRead`，属文件系统层，`sandbox.filesystem.disabled` 时失效）；`sandbox.credentials.envVars` 支持 `deny`（每条沙箱命令执行前 unset）与 `mask`（命令见到每会话哨兵值，请求前往 `injectHosts` 或 `network.allowedDomains` 内主机时由代理替换真实值；需 `network.tlsTerminate`，缺失时启动报错并失败关闭）；`deny` 跨作用域合并且不可移除、优先于 `mask`；`mask`、`network.tlsTerminate`、`credentials.allowPlaintextInject` 仅认用户、Managed 或 `--settings` 来源，仓库设置被忽略；无内置凭据拒绝清单，仅作用于沙箱内 Bash 命令；`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` 可不经沙箱剥离 Anthropic 与云 Provider 凭据。v2.1.221 起 Linux 与 WSL 凭据文件支持 `mode: "mask"`：沙箱命令读取哨兵副本（整文件或 `extract` 正则捕获片段），代理在出站时替换真实值；macOS 文件打码回退 `deny`。
- Codex 详情：`[shell_environment_policy]` 控制传给所生成命令的环境变量：`inherit = "none"|"core"`、`set` 显式赋值、`filters` exclude/include（大小写不敏感，支持 `*`/`?`）；`ignore_default_excludes` 默认 `true`，即默认不自动移除名称含 KEY、SECRET、TOKEN 的变量，设为 `false` 才应用自动排除；处理顺序为自动排除、自定义 exclude、`set`、include 允许列表；旧 `exclude`/`include_only` 数组不能与 `filters` 同层混用。无凭据文件打码或出站替换。
- Qwen Code 详情：官方沙箱文档未列凭据文件或敏感变量保护字段；容器沙箱挂载工作区与 `~/.qwen`，认证与设置在运行之间保留。
- Kimi Code 详情：配置文档无凭据保护字段，OS 或容器级沙箱未确认；permission rules 属工具规则层。
- Qoder CLI 详情：本地 CLI/SDK 文档未列凭据文件或敏感变量的 deny/mask/替换；云端会话 `vault_ids` 引用云端凭据库，不属于本地沙箱保护。
- 新增来源 `claude-credential-file-mask`（v2.1.221 更新日志，固定到 commit SHA）。
- 同步修正四个生成器（command、session、extension、security）中 `docs/capabilities/README.md` 的能力数：Slash 命令 28 → 29、权限与沙箱 8 → 9、扩展系统 7 → 8、任务执行与 Git 9 → 10，与实际详情文件数一致。

## 证据版本

- Claude Code 官方 Sandboxing 文档（code.claude.com/docs/en/sandboxing，2026-08-04 核对）：“Protect credentials” 一节原文记录 `sandbox.credentials` 需 v2.1.187+；文件 `deny` 等同 `filesystem.denyRead` 且属文件系统层；envVars `deny` 在每条沙箱命令前 unset；“File entries support only `"mode": "deny"`”；`mask` 需 v2.1.199+，哨兵值经沙箱代理在 `injectHosts`（未设时为 `network.allowedDomains` 全部主机）出站替换，`injectHosts` 必须被 `network.allowedDomains` 覆盖，缺 `network.tlsTerminate` 时 “masking fails closed” 且启动报告；`mask`、`network.tlsTerminate`、`credentials.allowPlaintextInject` 在仓库 `.claude/settings.json`/`.claude/settings.local.json` 中被忽略；“There is no built-in credential deny list”；“The setting affects sandboxed Bash commands only”；`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` 不经沙箱剥离 Anthropic 与云 Provider 凭据。
- Claude Code 官方仓库提交 `dd796139237c`（2026-08-04）CHANGELOG.md v2.1.221 条目原文：“Added `mode: "mask"` for sandbox credential files on Linux and WSL — sandboxed commands read a sentinel copy (the whole file, or just the spans captured by an `extract` regex) while the sandbox proxy substitutes the real value on egress; on macOS file masking falls back to `deny`”。该版本于 2026-08-04T00:14Z 发布。
- Codex 官方 Advanced configuration 文档（learn.chatgpt.com/docs/config-file/config-advanced，2026-08-04 核对）：“Shell environment policy” 一节原文记录 `inherit = "none"|"core"`、`set`、`filters` 的 exclude/include、`ignore_default_excludes` 默认 `true`（设为 `false` 才对名称含 KEY、SECRET、TOKEN 的变量自动排除）、处理顺序与旧数组兼容规则，并说明该配置用于 “avoid passing unnecessary secrets to spawned commands”。
- Qwen Code 官方仓库 `docs/users/features/sandbox.md`（main 分支，2026-08-04 核对）：仅列 Seatbelt Profile、容器挂载与代理配置；容器挂载工作区与 `~/.qwen` 使 “auth and settings persist between runs”；未列凭据文件或敏感变量保护字段。
- Kimi Code 官方仓库 `docs/zh/configuration/config-files.md` 与 `docs/zh/guides/interaction.md`（已固定 SHA 见版本与证据页）：无凭据保护字段；OS 或容器级沙箱未确认。
- Qoder CLI 官方 Permissions 与 SDK reference（docs.qoder.com，2026-08-04 核对）：路径权限规则、Sandbox Settings 与 `canUseTool` 之外未列凭据文件或敏感变量的 deny/mask/注入；`CloudSessionCreateParams.vault_ids` 为云端凭据库引用。
