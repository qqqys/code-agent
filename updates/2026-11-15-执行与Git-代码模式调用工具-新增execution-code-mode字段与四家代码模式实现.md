# 代码模式调用工具：新增 `execution-code-mode` 字段，能力字段总数由 117 增至 118——四家已有代码模式、只有 Kimi Code 没有

日期：2026-11-15
能力字段：`execution-code-mode`（执行与 Git · 代码模式调用工具，新增字段）

## 本次改动

同日上一单元把 “Claude Code v2.1.323 的 Code Mode 是本仓库尚未记录的新能力，需要新增字段” 记为未处理项。本次按官方来源逐家核对后发现，这不是 Claude Code 一家的孤立新功能，而是四家产品已经各自落地、且实现路线明显分岔的同一类能力：Claude Code 的 Code Mode（`REPL` 工具）、Codex 的 JavaScript code mode（`exec` + `wait` 工具、独立 V8 宿主进程）、Qwen Code 的 CodeModeOnly（`exec` 工具、QuickJS/WASM 子进程）与 Qoder CLI 的 CodeMode（更新日志宣布、文档站尚未收录）。矩阵此前没有任何字段承载它：`execution-shell` 记的是产品自己的 Shell 工具，`extension-tool-discovery` 记的是工具声明的延迟与按需发现，两者都只顺带提到 Code Mode 的副作用（Qwen 设置文档与 Codex 的 `code_mode_tool_search` 开关），没有记录「模型写代码、代码里发起嵌套工具调用」这一执行原语本身。因此本次新增 `execution-code-mode` 字段，放在执行与 Git 分类末尾。

**一手证据**（Claude Code 文档与更新日志固定到 main HEAD `d75f21b168edcfceb4127eb15cfa9ce6d84e41b2`；Codex 源码与 schema 固定到 main HEAD `03cb329415f3abd4216181443405ef32d5da8143`；Qwen Code 源码、设置文档与设计文档固定到 main HEAD `6e3b2dcc19f5c66125fc8e643d1c5d889a0d6ae7`；Kimi Code 固定到 main HEAD `f082f04a093a3e71a2263c5461d52507dc31f83a`；Qoder CLI 为更新日志与文档站 `.md` 孪生体的 2026-11-15 核对）：

- Claude Code 有官方专页 “Run tool calls from code with Code Mode”（`.md` 孪生体 15,659 字节），文档索引 `llms.txt`（58,496 字节）第 391 行已收录该页。定义逐字为 “Code Mode changes how Claude uses its tools. Without Code Mode, Claude asks for tool calls such as Bash, Read, or Edit directly and reads each result before it decides what to do next. With Code Mode, Claude writes a piece of JavaScript that makes the tool calls, and Claude Code runs that code in your session.”，并标注 “Code Mode is experimental and off by default. It may change or be removed in any release.”。承载代码的工具名是 `REPL`——官方写要检查代码就得写一个匹配 `REPL` 的 `PreToolUse` Hook 并从 `tool_input.code` 读 JavaScript，而工具参考页（91,496 字节）对 `REPL` 的整词命中数为 0，即该工具没有独立条目。可见性逐字为 “In the conversation, you see the tool calls, such as the edit's diff, and not the code. To read the code, press `Ctrl+O` to open the transcript viewer. Each piece of code appears there as a collapsed **Code** row”。长任务分两档：等待时 “the code stops after ten minutes, including time you spend at permission prompts”，后台时 “you can keep talking to Claude, and the code can run for up to two hours” 且必须以 auto 或 `bypassPermissions` 模式启动。权限逐字为 “Each tool call that Claude's code makes goes through your `deny` and `ask` permission rules and your `PreToolUse` hooks.”，auto mode 下则是 “the classifier reviews each piece of code before it runs, not each tool call. It doesn't see values computed at run time”。Requirements 六项（v2.1.323 及以上、Claude 订阅或 Console 账号、组织未启用 HIPAA 配置或零数据保留、Opus 5.5／Sonnet 5.5／Haiku 5.5／Fable 5.2、交互式终端 `claude` 会话、原生构建，Windows 另需 Git for Windows）与 11 行不可用原因表都取自该页；不可用时顶部与 `/status` 显示 “Code Mode (experimental) isn't available” 加原因。

- Codex 的代码模式是四家里最早、也最工程化的一支。Release rust-v0.114.0（2026-03-11T00:28:42Z）的 New Features 首条逐字为 “Added an experimental code mode for more isolated coding workflows. - Codex 的运行时是独立宿主进程里的 V8。`description.rs`（46,301 字节）的 `EXEC_DESCRIPTION_TEMPLATE` 首行逐字为 “Run JavaScript code to orchestrate/compose tool calls”，要点含 “Evaluates the provided JavaScript code in a fresh V8 isolate as an async module.”、“Runs raw JavaScript -- no Node, no file system, no network access, no console.” 与 “When the JS code is fully evaluated, the isolate's lifetime ends and unawaited promises are silently discarded.”；全局助手清单为 `exit()`、`text()`、`content()`、`image()`、`audio()`、`generatedImage()`、`store()`、`load()`、`notify()`、`setTimeout`／`clearTimeout`、`ALL_TOOLS` 与 `yield_control()`，其中 `store`/`load` 逐字为 “stores a serializable value under a string key for later `exec` calls in the same session”——这是四家里唯一的跨调用持久状态。`v8_init.rs`（2,665 字节）的注释逐字为 “V8 cannot change JIT mode after initialization, so a later call requesting a different mode returns an error. Code mode initializes V8 with JIT enabled by default”，`globals.rs`（7,089 字节）在安装全局前先 `delete_global` 掉 `console`、`Atomics`、`SharedArrayBuffer` 与 `WebAssembly`，并编译运行内置的 `settled.js` 与 `content.js`；`code-mode-host/Cargo.toml`（1,487 字节）确认二进制名是 `codex-code-mode-host`、依赖含 `tonic`（features `router`、`transport`、`zstd`）与 `axum`。

**跨产品事实**（写入详情页的 10 条）里最有比较价值的几条：四家全部默认关闭并标为实验性或开发中；承载代码的工具名三家三个样（`REPL`／`exec`/`exec`，Qoder 未公布）；运行时三种（Claude 未公布、Codex 是宿主进程里的 V8 isolate、Qwen 是子进程里的 QuickJS/WASM）；跨调用持久状态只有 Codex 的 `store`/`load`；长任务口径三套（Claude 十分钟与两小时、Codex 的 yield 加 `wait` 续接、Qwen 的 30 秒加 guest CPU 预算）；未 await 的调用在 Codex 是 “silently discarded”、在 Qwen 是 “cancelled when the script finishes”；与工具延迟发现的衔接在 Qwen 是「搜索可用就从 `exec` 描述里省略延迟工具签名」、在 Codex 是独立开关 `code_mode_tool_search`、在 Claude 没有公布路径。
