# 会话命名：Kimi Code 2.3.0 起首个完成回合后自动生成会话标题，Qoder CLI 的 `/rename` 与自动生成已被官方文档化，Claude Code 生成标题更正为可作恢复句柄

Kimi Code 在 2026-10-21T05:51:43Z 发布 [`@moonshot-ai/kimi-code@2.3.0`](https://github.com/MoonshotAI/kimi-code/releases/tag/%40moonshot-ai%2Fkimi-code%402.3.0)（标签提交 `b5e28fd6beac752a2cdcc0ff2f5fdf40e6494fbb`），仓库内 `apps/kimi-code/CHANGELOG.md` 的 2.3.0 段 Minor Changes 下逐字写明 “Automatically generate a session title after the first turn and show it as the terminal window title.”，指向 PR #4200 与合并提交 `5bab748dddaae4b2ac15822d72b83446e5fd7bf4`（提交说明含 “feat(tui): gate auto session title behind a tui.toml auto_session_title toggle”），2.3.0 标签提交比该合并提交超前 18 个提交、落后 0 个，即这项能力已随 2.3.0 正式发布而不是停在 main。触发点在 `apps/kimi-code/src/tui/kimi-tui.ts` 的 `handleTurnEnded`，末行逐字为 “if (event.reason === 'completed') void this.maybeAutoGenerateSessionTitle();”，该方法要求 `sessionId` 非空、`appState.autoSessionTitle !== false`，再经 `harness.getConfig()` 复核全局键，然后以 `source: 'first_turn'` 调 `generateSessionTitle`，每会话尝试上限 `MAX_AUTO_TITLE_ATTEMPTS = 3`（常量上方注释逐字为 “Per-session cap on automatic title-generation attempts; failures stay retryable across turns until the cap so a transient error is not sticky.”），成功即记为 done，catch 块为空并附注释 “title generation is best-effort; the session keeps its current title”。开关有两个且默认都是 `true`：`config.toml` 顶层字段表写 “| `auto_session_title` | `boolean` | `true` | 是否允许客户端自动生成会话标题；显式设为 `false` 时关闭 |”，`tui.toml` 表写 “| `auto_session_title` | `boolean` | `true` | 首个完成的轮次后由 TUI 自动生成会话标题；设为 `false` 只关闭 TUI 的触发，不影响 `config.toml` 中的全局 `auto_session_title` |”。生成不用会话模型，而是走托管平台的 `chat_title` 工具：`packages/oauth/src/managed-tools.ts` 的文件头注释逐字为 “Managed-platform `/tools` dispatch: POSTs `{method, params}` to `{kimiCodeBaseUrl}/tools` with a Bearer access token”，`sessionTitleService.ts` 要求 Kimi Code Provider 属 OAuth 目录厂商且配置了 `oauth`，`OAuthError` 记 debug “chat_title request unavailable:” 后放弃、HTTP 401 强制刷新令牌重试一次、其他失败记 “chat_title request failed:”，因此只配自定义 API Key 的 Provider 不会生成标题。标题按 `MAX_GENERATED_TITLE_LENGTH = 200` 截断后以 `{ title, titleKind: 'generated' }` 写进会话 `state.json`（`META_KEY` 即 `state.json`，`touchUpdatedAt: false`）并广播 `session.meta.updated`；非 `force` 生成在 `titleKind` 已是 `custom`（用户 `/title` 设的）或 `generated` 时直接返回，所以自动生成至多成功一次且永不覆盖手工标题。官方中文会话指南第 24 与 64 行仍只写 `state.json` 存会话标题、`/title`（别名 `/rename`）设置或显示标题，没有描述自动生成，公开说明只落在配置文档的两行 `auto_session_title` 上，本仓库此前 Kimi 详情「公开会话文档未描述单独的 AI 自动命名入口」一句因此过期。

顺着「自动生成的触发时机、开关、生成引擎、上限与落盘」这一层核对其余四家，发现两处必须更正的旧记录。第一处在 Qoder CLI：本仓库此前把 Qoder 列写成「TUI 命令表未列出」并把整列证据状态标为未确认，而 2026-10-21 复核时官方 [Slash 命令参考](https://docs.qoder.com/cli/slash-reference) 的会话管理表已在 `/resume` 与 `/branch` 之间列出 `/rename`，描述逐字为 “Rename the current session.”，[Session Management 页](https://docs.qoder.com/cli/sessions)（1,174,731 字节）也逐字写 “You can also use `/rename` to rename the current session from within the session.”，并给出启动命名 “Use `-n` (`--name`) to set an easily recognizable display name for a session:” 加示例 `qoder -n "Refactor login"`；[Release Notes](https://docs.qoder.com/release-notes/qoder-cli) 的 CLI 1.1.52（September 14, 2026）更把自动生成写死为 “Type `/rename` to auto-generate a session name based on the current conversation; manually entered names are automatically sanitized and length-limited”，CLI 1.1.9（July 30, 2026）为 “Added support for running /rename while a task is in progress”。第二处在 Claude Code：官方 [Manage sessions 页](https://code.claude.com/docs/en/sessions)（31,381 字节）在 “Name your sessions” 一节逐字写 “Sessions you don't name still get two labels that Claude Code assigns. Only the generated title works as a resume handle”，即默认显示名（工作目录名加两位字符后缀，官方示例 `my-app-3f`）不是恢复句柄，而 AI 生成标题与接受计划后替换成的计划标题都可以传给 `claude --resume` 或 `/resume` 并“按用户设的名称同样解析”，本仓库此前记的「未命名会话还会有默认显示名和 AI 生成标题，但两者不是恢复句柄」把生成标题一并否掉了，本次改正。

Qwen Code 一侧此前只有一句「自动命名通过快速模型根据会话生成标题」，本次按 main 分支提交 `e8ddd0d79a4f562d0513e0987ac8dbe328531e2c` 补齐触发时机与边界：`chatRecordingService.ts` 在每记录一个助手回合后以 fire-and-forget 方式调 `maybeTriggerAutoTitle()`（方法注释逐字为 “Fire-and-forget: after an assistant turn is recorded, attempt to generate a short session title from the conversation so far.” 与 “Errors are swallowed. The title is best-effort and must never surface as a user-visible error or interrupt recording.”），跳过条件依次是已有标题、写入失败、有待完成的显式标题写入、已有在途生成、`autoTitleAttempts >= AUTO_TITLE_ATTEMPT_CAP`（同为 3）、`QWEN_DISABLE_AUTO_TITLE` 为真值（`0`/`false`/`no`/`off` 视为未关闭）、既非交互式又没开 Zed/ACP 集成（注释写明 `qwen -p`、cron 与 CI 一类单次运行整个跳过，而 daemon 的 ACP 会话仍要生成）、没有配置 fast model；输入是最多 `MAX_TITLE_USER_DISPLAY_TEXTS = 20` 条用户显示文本的滚动窗口，提示词首句为 “Generate a concise, sentence-case title (3-7 words) that captures what this programming-assistant session is about. Think of it as a git commit subject for the session.”，长度上限 `SESSION_TITLE_MAX_LENGTH = 200`，标题以 `titleSource` 的 `auto`/`manual` 写进当前会话 JSONL，落盘前还会重读该 JSONL 尾部以防覆盖另一个终端里的手工命名。也就是说 Qwen Code 与 Kimi Code 在「回合后自动触发、3 次尝试上限、尽力而为、不覆盖手工名称」这四点上一致，差别在生成引擎（fast model 对托管 `chat_title` 工具）、关闭方式（环境变量对两个 `auto_session_title` 键）与落盘字段（`titleSource` 对 `titleKind`）。Codex 一侧命令参考仍只承诺手工命名，但本次补上两条此前没记的入口与用途：`/rename` 不带参数会打开命名提示（“Type `/rename <name>`, or type `/rename` to open the naming prompt.”）、`/new <name>` 可在创建时命名（“To name the new chat as you create it, run `/new bug bash`.”），而 `codex archive`、`codex unarchive` 与 `codex delete` 都按 “by session ID or session name” 接受目标，因此名称在 Codex 是这三条子命令的句柄。本次只处理 `session-naming` 一个能力字段，能力字段总数维持 115。
