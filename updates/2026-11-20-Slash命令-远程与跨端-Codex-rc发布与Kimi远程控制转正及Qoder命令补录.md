### 1. Codex：`/rc`（别名 `/remote`）随 rust-v0.171.0 进入正式 Release

发布坐标：rust-v0.171.0 于 2026-11-20T00:44:47Z 发布，附注标签对象 `295eca93394bb83a6ec8e0841033f3997f97fcbd`、指向提交 `ccf9be8cc458bd6b8336fe84d68d8893f2691a5e`；命令本身由提交 `5f775c7f4f5f3e0b3bb6eb499b280e023e697f71`（2026-11-17T21:05:23Z，PR #62121，标题 “Add `/rc` to manage remote control from the TUI”）合入，17 个文件改动、新增 `codex-rs/tui/src/app/remote_control.rs`（+375 行）与 `remote_control_tests.rs`（+124 行）及菜单快照。上一单元（`cmd-tasks`）已把 `slash_command.rs` 的坐标固定在同一个提交，本次沿用并改挂到标签提交，两个坐标下该文件都是 14,582 字节、逐字节相同。

命令定义（`codex-rs/tui/src/slash_command.rs`）：枚举为 `#[strum(to_string = "rc", serialize = "remote")]` 加 `Rc,`，即主命令 `/rc`、别名 `/remote`；描述匹配臂逐字为 `SlashCommand::Rc => "manage remote control for the local background server",`。四个可用性判定都含 `Rc`——`supports_inline_args`、`available_in_side_conversation`、`available_when_thread_unavailable` 三个清单，以及 `available_during_task` 的 `true` 分支；`is_visible` 走默认 `_ => true`，即命令菜单可见、回合运行中、side conversation 内与线程不可用时都能执行。作为对照，同枚举的 `App` 的 `is_visible` 是 `cfg!(any(target_os = "macos", target_os = "windows"))`。

行为与门禁（`codex-rs/tui/src/app/remote_control.rs`，15,284 字节）：文件头注释逐字为 “Remote control configures the entire local daemon. Device pairing is a separate action, and pairing codes are redacted from event diagnostics.”，`enum Action` 为 `Menu`／`Enable`／`Disable`／`AddDevice`，`const OPERATION_TIMEOUT: Duration = Duration::from_secs(/*secs*/ 30);`。不带参数运行时 `slash_dispatch.rs`（60,668 字节）分派 `AppEvent::RemoteControl(Action::Menu)`，打开标题 `"Remote control"` 的菜单：副标题在已连接时为 `"Applies to local sessions; cloud sessions are unaffected."`，条目是按当前状态显示 `"Enable"`／`"Enable (disabled)"`／`"Disable"` 的开关加 `"Add device"`，未开启时 `"Add device"` 置灰并附原因 `"Enable remote control first"`。带非空内联参数时只回一句 `"Open /rc and choose Disable to turn off remote control."`，即 `/rc off` 一类写法不生效。

四道前置条件与三处落盘/超时语义：① 需要 Codex 自管的本地后台服务，拿不到时菜单副标题为 `"Remote control requires the local background server"`、非菜单动作直接报同一句；② 服务端版本校验以 `0.163.0-alpha.2` 为下限，不满足时报 `"Update the background server with /daemon to use persistent remote control."`；③ 开关写进守护进程 home 下 `app-server-daemon/settings.json` 的 `remoteControlEnabled`（文件不存在按 `false`），守护进程已改但偏好没写进去时报 `"Remote control changed for the running daemon, but the preference could not be saved. It may revert after restart."`，当前状态与已保存偏好不一致时菜单副标题改提示 `"Remote control is off now, but may return after restart. Choose Disable to save the preference."`；④ `"Add device"` 发 `RemoteControlPairingStart { manual_code: true }` 并取 `manual_pairing_code`，打开标题 `"Add device"`、副标题 `"Enter this pairing code on your other device: {code}. If it expires, select Add device again."` 的视图，拿不到码时报 `"No manual pairing code was returned."`。单次操作 30 秒超时（状态查询与其他动作的文案分别是 `"Remote control status timed out. Try again."` 与 `"The remote control operation timed out. Its outcome is unknown; reopen /rc to check the state."`），同一时刻只允许一个操作（`"A remote control operation is already in progress. ### 3. Qoder CLI：`/remote-control` 与 `/remote-env` 属漏记，本次补入

官方 Slash 命令参考 `.md` 变体（11,720 字节，与同日 `cmd-tasks` 单元取到的同一页逐字节相同）的 “## Remote and Other” 表逐字列出 “`/remote-control` — Remotely control the session.” 与 “`/remote-env` — Manage remote environments.”，同表另有 `/add-dir`、`/context`、`/docs`、`/help`、`/about`、`/feedback` 与 `/release-notes`；页末 “## Conditional Commands” 只列 `/agents`、`/plan`、`/workflows`、`/marketplace`、`/skills`、`/mcp` 与 `/setup-github`，两条命令都不在其中，即无条件可见。此前详情把 Qoder 记为「Qoder 提供 Remote Control 和 Cloud Mode 文档，但当前 Slash 命令目录没有独立远程控制命令」并标未确认、对照表写成「条件项：Cloud Mode」，都属漏记而非产品新增，本次一并改正。

`/remote-control` 的行为与子命令由官方 Remote Control 页给出（`https://docs.qoder.com/cli/remote-control.md`，3,617 字节；`https://docs.qoder.com/en/cli/remote-control` 同样 200）。首段逐字为 “Remote Control lets developers stay in control of running Qoder CLI Agents even when away from the computer — use your phone or browser to make critical decisions at key moments.”，并分两种模式：

- **远程控制模式**（针对已有会话）：“In a running qoder session, type: `/remote-control`”、“On success, a QR code and URL will appear. Scan the QR code with your phone camera, or copy the URL to open in a browser.”；用同一账号登录 Qoder 手机 App 后可 “View the local CLI's running status in real time”、“Approve or reject operations that need authorization”、“Send new tasks from your phone”；执行位置逐字为 “Your local terminal executes the tasks you dispatch remotely. All output files are saved on your local computer.”；停止方式为 “In the CLI, type: `/remote-control stop`”。
- **守护模式**（不需要先开会话）：“Run directly in your project directory (no need to start a qoder session first): `qoder remote-control`”，同样打印二维码与 URL；手机端 “Tap the "+" button in the bottom-right corner of the Qoder mobile app to create a new task.”、“You can send a second task without waiting for the first to finish”、“Each task's status and results are displayed independently”；CLI 侧 “processes tasks sequentially or in parallel”、“All generated files are saved on the computer running the CLI”；退出为 “Press `Ctrl+C` to exit.”。

两种模式都要求 “Your local computer must remain active.”；FAQ 逐字为 “Type `/remote-control status` in the CLI to view the current remote control connection status.” 与 “Visit https://qoder.com/agents in your browser to manage your remote tasks.”。CLI 参数参考 `.md` 变体（13,961 字节）的 `qoder <subcommand>` 表把 `remote-control` 描述为 “Start the remote-control daemon.”，同表另有 `mcp`、`plugins`、`skills`、`hooks`、`agents`、`login`、`commit`、`rollback`、`update`、`status`、`sites`、`feedback` 与 `wiki`；该页正文与示例统一用 `qoder` 作可执行名（“In addition to startup parameters, `qoder` also provides several subcommands in the form of `qoder <subcommand>`”），npm 包名 `@qoder-ai/qodercli` 只出现在安装页——本仓库 `surface-remote-control` 字段此前记的 `qodercli remote-control` 应据此校正，属另一字段、留作后续单元。

`/remote-env` 属云端环境选择而不是会话迁移，本次只在命令目录收录、结论仍归 `surface-cloud`：官方 Cloud Mode 页 `.md` 变体（5,015 字节）页首写 “The `--remote` mode runs your Qoder CLI tasks directly on a cloud VM managed by Qoder.” 与 “Complements the existing Remote Control mode.”，“### 2. Pick a cloud environment with /remote-env” 一节给出选择器文本 “Remote Environment / Select the default cloud environment.”，选择写进用户级 `~/.qoder/settings.json` 的 `remote.defaultCloudEnvironmentId` 并写 “All subsequent `--remote` invocations reuse this default environment — no need to pick it every time.”；命令参考表把它的 Where it works 记为 “Only inside the qoder interactive session (type `/` and pick it)”、Purpose 记为 “Select / switch / create a cloud execution environment as the default for `--remote`”、Scope 记为 “User level (written to `~/.qoder/settings.json`), shared across terminals”。Claude 命令表里同名的 `/remote-env`（“Choose the default cloud environment for cloud sessions you start from the CLI”）同理归 `surface-cloud`，本次只在 Claude 记录的条件栏点名边界。

版本线只能夹逼：官方 CLI 更新日志（`https://changelog.qoder.com/cli`，2026-11-20 核对，HTML 823,699 字节、去标签后正文 1,731 行、196 个版本条目，最新为 November 20, 2026 · CLI 1.1.94）里与远程控制相关的条目是 “Remote Control enabled by default”（April 29, 2026 · CLI 0.2.5 · 小节标题 “BYOK, Permissions & Remote Control”）、“Fixed remote control subagents not handling session reconnection properly”（CLI 0.2.9 段，同段另有 “Fixed /add-dir trusted directories still requiring read permission approval”）、“Improved the interaction experience for subagent, feedback, remote control, and other features”（July 14, 2026 · CLI 1.0.45）、“Added support for remote-controlled artifact display and download”（August 1, 2026 · CLI 1.1.11）与 “Improved the startup guidance shown for the remote control daemon”（August 7, 2026 · CLI 1.1.17 · 小节标题 “Status Line Enhancements”）。整份更新日志没有 `/remote-control` 或 `/remote-env` 的首次出现条目，因此两个命令的引入版本记为未确认，只能确认 CLI 0.2.5 起远程控制默认开启；二维码有效期、断线重连行为与 `/remote-control` 的完整子命令集合同样未确认。
