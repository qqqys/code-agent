# 代码 Review：Claude Code `/code-review --max-findings` findings 上限参数，并补录 `--post` 与 GitLab `--comment`

Claude Code 官方命令文档当前的逐字 synopsis 是 `/code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]`，别名 `/review` 一行给出同一 synopsis 与同一组级别和旗标。其中 `--max-findings` 由 v2.1.288 引入：官方 Code Review 页逐字写 “`--max-findings <n>`, `--max-findings all`, or `--max-findings default`: reports up to `n` findings, or every finding with `all`, in place of the review's usual limit. Later reviews reuse the value you typed until you pass `--max-findings default`. Requires Claude Code v2.1.288 or later”，更新日志（固定到提交 `1c229fcd1e1e`）逐字写 “Added `--max-findings <n>|all` to /code-review to report more or fewer findings than the usual limit; the choice is reused until you pass `--max-findings default`”。矩阵 `execution-review`（代码 Review）与 `cmd-review`（代码审查）两个字段的 Claude 列此前只记到 `[--fix] [--comment]`，没有 findings 条数参数。

本次同时补录同一批官方页面上此前缺失的两项：`--post`（v2.1.227 起，`ultra` 审查 `github.com` PR 时在启动对话框预选发帖）与 `--comment` 发 GitLab MR（v2.1.257 起，经 GitLab 的 `glab` CLI 发布为单条 note），以及 v2.1.290 更新日志记录的 medium 级别覆盖范围变化。其余四家无同类变化：Codex `/review`、Qwen Code `/review`（含 `--severity-floor` 严重级别过滤与 `--topology minimal` 固定至多 15 条 findings）与 Qoder CLI `/review [instruction]` 的当前一手资料都没有列出 Review findings 条数参数，Kimi Code 没有内置 `/review`，四家矩阵结论保持不变。

## 修正

- `execution-review`（代码 Review）矩阵 Claude Code 列由 “`/review` 为 `/code-review` 别名 · `ultra` 云审查 · GitHub Review” 更新为追加 `--max-findings n|all|default`（v2.1.288 起、取值跨审查复用直到传 `default`）、`--post`（默认 `--no-post`）与 `--comment` 自 v2.1.257 起可发 GitLab MR（经 `glab`）。证据状态维持“官方确认”。其余四家矩阵结论不变。
- Claude Code 详情（入口）把命令 synopsis 由 `[--fix] [--comment] [target]` 更正为官方逐字的 `[--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]`。
- Claude Code 详情（执行行为）补录：`--max-findings n` 限制为 `n` 条、`all` 报告全部 findings，两者取代审查的常规上限，输入取值被后续审查复用直到传 `--max-findings default`；官方文档只写“审查的常规上限”，没有给出默认条数，也没有给出复用值的保存位置。同时补录级别复用规则的完整条件（`-p` 传入的级别不更新被复用的值、`ultra` 既不更新也不使用、从未输入过级别时用会话当前 effort）、`--comment` 的 GitLab MR 单条 note 路径，以及 `--post` 的发帖形态（以本人 GitHub 账号发布、结尾带 “Generated by Claude Code” 的单条普通评论，不是 Review 也不是批准）与 `Posted`/`Already posted`/`Failed` 三种结果回报。v2.1.290 起 medium 级别在“没有调优审查设置的模型”（更新日志点名 Opus 5.5 与 Sonnet 5.5）上也报告清理类与 CLAUDE.md 约定类 findings。
- Claude Code 详情（外部写入）补录：本地审查读取仓库的 `CLAUDE.md` 文件并把新引入的违规当作 nit 级 findings；`--post` 的发帖不在本机执行，而是把审查的会话 ID 发给 Anthropic API，由 API 通过用户已连接的 GitHub 账号发布该审查已保存的 findings。
- Claude Code 详情（产物）补录：findings 列表每条显示文件位置、一句话摘要与 `correctness` 之类的分类标签；新增 GitLab MR 单条 note 与 `--post` 以本人账号发布的 PR 普通评论。
- Claude Code 详情（条件与边界）新增版本条件（`--max-findings` 需 v2.1.288、`--post` 需 v2.1.227、GitLab `--comment` 需 v2.1.257）与发帖条件：要求与审查本身相同的 claude.ai 登录，第三方 Provider 或设置 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 时不可用；审查分支或 GitHub Enterprise Server PR 时只在会话内显示 findings、不提供发帖；交互式会话须保持打开到审查结束，发帖选择只在当前会话保留、会话先结束则即使之后恢复对话也不发帖；非交互发帖只能用 `claude ultrareview --post`（运行该子命令即表示同意、不再询问），`claude -p '/code-review ultra'` 会在 findings 到达前退出因而不发帖。
- 跨产品事实新增两条：一条记录 `--max-findings` 的三种取值与复用规则及官方文档未给出的两项信息，一条记录 findings 数量控制在五家中的分布（只有 Claude Code 提供显式条数参数）。
- `cmd-review`（代码审查）Claude Code 详情同步更新 synopsis、参数、运行界面、持久化与条件，并新增一条跨产品事实。
- `site/data.js`：`updatedAt` 由 2026-10-05 更新为 2026-10-06；新增来源 `claude-v21288-max-findings-changelog`（提交 `1c229fcd1e1e` 的更新日志）与 `claude-v21290-review-changelog`（提交 `e8ae451830fb` 的更新日志）；能力字段总数不变（114 个）。
- `docs/09-版本与证据.md`：Claude Code 核对日期由 2026-10-05 更新为 2026-10-06，主要材料追加“代码 Review findings 上限与发帖参数”条目；官方来源表“执行与 Git”列 Claude Code 追加两个更新日志链接。
- `README.md` 核对日期更新为 2026-10-06。
- `npm run generate` 重新生成 `docs/01-Slash命令矩阵.md`、`docs/06-任务执行与Git矩阵.md`、`docs/capabilities/commands/`、`docs/capabilities/execution/`（含各页核对日期）；`npm test` 通过。

## 证据版本

- 官方命令文档 <https://code.claude.com/docs/en/commands>（2026-10-06 核对）逐字给出 `/code-review` 与 `/review` 两行 synopsis：`/code-review [low|medium|high|xhigh|max|ultra] [--fix] [--comment] [--max-findings n|all|default] [pr#|branch|path]`，说明文字含 “Pass `--fix` to apply findings, `--comment` to post them on the GitHub PR or GitLab merge request, or `ultra` to run a deep cloud review. Posting to a GitLab merge request requires Claude Code v2.1.257 or later. With `ultra` on a `github.com` PR target, pass `--post` to preselect posting the finished findings to the PR in the launch dialog; `--post` requires Claude Code v2.1.227 or later.”；`/review` 行另记 “Before v2.1.223, `/review` was a separate command that ran a single-pass, read-only review of a GitHub pull request by number, listing open PRs to pick from when run with no argument; from v2.1.186 through v2.1.201, it ran the same multi-agent engine as `/code-review medium`”。
- 官方 Code Review 文档 <https://code.claude.com/docs/en/code-review>（2026-10-06 核对）逐字记录 `--max-findings` 条目（见上）、`--post` 条目、“At `low` and `medium`, the review reports only the findings it's most confident in, so you see fewer false positives; `high` through `max` broaden coverage and may include findings the review is less sure about.”、级别复用规则（含通知文案 `Reusing high effort, the level you typed last time`、“a level you pass in a non-interactive `-p` run doesn't update it”、“`ultra` neither updates nor uses the remembered level”、“If you've never typed a level, the review uses the session's current effort.”）、“When you pass `--comment` for a GitLab merge request, Claude Code posts the findings through GitLab's `glab` CLI. Requires Claude Code v2.1.257 or later.”、“Claude Code renders the report as a findings list, and each entry shows the file location, a one-sentence summary, and a category tag such as `correctness` when the finding carries one.”、“Code Review reads your repository's `CLAUDE.md` files and treats newly introduced violations as nit-level findings.”，以及 `/simplify` 为只清理并默认应用修复、不找缺陷的独立审查。该页没有给出常规 findings 上限的条数，也没有给出 `--max-findings` 复用值的保存位置，两处按“未确认”记录。
- 官方 ultrareview 文档 <https://code.claude.com/docs/en/ultrareview> 的 “Post findings to the pull request” 一节（2026-10-06 核对）逐字记录：v2.1.227 起审查 `github.com` PR 时可把完成的 findings 以本人 GitHub 账号发为单条普通评论，该评论不是 review 也不是 approval 且结尾带 “Generated by Claude Code”；审查分支或 GitHub Enterprise Server PR 时只在会话内显示；“Claude Code never posts unless you choose to on that run, and `--no-post` is the default.”；交互式在启动对话框选 **Run and post the findings to the PR as me**，加 `--post`（如 `/code-review ultra 1234 --post`）只预选该选项、仍然询问后才启动；非交互用 `claude ultrareview` 子命令加 `--post`，运行即表示同意、不再询问，而 `claude -p '/code-review ultra'` 会在 findings 到达前退出因而不发帖；发帖不在本机执行，而是把审查的会话 ID 发给 Anthropic API，由它通过用户已连接的 GitHub 账号发布该审查已保存的 findings；要求与审查本身相同的 claude.ai 登录，第三方 Provider 或设置 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 时不可用；交互式会话在 findings 到达时开始发帖，须保持会话打开直到审查结束，发帖选择只在该会话保留，会话在审查结束前终止则不发帖、即使之后恢复对话；结果分 `Posted`（给评论链接）、`Already posted`（同一次审查已发过、改给 PR 链接）、`Failed`（说明原因且 findings 留在终端供手工发布）。
