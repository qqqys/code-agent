## 本次改动

本次以 Kimi Code 当天发布的 2.5.0 为起点，把「会话分支」在五家全部重新核对，结果作废了四条旧结论（Kimi 的「回合运行中 fork 报错」、Kimi 的「恢复命令打印尚未发布」、Codex 的「`codex exec fork` 尚未进入 Release 且官方文档未列」、Qoder 的「TUI 命令表未列出 `/fork` 或 `/branch`、能力只在 SDK」），并补齐了 Claude 的分支继承表与 Codex 新出现的顶层 `codex fork` 子命令。

**Kimi Code 2.5.0 让「运行中 fork」与「历史回合 fork」同时落地**（GitHub Release `@moonshot-ai/kimi-code@2.5.0` 的 `<published>` 为 2026-11-04T11:52:02Z，Release 页指向提交 `41c341434ae24e45bfe0f2232ec11b80531ac717`；npm 上 `@moonshot-ai/kimi-code@2.5.0` 发布于 2026-11-04T11:59:13.163Z 且是当前 `latest` dist-tag）：

- **官方 CHANGELOG 的 `## 2.5.0` 段 Minor Changes 逐字为** “Add support for forking running sessions and forking from a selected historical turn.”（PR #4544，提交 `e24e1e1919d729edaa8fe0d60b820cd8f4fdd2b5`，author date 2026-11-02T05:26:33Z）。该提交新增的 `.changeset/fork-running-session-turns.md`（127 字节）frontmatter 为 `"@moonshot-ai/kimi-code": minor`，正文与 CHANGELOG 逐字一致；提交信息的分提交含 “feat(agent-core-v2): support forking running sessions / Keep source turns running while forking only completed history. Expose historical turn selection through klient and the server API.”、“fix(agent-core-v2): allow forks before the first turn completes” 与 “feat(agent-core-v2): preserve active prompts in running forks”。
- **作废旧结论「0.36.1 起在回合运行中 fork 会报错，不再复制未写完的回合」**：0.36.1（npm 2026-08-14T12:53:34.177Z）的 PR #2916（提交 `7475c2e2e3dd86ac0b8a8d51d4f1d233ed7df797`）确实加过这条拒绝——changeset `.changeset/fork-busy-rejection.md` 逐字为 “Show a clear error when forking a session while its turn is running, instead of copying a partially written turn.”，同批的 `.changeset/sdk-v2-fork-turn.md` 逐字为 “Support forking a session from a specific turn in the v2-backed client, and reject forking a live session while its turn is running.”，实现里抛出的消息是 `Session "<id>" cannot be forked while a turn is running`。PR #4544 的 diff **整段删除**了 `if (agentHandle.accessor.get(IAgentLoopService).snapshot().state === 'running') { throw new Error2(ErrorCodes.SESSION_FORK_ACTIVE_TURN, …) }`，并把 `tryAcquireQuiescence()` 拿不到 hold 时的消息由 “cannot be forked while a turn is running or queued, or while another fork is copying it” 改为 “cannot be forked while another session history operation is in progress”。2.5.0 提交下的 `packages/agent-core-v2/src/workspace/sessionLifecycle/sessionLifecycleService.ts`（42,578 字节）已完全不含 “cannot be forked while a turn is running”，`SESSION_FORK_ACTIVE_TURN` 只剩「另一个会话历史操作正在进行」这一种触发条件。
- **运行中 fork 的边界有了官方逐字口径**：中文服务 API 参考 `docs/zh/reference/server-api.md`（2.5.0 提交下 158,601 字节，与 main 同字节数）的 `#### POST /api/v1/sessions/{session_id}:fork` 一节由 “当会话中任一 Agent 有进行中的轮次时，fork 会被拒绝。” 改为 “将会话——其转录、Agent 状态与文件——复制到同一工作区中的新会话，并广播 `event.session.created`。源会话会继续运行；如果存在进行中的轮次，fork 会保留该轮次之前最近一个已完成的边界，并将当前轮次的用户 prompt 保存为一个仅含 prompt 的 `cancelled` 轮次，不包含 Assistant 输出、工具活动、排队输入或后续事件。”，英文页对应 “The source keeps running. If a turn is active, the fork retains the last completed turn before it and the active turn's user prompt as a prompt-only `cancelled` turn; active assistant output, tool activity, queued input, and later events are excluded.”
- **历史回合分支的三个入口与锚点约束**：服务 API 的参数表新增一行 `turn_index`（body，integer）逐字为 “要保留到的持久化 engine `turnId`（包含该轮次），允许编号空洞。必须是非负安全整数，且该轮次已经完成”，错误码新增 “`40001`：`turn_index` 无效、不存在或选中了进行中的轮次”，原有 “`40901`: the session has an active turn and cannot be forked” 在中英文两页各删一处、改为 “`40901`: another session history operation is in progress”；klient 的 `SessionFacade` 签名逐字为 `fork(input?: { title?: string; metadata?: Record<string, unknown>; turnIndex?: number; }): Promise<SessionMeta>;`，node-sdk 的 `forkSession(input: ForkSessionInput)` 把 `{ sourceSessionId, newSessionId: input.forkId, title, metadata, turnIndex }` 交给 App 作用域的 `ISessionManager.fork`，方法注释写明失败以 v1 的码与 details 跨进程内调用返回（`request.invalid` 带 `{turnIndex, availableTurns}`、`session.fork_active_turn`），并记默认标题 “v1: "New Session", v2: "Fork: <source>"”；引擎侧 `assertForkTurnIndex` 的报错逐字为 “forkSession turnIndex must be a non-negative safe integer”。`POST /api/v1/sessions/{session_id}/children` 一节改为 “运行中的源会话采用与 `:fork` 相同的已完成轮次边界，以及仅含 prompt 的 `cancelled` 当前轮次；创建子会话不接受历史 `turn_index` 参数。”
- **TUI `/fork` 本身没有历史回合入口**：2.5.0 提交下的 `apps/kimi-code/src/tui/commands/session.ts`（7,444 字节，与 main 同字节数；该路径最后一次改动是 `5f3ab5fac81e050fc2fa10787dd560655f377d16`，2026-10-29T12:43:07Z）里 `handleForkCommand(host, args)` 首行即 `void args;`，只调用 `host.harness.forkSession({ id: session.id })`，既不传 `turnIndex` 也没有任何回合运行中的前置判断；PR #4544 没有改动 `apps/kimi-code` 下任何文件（只改 `packages/agent-core-v2`、`packages/klient`、`packages/node-sdk`、`packages/kap-server`、`apps/vscode` 与两份 server-api 文档），因此历史回合选择只经 klient、node-sdk 与服务 API 暴露，VS Code 扩展另有 `apps/vscode/shared/fork-turn-index.ts`（属其他 Surface）。TUI 侧的 `host.harness` 类型是 `@moonshot-ai/kimi-code-sdk` 的 `KimiHarness`（`apps/kimi-code/src/tui/commands/dispatch.ts` 第 5 行导入），即 `/fork` 与 SDK 走同一条引擎路径。
- **作废旧结论「恢复命令打印与剪贴板复制于 2026-08-15 合入 main，尚未发布」**：官方 CHANGELOG 把 “Print and copy the full `kimi --resume` command after `/fork`.”（PR #2940，提交 `6b72345f8bb03487e3bcc05b541e65484818428c`）列在 **`## 0.37.0`** 段，npm 上 0.37.0 发布于 2026-08-18T11:23:08.390Z；`@moonshot-ai/kimi-code@2.4.1` 标签下的同一文件（7,440 字节）已含 `forkResumeCommand`、`Command copied to clipboard`、`Command copied via terminal escape sequence (unverified)` 与 `Failed to copy command to clipboard`，2.5.0 提交下也仍在（唯一措辞差异是 `failed to release its runtime` 在 2.5.0 变成 `failed to release its environment`，随 PR #4062 的远程环境改动）。
