# 生命周期 Hooks：Claude Code v2.1.312 把 prompt 与 agent Hook 的并发口径改为每会话 24 个（含 Subagent）并给 `timeout` 加 1 秒下限，官方 Hooks 参考页首次写出并发段落，Codex 三条「尚未发布」随 rust-v0.165.0 过期

本字段在 2026-10-19 那轮核对里留下三条未确认：Claude Code 的 12 个并发上限是否同样约束 command、http 与 `mcp_tool`，是按事件还是按会话计，以及排队等待的时间是否计入 Hook 自身的 `timeout`。这次官方 Hooks 参考页与 v2.1.312 更新日志各给出了一半答案，而且两边对不上。

官方 [Hooks 参考页](https://code.claude.com/docs/en/hooks#hook-handler-fields)（2026-10-28 抓取 `.md`，282,379 字节，比 2026-10-19 记录的 273,668 字节增加，本次取到全文而不是前 100,000 字符）在 “Hook handler fields” 一节新增了一段并发说明，逐字为 “When an event fires, its matching hooks run in parallel. If more than 12 of them are prompt or agent hooks, 12 of those run at once and the rest start as running ones finish. Each waiting hook's [`timeout`](#common-fields) starts counting when that hook starts.”，紧接的一段是此前已记录的 “If you define the same handler in more than one settings file, it runs once. A plugin's or skill's copy of the same handler stays separate.”。据此两条未确认有了官方口径：这个数字只约束 prompt 与 agent 两类 Handler（该句没有给 command、http 与 `mcp_tool` 任何上限，全页也没有别的并发数字），排队等待不计入 Hook 自身的 `timeout`——`timeout` 从该 Hook 真正开始运行时才起算。

[Claude Code v2.1.312](https://github.com/anthropics/claude-code/releases/tag/v2.1.312)（2026-10-27T20:24:20Z 发布，更新日志固定到提交 `0e1f4789406477380b267a01f3ddd50b0211e5b3`，该提交于 2026-10-27T20:23:56Z 更新 `CHANGELOG.md` 与 `feed.xml`）里与本字段相关的一条逐字为 “Changed prompt and agent hooks to run at most 24 at a time per session, sub-agents included, plus at most 12 that have waited longer than their event's timeout; a `timeout` under 1 second now counts as 1 second”。它把 v2.1.302 的「同一事件至多 12 个」改成「每会话至多 24 个」并把 Subagent 计入同一预算，另外容许至多 12 个等待时间已超过其事件 `timeout` 的排队 Hook，同时给 `timeout` 加了 1 秒下限。参考页在核对日期仍写「同一事件 12 个」、没有出现 24 这个数字、也没有说 Subagent 是否共用预算，`#### Common fields` 的 `timeout` 行与 `#### Timeouts` 一节都还没有 1 秒下限，所以「按事件还是按会话计」以及「24 与 12 相加是否意味着同一会话最多 36 个 prompt/agent Hook 同时在跑」这两点改成记为两处一手资料冲突、只有一处记录。Hooks 指南页（66,090 字节）只写 “When an event fires, Claude Code runs the matching hooks in parallel” 并把重复 Handler 的处理指向参考页，没有任何数字。同版另有两条 Hook 条目属其他方面、本次未处理：v2.1.311 的 “Fixed `SubagentStop` hooks running about twice a minute for each running subagent instead of once when it finishes” 属事件触发频次，v2.1.310 的 “Windows: Fixed PreToolUse and PermissionRequest hooks letting a tool call through when Git Bash is missing and the hook's command is only quoted strings, such as a quoted path” 属失败语义。

顺着同一条并发线复核其余四家，结论是四家的口径都没变，但三家的发布坐标已经过期。Codex 官方 [Hooks 页](https://learn.chatgpt.com/docs/hooks)（2026-10-28 以 `.md` 复核，47,133 字节）的三句并发口径逐字未变，同步 command Hook 仍没有数字上限、后台 Hook 仍是每会话 8 个；源码侧最新非 alpha Release [rust-v0.165.0](https://github.com/openai/codex/releases/tag/rust-v0.165.0)（2026-10-27T20:09:38Z 发布，标签对象 `e374836b2728d9b7aa981c2902649e640a2edaa8` 指向提交 `360319d8dee62d87e2d59fc0c21805d79519cfed`）下 `codex-rs/hooks/src/engine/dispatcher.rs`（22,340 字节）的 `execute_handlers_with_metadata` 仍把每个同步 Handler 逐个推进同一个 `FuturesUnordered`、文件里没有条数上限或信号量，`HookExecutionMode::Async` 的走 `schedule_async_hook`；该标签新增 `HandlerSourcePath::ExecutorScoped` 一支，environment 作用域的 Handler 先被挑出同步批次，等本地同步 Hook 全部结束并排序后只在 `should_stop || !should_block` 时用 `schedule_async_task` 异步投递、失败只压一条 `executor-scoped hook failed` 警告，官方文档没有描述这层顺序。用 GitHub compare 接口核对，此前记为「合入 main 尚未发布」的三个提交 `70b3bb6d8814ab3f2045238b4ae14c43da99783b`（观察型 `PreModelRequest`/`PostModelRequest`）、`87070a77925c`（会话内 Hook MCP 执行）与 `d35e5495f991`（Hook MCP 调用改经当前连接集）相对该标签都是 `status: behind`、`ahead_by: 0`，即都已发布：标签下 `codex-rs/protocol/src/hooks.rs`（7,482 字节）的 `HookEventName` 列出 14 个 serde 名、前两个就是这两个事件，`codex-rs/core/src/hook_mcp_executor.rs`（2,143 字节）的 `CoreHookMcpExecutor` 持有会话 `Arc<McpRuntime>` 与 `thread_id`，`codex-rs/hooks/src/engine/mcp_runner.rs`（6,360 字节）的入口签名是必填的 `executor: &dyn HookMcpExecutor`，“MCP invocation is not available yet” 字样与 `mcp_executor` 标识符在 `hook_runtime.rs`（52,157 字节）与 `session/mod.rs`（231,366 字节）里都已消失。官方 Hooks 页的事件表仍是 12 个、发布说明也没有提到这两个事件（该版与 Hook 相关的五条是 SigV4 代理 MITM hooks、prompt telemetry、environment attachments、environment-scoped managed hooks 与 environment hooks on their owning executors，属其他方面），因此改记为「已发布但官方文档未列」。另外 `codex-rs/config/src/hook_config.rs` 在这个标签只剩 2,293 字节、改为重导出 `codex_protocol::hooks::HookEventsToml`，此前按 `matcher_groups_mut` 数组长度记事件数的坐标随之失效。
