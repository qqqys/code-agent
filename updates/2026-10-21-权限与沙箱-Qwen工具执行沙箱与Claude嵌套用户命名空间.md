# 文件系统隔离：Qwen Code v0.24.4 起的 Linux 工具执行沙箱 `tools.executionSandbox`、Claude Code v2.1.305 的 `sandbox.allowNestedUserNamespaces`，并更正 Codex 的 Linux 后端与 Qoder 的沙箱文档状态

本次只处理 `security-filesystem`（文件系统隔离）一个能力字段，能力字段总数维持 115。这一轮同时带来一处「矩阵尚未记录的新功能」、两处更正与一处结论降级，主线是三家的 Linux 边界都落在 bubblewrap 上，而 bubblewrap 在 Linux 上要先能创建用户命名空间。

最大的缺口在 Qwen Code。本仓库此前的 Qwen 列只写「Seatbelt 或容器 Sandbox；默认关闭」，把 `qwen-sandbox` 来源固定在提交 `2e08486b529bf64ca3b31d13424ad12f1100de93`。核对日期标签 v0.25.3（提交 `b28b0d948fa28b89750ac5f1525b95e1746f47ab`）下的 `docs/users/features/sandbox.md` 首句已经是 “This document explains tool execution confinement on Linux and the existing whole-CLI sandbox methods.”，整份文档 17,891 字节、与 main 分支同文件逐字一致，开头第一大节就是 “## Linux tool execution sandbox”。这是一层此前完全没记录的机制：策略键 `tools.executionSandbox` 由运算符（User 设置 `~/.qwen/settings.json`，或 `QWEN_HOME` 选择的目录；或管理员 System 设置）所有，必填 `filesystem`（`read-only` 或 `workspace-write`）与 `network`（`open` 或 `closed`）、可选 `backend`（默认 `auto`，或 `bwrap`、`landlock`）；只有命令及其子进程进边界，CLI 本体、模型传输、认证与会话存储留在宿主。旧的「整个 CLI 跑在 bwrap 里」的启动路径已被移除，官方给了专门的迁移小节，源码里的迁移报错是 `BWRAP_MIGRATION_MESSAGE`。往前追版本时间线：PR #12267（提交 `1afbcffe21c98046670e8e4837a640f5d50465b1`，2026-09-22T10:55:51Z）把 bwrap 沙箱移到工具执行，首个记录该节的稳定标签是 v0.24.4（提交 `9674d6efdc8ac16583270bd2a55cfa49e3ec254e`，2026-09-22T15:15:06Z 发布），当时文档还写 “Landlock is not available in this release.”，而再前一个稳定标签 v0.24.0 的同文件只有 8,559 字节、Linux 方法仍只有 “Use Docker or Podman.”；PR #12278（提交 `1a5a74bc35b5ac35298118af81df8a973d49260a`，2026-09-29T03:45:46Z）加入 Landlock 回退，首个记录它的稳定标签是 v0.24.7（提交 `b12edec1401a28fc53cd9e714d5928b285071fc8`，2026-09-29T14:02:21Z 发布）；PR #13140（提交 `09411aa0a9193b2e1d86f1a8de7c65e513757a52`，2026-10-03T12:02:48Z）收紧设置失败与沙箱命令流。也就是说这一层在稳定通道已经存在一个月，矩阵一直没跟上。

第二处是 Claude Code 的新键。官方仓库 `CHANGELOG.md`（main 分支，固定到提交 `49b8c35f8c57493c2f0eba1429ccaa9638ab8712`，2026-10-20T20:46:27Z，提交说明 “chore: Update CHANGELOG.md and feed.xml”，只改 `CHANGELOG.md` 与 `feed.xml`）在 `## 2.1.305` 段下逐字写明 “Added `sandbox.allowNestedUserNamespaces` so sandboxed commands on Linux can create user namespaces (Chromium, rootless podman); this lets them get around the sandbox's file protections”，对应 Release [v2.1.305](https://github.com/anthropics/claude-code/releases/tag/v2.1.305) 发布于 2026-10-20T20:46:50Z。官方两页在核对日期都还没跟进：Sandboxing 页（95,397 字节）全文 `allowNestedUserNamespaces` 出现 0 次，Settings 参考页的索引表也没有该行。因此它的取值集合、默认值、可写作用域与版本门槛记为未确认，它同 `enableWeakerNestedSandbox` 的分工（一个放行沙箱内自己建用户命名空间、一个改挂容器已有的 `/proc`）官方也没有说明。顺着这一层复核时还发现，官方文档里早已存在、但本仓库一直没记的 `sandbox.enableWeakerNestedSandbox` 与 Ubuntu 24.04 及以后的 AppArmor 用户命名空间前置条件也一并补上了。

第三处是更正。本仓库此前的跨产品事实第 2 条写「Codex 在 macOS 用 Seatbelt、Linux 用 Landlock」。Codex 官方 Sandboxing 页（492,064 字节）的口径不是这样：它写 “Codex uses platform-native enforcement on each OS. The implementation differs between macOS, Linux, WSL2, and native Windows”，macOS 是 “the built-in Seatbelt framework”，Windows 是 “Codex uses the native Windows sandbox when you run in PowerShell and the Linux sandbox implementation when you run in WSL2”，而 Linux 一侧逐字为 “Codex uses the first `bwrap` executable it finds on `PATH`. If no `bwrap` executable is available, Codex falls back to a bundled helper, but that helper requires support for unprivileged user namespace creation.”，全页没有 Landlock 或 seccomp 字样。回到仓库核对：标签 `rust-v0.164.0-alpha.9`（提交 `bcee56bcdb74cbf08fc6dd47ef0079fded4bba9a`）下 `codex-rs/linux-sandbox/Cargo.toml` 的 Linux 依赖段确实同时列出 `landlock` 与 `seccompiler`，但构造边界的是同目录 `src/bwrap.rs`（1522 行），它在两处参数构造里都显式加 `--unshare-user`。所以旧记录不算凭空捏造，而是把 crate 的实现依赖当成了官方口径的边界；现在改成文档口径为 bubblewrap、Landlock 与 seccomp 另注为实现依赖。

第四处是结论降级。本仓库此前的 Qoder 列写「路径权限规则；SDK 条件 Sandbox」，详情里写「SDK 的 `sandbox.filesystem` 可设置 allow/deny read/write，且 Sandbox 默认关闭」，来源为 `qoder-sdk-reference`。核对日期这些都已无法复核：官方文档索引 `https://docs.qoder.com/llms.txt`（646 个链接，其中 96 个为 `/cli/` 页面）里没有 CLI 的 Sandbox 页，此前引用的 `https://docs.qoder.com/en/cli/sandbox` 与 `https://docs.qoder.com/cli/sandbox` 都返回 404；逐页抓取这 96 个 `/cli/*.md` 后只有三页出现 sandbox 字样，设置参考页（30,253 字节的 Markdown 形式）与 SDK 参考页都没有任何 `sandbox.*` 键。Qoder 列因此由「条件项」改为「未确认」。索引里含 sandbox 的其余链接属 Qoder IDE（`qoder/approval-and-sandbox`、`user-guide/quest/terminal-and-sandbox` 等）与 Cloud Agents 两个别的 Surface，按本仓库的 Surface 规则不并入 CLI。

Kimi Code 一侧结论没变，但依据变硬了：2.3.0 标签提交 `b5e28fd6beac752a2cdcc0ff2f5fdf40e6494fbb` 的整棵仓库树里没有任何路径含 sandbox、bwrap、bubblewrap、landlock、seccomp 或 seatbelt 字样，该标签的 `docs/zh/configuration/config-files.md`、`docs/zh/reference/tools.md` 与 `docs/zh/configuration/env-vars.md` 也都没有这些词；文件边界由 `packages/agent-core-v2/src/agent/permissionPolicy/policies/` 下的策略与 `packages/agent-core-v2/src/tool/path-access.ts` 的路径判定提供，属权限规则层而不是 OS 或容器隔离层。
