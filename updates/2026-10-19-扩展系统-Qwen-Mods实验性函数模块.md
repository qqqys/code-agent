# 生命周期 Hooks：Qwen Code v0.25.3 的实验性 Mod API（Claude Code Mod API 子集，隔离 QuickJS worker），并更正 headless 提示词门禁的稳定通道发布状态

Qwen Code 在 v0.25.3 稳定通道（2026-10-19T06:06:37Z 发布，标签提交 `b28b0d948fa28b89750ac5f1525b95e1746f47ab`）的 Features 里列出 “feat(mods): support commands in interactive terminals (PR4a) (#14268)”，官方文档 `docs/users/extension/mods.md`（同一标签下 24,532 字节）逐字写 “Qwen Code can run a small subset of the Claude Code Mod API in headless and interactive terminal sessions.”。这是本字段此前没有记录的一手确认新功能：矩阵原记录把 Qwen 的函数 Hook 写成「运行时还存在 session-only 的内部 function Hook」「由 Skill 系统内部使用、当前不作为面向终端用户的公开 API」，而现在 Qwen 有了一个面向终端用户、可安装的实验性 Mod API。它与 Claude Code 自 v2.1.287 起的 mod 同源——同样用插件 `hooks/hooks.json` 顶层的 `modules`（官方示例 `{ "modules": ["./register.js"] }`）声明一个 ESM 入口、同样导出 `register(on, options)`——但官方明确写这是 “a supported subset, not full compatibility with existing Claude Mods”，作者 API 基于 Claude Code 2.1.296 声明、再入行为遵循 Claude Code 2.1.301。

两家的 mod 在运行位置与权限方向上正好相反，这一点写进了跨产品事实：Claude 的 mod 在 Claude Code 自己的进程里运行、不进沙箱、能读写文件与发起网络请求、能批准工具调用从而绕过 `ask` 规则与 `PreToolUse` 阻断，并能绘制 pane 与 band；Qwen 的 mod 运行在「每插件一个、位于会话 worker 内的隔离 QuickJS 环境」（官方逐字 “Separate QuickJS environment per plugin inside a session worker; no Node, filesystem or network APIs; memory, stack, source/output and execution limits”），官方逐字写 “a Mod cannot upgrade a native deny or ask to allow.”“A Mod-authored `rule`, `hook` or `ceiling` cannot create host permissions.”，且每次普通 `tool.call` 的 `next` 都重新走一遍原生校验、经典 Hook、权限、审批与调用守卫，也不绘制界面。Codex、Kimi 与 Qoder 公开可配置的 Handler 仍在进程外执行（Codex command 与 `mcp_tool`、Kimi command、Qoder command/HTTP/prompt/agent），没有进程内或隔离 worker 的函数模块。

Qwen mod 的能力边界取自官方文档：`experimental.mods: true` 开启（默认关闭），还要求受信任工作区与一个已启用的 Claude 或原生 Qwen 扩展，Agent Plugins v1 便携包继续忽略 hooks，安全模式、bare 模式与 `disableAllHooks` 都阻止加载；mod 用 `$.command.register({ name, description, argumentHint })` 在 `session.start` 期间注册不经模型请求运行的 Slash 命令（“Commands cannot return `context`, `exitCode` or engine references yet.”），用 `on(<event>, ...)` 拦截 `session.start`/`session.end`/`command.run`/`command.register`/`ui.log`/`tool.call`/`tool.check` 七类事件（事件名支持精确名、`command.*` 一类前缀、`*` 与单个 `!session.*` 否定，`!*` 与 `!!...` 被拒绝），用 `$.ui.log` 写 transcript（text 模式走 stderr、JSON 模式走 `system/ui_log`，都不进模型输入、每条上限 2,000 字符），模块变量在 stream-json 或交互进程里跨回合保留而 `/clear` 与 `/resume` 不重载模块，`state`/`store`、渲染、流式事件、热重载、JSX/TSX、运行时 package import、内置命令拦截、工具注册与 `$.tool` API 都未实现；工具拦截（`tool.call` 返回 `{deny}`/`{result}`、`tool.check` 的 `next` 返回带 `decision`（`allow`/`ask`/`deny`）的对象）只在 headless 会话可用，交互终端（Ink 与 OpenTUI）只支持命令、生命周期与日志，显式 `tool.call`/`tool.check`/`tool.*` 注册会在模型请求前拒绝初始化，而 ACP、managed/SSH、sandbox 与 session-agent 入口在本版本不运行 mod（官方逐字 “Mods do not run in ACP, managed/SSH, sandbox or session-agent entry points in this version.”）；`pluginConfigs.<mod>.toolDialect` 取 `claude` 或 `native`（默认）切换 `run_shell_command`↔`Bash`、`edit`↔`Edit`、`write_file`↔`Write` 方言，`pluginConfigs.<mod>.options` 对应 manifest 的 `userConfig`，选项按 SystemDefaults → User → System 合并且工作区设置即使受信任也忽略，`sensitive: true` 显式不支持、没有密钥存储或配置 UI；安装用 `qwen extensions install ./hello-mod --consent`。交互终端支持随 PR #14268（合并提交 `2eafeebc556075b24c5a922f2b565254195e4692`，2026-10-16T10:20:23Z 合入 main，把此前只支持 headless 的隔离 mod 运行时接到 Ink 与 OpenTUI 两个渲染器）接入。

同一轮复核还更正一条发布状态。本字段此前记录 headless 下命令与 Skill 输入改在展开前先过 `UserPromptSubmit`（PR #14356，提交 `52ae53b02a17d6214e9e4f81578f2ba2725539a6`）「已在预览通道 v0.25.3-preview.0 发布、稳定通道 v0.25.2 尚未包含」。v0.25.3 稳定通道的 Bug Fixes 逐字列出 “fix(hooks): gate headless file and skill prompts before expansion (#14356)”，因此这条已随稳定通道发布，矩阵单元格与详情页的发布状态据此更正，此前「稳定通道最新 Release 仍是 v0.25.2、尚未包含」的记录随之过期。

本次只处理 `extension-hooks` 一个能力字段，能力字段总数维持 115。`updatedAt` 维持 2026-10-19（核对日期当天，且本次证据均取自 2026-10-19 复核的 v0.25.3 标签与发布说明），五列核对日期不变；Qwen 列证据状态维持「源码确认」（mod 由官方文档与稳定 Release 确认，但该列其余内容仍以源码取证为主，沿用既有标签），其余四列证据状态不变。

## 修正

- `extension-hooks`（生命周期 Hooks）矩阵 Qwen 列结论改写：把 headless 提示词门禁的发布状态由「（v0.25.3-preview.0，稳定通道 v0.25.2 尚未包含）」更正为「（v0.25.3 起稳定通道包含）」，并新增一条条件项「`experimental.mods` 开启后插件 `hooks/hooks.json` 的 `modules` 注册隔离 QuickJS 函数模块（mod，Claude Code Mod API 子集），交互终端与 headless 注册 Slash 命令、拦截生命周期并写 transcript 日志，`tool.call`/`tool.check` 工具拦截仅 headless（v0.25.3 起）」。其余四列结论不变。
- 能力「本页包含」把 mod 一项由「插件内进程执行的 JS/TS 函数 Hook 模块（mod）与其界面绘制」改为「插件携带的 JS/TS 函数 Hook 模块（mod）：Claude Code 在自身进程内执行并可绘制界面，Qwen Code 在隔离 QuickJS worker 中执行、不绘制界面」，以同时覆盖两家不同的运行位置。
- 跨产品事实第 3 条改写：在 Claude mod 之后补 Qwen 自 v0.25.3 起的实验性 Mod API 子集（`experimental.mods`、隔离 QuickJS、七类事件、工具拦截仅 headless、不绘制界面），并把「其余四家公开可配置的 Handler 都在进程外执行」收窄为「Codex、Kimi 与 Qoder 公开可配置的 Handler 仍在进程外执行……没有进程内或隔离 worker 的函数模块」，同时保留 Qwen 内部 `function` Handler 与面向终端用户的 mod 是两回事这一区分。
- 跨产品事实第 4 条改写：把笼统的「mod 更进一步」明确为「Claude 的 mod」，并新增「Qwen 的 mod 走相反方向」一句，逐字引用官方的不可提权与不可创建宿主权限两条，以及每次 `tool.call` 的 `next` 重新走原生校验链。
- Qwen 详情：`entry` 补 mod 的安装与加载入口（`qwen extensions install <dir> --consent`、`experimental.mods` 与受信任工作区）；`components` 新增整段实验性 Mod API（开启键、目录与清单、ESM 入口后缀、隔离与限额、命令注册、七类事件与匹配模式、`$.ui.log` 与 2,000 字符上限、模块状态保留、未实现项、工具拦截仅 headless 与交互终端范围、`toolDialect` 与 `options`、选项优先级）；`conditions` 把 headless 门禁的发布状态更正为随 v0.25.3 稳定通道发布并标注旧记录过期，另新增整段 Mod API 边界（默认关闭、受信任工作区与扩展要求、Agent Plugins v1 忽略 hooks、safe/bare/`disableAllHooks` 阻止加载、可用与不可用 Surface、不可提权与无密钥存储、PR #14268 与 v0.25.3 发布坐标、作者 API 基于 Claude Code 2.1.296/2.1.301）；`sources` 由 6 条增至 9 条。
