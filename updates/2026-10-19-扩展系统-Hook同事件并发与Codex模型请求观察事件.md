# 生命周期 Hooks：Claude Code v2.1.302 的 prompt 与 agent Hook 同事件 12 个并发上限、Codex `PreModelRequest`/`PostModelRequest` 观察型事件，以及五家同事件执行顺序核对

Claude Code v2.1.302（2026-10-16T20:53:06Z 发布）的更新日志里有一条属于本字段、此前只在 `agent-background` 的来源标签里被顺带引用而没有写进 Hooks 记录的变更，逐字为 “Changed prompt and agent hooks so that at most 12 of one event run at a time; the rest wait their turn”，即 prompt 与 agent 两类 Handler 在同一个事件上至多 12 个并发运行、其余排队等自己的轮次。矩阵此前已有的两个并发数字都只约束后台或异步执行（Codex 每会话 8 个后台 Hook、Qwen 10 个异步槽），这一条是第一个落在「同一事件上同时运行几条」的一手数字，而且落在会调用模型的 prompt 与 agent 两类 Handler 上：官方 Hooks 参考在 2026-10-19 复核时仍只写 “All matching hooks run in parallel. If you define the same handler in more than one settings file, it runs once. A plugin's or skill's copy of the same handler stays separate.”，抓取到的部分（该页 273,668 字节、抓取工具只处理了前 100,000 字符）没有任何数字上限，也没有 Qwen 那种 `sequential: true` 强制顺序执行的字段，因此这个 12 是否同样约束 command、http 与 `mcp_tool`，是按事件还是按会话计，以及排队等待是否计入 Hook 自身的 `timeout`，本次都记为未确认。核对日期最新 Release v2.1.303（2026-10-18T22:26:54Z）的更新日志只有 “Bug fixes and reliability improvements”，没有任何 Hook 条目。

Codex 官方仓库在 2026-10-18T22:36:47Z 合入 [PR #55144 “Add observation-only model request lifecycle hooks”](https://github.com/openai/codex/pull/55144)（提交 `70b3bb6d8814ab3f2045238b4ae14c43da99783b`，改动 46 个文件），新增 `PreModelRequest` 与 `PostModelRequest` 两个事件，把 Hook 的生命周期节点从工具与会话层推进到模型请求层：这两个事件围绕每次模型请求尝试触发并包含重试，事件模块 `codex-rs/hooks/src/events/model_request.rs` 的文件头注释逐字为 “//! Observation-only lifecycle hooks. Output is logged, never interpreted as control flow.”，提交说明也写明 “Treat hook output as diagnostic data without allowing it to veto requests or alter model context.”。这是本字段此前没有记录的一手确认新功能：矩阵原记录的事件目录是「11 个事件 + `Interrupt`」，配置层的事件键现在变成 14 个。

顺着「同一事件的多条 Hook 怎么跑」这条线复核其余三家：Qwen Code 的官方 Hooks 文档写 “By default, hooks execute in parallel for better performance” 并提供 `sequential: true` 强制顺序执行（顺序 Hook 可把改过的输入传给链上下一个），`async: true` 的 command Hook 占 10 个并发槽之一、占满即跳过——`sequential` 这个字段此前完全没有进过矩阵；Kimi Code 写同一事件命中的多条规则全部并行、`command` 完全相同的只运行一次，没有给数字上限；Qoder CLI 的 Hooks 页既没有说并行还是顺序、也没有任何并发数字，与顺序相关的只有配置合并口径 “All three sources are loaded and merged together (hooks for the same event do not override each other)”，同事件并发数记为未确认。

同一轮复核还带出两条一手变更。Qwen Code 提交 `52ae53b02a17d6214e9e4f81578f2ba2725539a6`（PR #14356 “fix(hooks): gate headless file and skill prompts before expansion”，2026-10-16 合入）改了 headless 下 `UserPromptSubmit` 的门禁时点：调用自定义命令或 Skill（含多个堆叠 Skill）的输入改在命令展开前受检、Hook 只跑一次且 `prompt` 与 `submitted_prompt` 都是原始输入，阻断因此能挡掉命令内嵌的 `!{...}` shell 命令、Skill 的 allowed tools 与 hooks 注册以及随后的模型请求；该提交已随 v0.25.3-preview.0（2026-10-16T18:28Z）发布，稳定通道 v0.25.2（2026-10-15T15:41:15Z）早于它。Kimi Code 提交 `c1459a61845056832b85a0a220ee11a2bc5132f8`（PR #4242 “fix(server): run agent hooks in the session's working directory”，2026-10-15T11:38:24Z 合入）把 Agent 级 Hook 的工作目录从引擎启动目录改回会话目录，此前文档里「hook 命令的工作目录是当前会话的项目目录」这句对走服务器路径的 Agent 级 Hook 并不成立；该提交带 patch 级 changeset，最新 Release 2.2.0（2026-10-14T15:31:16Z）早于它，尚未发布。

本次只处理 `extension-hooks` 一个能力字段，能力字段总数维持 115。五列的核对日期都更新到 2026-10-19，因为五家在这一层的证据都是本次新取得或新复核的；五列的证据状态不变（Claude 官方确认、Codex 条件项、Qwen 源码确认、Kimi 官方确认、Qoder 官方确认）。
