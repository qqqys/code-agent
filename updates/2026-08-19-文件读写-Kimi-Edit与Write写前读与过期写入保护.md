# 文件读写：Kimi Code Edit/Write 写前读与过期写入保护（staleGuard）

Kimi Code 官方仓库在 2026-08-19 合入 PR #3096（`feat(agent-core-v2): guard Edit and Write against stale or unread files`，合并提交 `67fbcdf1ba7dceeebb58875b3b7c81b4b30cf0de`），在 v2 引擎（agent-core-v2）新增 `staleGuard` 功能：Edit/Write 修改已有文件前要求本 Agent 已成功读取该文件，且磁盘 mtime 与读取时记录一致，否则拒绝写入。changeset `.changeset/file-write-staleness-guard.md` 为 `@moonshot-ai/kimi-code` 的 patch 级变更，最新 Release 0.37.2（2026-08-18 发布）不含该提交，属于合入 main 尚未发布。矩阵既有 `execution-files`（文件读写）字段的比较边界本就包含"修改前读取、权限审批与工作区边界"，但该字段此前没有记录任何一家的写前读或过期写入保护行为，本次在这一字段内补录 Kimi 新功能，并同步补录核对中发现的 Claude Code 官方工具参考读后再改要求、Codex Apply Patch 指南失败恢复、Qwen Code `edit` 读后再改强制机制。

## 修正

- `execution-files`（文件读写域）矩阵结论更新：Kimi Code 列由 "`Read` · `Edit` · `Write`" 更新为 "`Read` · `Edit` · `Write` · 条件：Edit/Write 拒绝未读取或读取后磁盘已变的已有文件（main 分支，尚未发布）"；Claude Code 列由 "`Read` · `Edit` · `Write`" 更新为 "`Read` · `Edit` · `Write` · 官方工具参考记录读后再改要求与模型差异"。Codex、Qwen Code、Qoder CLI 矩阵结论不变。
- Kimi Code 详情：staleGuard 在工具执行前拦截 Edit/Write——修改已有文件要求本 Agent 此前成功执行过 `Read`（`Read`/`Edit`/`Write` 成功执行后记录文件 mtimeMs，失败不记录），当前磁盘 mtime 与记录不一致即拒绝；同一批工具调用中已有对同一路径的 `Read` 时放行（`coveredByEarlierRead`）；新建文件、stat 失败或无 mtime 的文件不受影响。拒绝文案分别为 `"…" has not been read by this agent yet. Read the file before writing to it.` 与 `"…" has been modified on disk since this agent last read it. Read the file again before writing to it.`；Agent 运行时变化（`IAgentRuntimeService.onDidChange`）清空记录。该功能无配置开关，`StaleGuardFeature` 在 agent-core-v2 无条件注册；官方配置文档（该提交时点）称 agent-core-v2 为默认引擎、`KIMI_CODE_LEGACY_FLAG=1` 选择旧版引擎、`kimi web` 始终使用 v2，旧版引擎无此实现；官方工具文档尚未同步。
- Claude Code 详情：补录官方工具参考（tools-reference）的读后再改要求——当前会话需先读取目标文件，`PARTIAL view` 截断的读取不算；Claude Opus 4.6、Haiku 4.5 及更早模型始终要求先读，较新模型在读取无需权限提示且 Read 工具可用时可编辑未读文件；Bash 用 `cat`、`nl`、`bat`、`batcat`、`head`、`tail`、`sed -n 'X,Yp'`、`grep`、`egrep`、`fgrep`、`rg` 查看单文件且无管道或重定向也满足要求；`Write` 覆盖已有文件是否必须先读取决于模型与文件，Jupyter Notebook 与部分读取的文件对所有模型都要求先读，新建文件不受限；文件在上次读取后变化时，仅当 `old_string` 与当前内容精确且唯一匹配、读取无需提示才允许直接编辑，其余情况要先重读。
- Codex 详情：补录官方 Apply Patch 指南（Responses API harness 说明，developers.openai.com/api/docs/guides/tools-apply-patch）——`create_file`/`update_file`/`delete_file` 三种 V4A diff 操作由 harness 应用，未设写前读强制要求；`update_file` 上下文与文件内容不匹配时应用失败并返回如 `Error: Invalid Context` 的错误，模型据此重读文件或简化改动后重试。
- Qwen Code 详情：`edit` 读后再改规则改写为源码级描述——`checkPriorRead` 强制读后再改，未经合法读取的已有文件拒绝编辑，按 mtime/文件大小检测过期，并在读取后、写入前各复核一次以收紧 TOCTOU 窗口；工具描述也要求先查看文件当前内容再尝试替换。
- Qoder CLI 详情：条件与边界补充官方内置工具文档未列写前读/过期写入保护。
- 跨产品事实新增第 5 条：五家写前读与过期写入保护机制对比。
- `site/data.js`：新增来源 `kimi-stale-guard-commit`（合并提交 `67fbcdf1ba7d`）、`kimi-stale-guard-service`（`staleGuardService.ts`）、`kimi-stale-guard-changeset`（`.changeset/file-write-staleness-guard.md`）、`kimi-stale-guard-config`（该提交时点 `docs/zh/configuration/config-files.md`）与 `codex-apply-patch-guide`（Apply Patch 指南）。
- `docs/09-版本与证据.md`：Kimi Code 核对日期更新为 2026-08-19，主要材料新增 Edit/Write 写前读与过期写入保护条目；Claude Code 核对日期更新为 2026-08-19，主要材料新增 Edit/Write 读后再改要求条目；Codex 主要材料新增 Apply Patch 指南条目；Qwen Code 主要材料的 `edit` 工具条目补充 `checkPriorRead` 读后再改强制与写入前过期复核；官方来源表 Codex 与 Kimi 执行与 Git 列分别新增 Apply Patch 指南与 staleGuard 提交、服务源码、changeset、默认引擎配置文档链接。
