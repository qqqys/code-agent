# 服务端与 Daemon：Codex 本地后台 app-server daemon 与 `/daemon` 管理菜单（2026-10-11 新增重启动作），并复核其余四家常驻服务

Codex 官方仓库在 2026-10-11 合入提交 [`27065a91ccbf5ba8532844be3777fcf83b77820d`](https://github.com/openai/codex/commit/27065a91ccbf5ba8532844be3777fcf83b77820d)（PR #53173，标题逐字为 “Allow restarting managed background servers from the TUI”），给 TUI 的 `/daemon` 菜单新增 “Restart background server” 一项。顺着这条提交核对其余一手资料后发现：Codex CLI 有一个由 TUI 隐式发现并附加的**本地后台 app-server daemon**，以及一整套管理它的入口——`codex app-server daemon start|restart|update|enable-remote-control|disable-remote-control|stop|version|bootstrap` 八个生命周期子命令（记录在官方仓库 `codex-rs/app-server-daemon/README.md`）与 TUI 内的 `/daemon` 菜单（源码描述 “Manage the local background server”，2026-09-16 提交 `04581f96044a`、PR #45854 引入，rust-v0.162.1 标签的 `SlashCommand` 枚举已含 `Daemon` 变体）。

这是本仓库此前完全没有记录的一手确认能力：`surface-service`（服务端与 Daemon）字段的 Codex 列只写了 `codex app-server` 与 `mcp-server` 两个显式启动的协议服务器，没有任何 daemon、自动附加、状态文件、版本更新或重启内容；`docs/09` 的 Codex 材料里也没有出现过 `app-server-daemon`。本次只处理 `surface-service` 一个字段，补录 Codex 的本地后台 daemon，并把其余四家的常驻服务入口按当前一手资料复核一遍。

证据边界：官方文档站的 [App Server](https://learn.chatgpt.com/docs/app-server) 页没有任何 daemon 字样，[Developer commands](https://learn.chatgpt.com/docs/developer-commands?surface=cli) 页只在 `codex remote-control` 段两次提到 daemon，其内置 Slash 命令表（50 行）没有 `/daemon` 行、CLI 子命令表（26 个子命令）也没有 `codex app-server daemon`。daemon 的生命周期、状态文件与菜单行为全部取自官方仓库的 README、TUI 源码与 CLI 集成测试。
