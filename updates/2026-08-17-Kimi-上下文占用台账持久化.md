# Kimi Code 上下文占用实测值随 resume 恢复

Kimi Code 官方仓库在 2026-08-16 合入提交 `ee564e5ec90a`（PR #2969），把 v2 引擎的 token 计数台账持久化到会话 wire journal：`token_counting.measured`、`token_counting.truncated`、`token_counting.rebased` 三类记录由 `TransientOpMap`（`persist: false`）改为 `PersistedOpMap`，随会话事件流写入 `agents/*/wire.jsonl`。此后会话归档/取消归档或任意关闭 → resume，显示的上下文大小保持实测值，不再回落到较小的估算直到下一次模型调用。changeset `.changeset/persist-token-counting-ledger.md`（`@moonshot-ai/kimi-code` patch）未被 Release 消费（最新 Release 为 0.36.1，2026-08-14 发布），标注为"合入 main 尚未发布"。

## 证据版本

- Kimi Code 提交 `ee564e5ec90afd068123b8052928c53f1fd5a27d`（`fix(agent-core-v2): persist token counting ledger so resume restores measured context size (#2969)`，2026-08-16T11:31:31Z 合入 main）：`tokenCountingOps.ts` 中三个 Op 移除 `persist: false` 并从 `TransientOpMap` 移入 `PersistedOpMap`；`docs/wire-manifest.d.ts` 中 `token_counting.measured`/`rebased`/`truncated` 的标记由 transient 改为 persisted；新增测试 "keeps the measured size across a close → resume round trip"（flush 后 wire 记录包含 `token_counting.measured`，resume 恢复后 `latestMeasured()` 与 `statusSize()` 与关闭前一致）。
- 该提交处的 `.changeset/persist-token-counting-ledger.md` 原文："Persist the token counting ledger (`token_counting.measured` / `truncated` / `rebased`) to the wire journal, so the displayed context size keeps its measured value after archiving and unarchiving a session (or any close → resume) instead of dropping to a smaller estimate until the next LLM call."，级别 patch。
- 该提交处的 `packages/agent-core-v2/src/agent/tokenCounting/tokenCountingOps.ts`：台账状态为 `{ anchors, tokens }`，`anchors` 是实测上下文大小的活动历史——每次 LLM 实测交换一条（`measured: true`），清空/压缩后为单条 rebase 锚点；`token_counting.measured` 带非单调防护（较短上下文的过期锚点不会覆盖更新的交换），`token_counting.truncated` 为 undo 截断丢弃截断点之后的锚点，`token_counting.rebased` 的压缩锚点传 `measured: false`（混合实测摘要与保留消息、请求开销估算）；Op 经 `toEvent` 发出 `agent.status.updated { contextTokens }`。
- 该提交处的 `apps/kimi-code/src/tui/components/messages/usage-panel.ts` 与 `status-panel.ts`：`/usage` 面板与 `/status` 的 Context window 段落都消费 `contextUsage`/`contextTokens`/`maxContextTokens` 渲染进度条；`/status` 在窗口数据缺失时显示 `No context window data available.`。
- 该提交处的 `docs/zh/configuration/data-locations.md`：会话目录内 `agents/main/wire.jsonl` 是 main agent 的完整通信记录，用于会话恢复和回放。
- 发布状态：最新 Release 为 0.36.1（2026-08-14T12:53:36Z），提交（2026-08-16T11:31:31Z）晚于该发布，changeset 未被 Release 消费。
