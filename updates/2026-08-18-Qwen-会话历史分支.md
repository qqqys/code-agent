# Qwen Code 从任意 Assistant 响应分支会话（v0.21.13）

Qwen Code 官方仓库在 2026-08-15 合入 PR #8817（`feat: support fork from any conversation`，合并提交 `9f8f65dde043c10cb6a13ea1d4a03928d83d98dc`），引入“持久检查点”（durable checkpoint），支持从任意已完成 Assistant 响应分支出独立会话；该功能随 v0.21.13（2026-08-17T02:11Z 发布，标签 `d95901597430`）发布，v0.21.13 发布说明明确列出本项（#8817）。

## 证据版本

- Qwen Code PR #8817（`feat: support fork from any conversation`）：2026-08-15T10:02:06Z 合入 main，合并提交 `9f8f65dde043c10cb6a13ea1d4a03928d83d98dc`，62 个文件变更；新增 `docs/design/web-shell/assistant-response-session-branching.md`，修改 `packages/core/src/services/chatRecordingService.ts`、`sessionService.ts`、`packages/cli/src/serve/routes/session.ts`、`packages/acp-bridge/src/bridge.ts`、`packages/cli/src/acp-integration/acpAgent.ts`、`packages/web-shell/client/`（MessageItem/MessageList/App）、`packages/sdk-typescript/src/daemon/DaemonClient.ts`；未改动 `packages/cli/src/ui/commands/` 下任何命令。
- 该提交处的设计文档：可从“功能引入后录制的、成功完成的交互式用户回合的最终 Assistant 响应”分支；“分支截断对话历史，不回退或替换当前工作目录、Git 状态或工作文件”；Branch 动作仅在存在持久检查点且无活跃回合时显示，旧响应不显示；“持久 `branch_checkpoint` 记录是响应可分支的唯一依据”；检查点 schema 为 `BranchCheckpointRecordPayloadV1`（`v: 1`、`startExclusiveRecordUuid`、`assistantRecordUuid`）；检查点创建失败时回合仍成功返回、不带分支点；错误分支：`branch_point_invalid` 对无效/失效/畸形/过期检查点返回 HTTP 409 且“不回退到当前会话尾部”，`atRecordId` 存在但非字符串返回 HTTP 400（与 409 区分以免触发过期恢复逻辑），回合活跃时立即返回 `session_busy`；状态表中对话历史物理截断、文件历史备份仅保留检查点之前的快照并经校验句柄复制、源记录 UUID 保留、`parent_session`/`session_source` 不继承、检查点后的 side artifacts 排除；“没有迁移为旧记录合成检查点”；SDK 请求限 120 秒。
- 该提交处的 `packages/cli/src/serve/routes/session.ts`：`app.post('/session/:id/branch', ...)`，`withPrimaryOnlyMutableSession` 限定主会话；`name` 去除控制字符并截断到 200 字符；`atRecordId` 非字符串返回 400 `branch_point_invalid`；调用 `runtime.bridge.branchSession(sessionId, { name, atRecordId? }, { clientId })`；不带 `atRecordId` 时保留 v1 行为并对断连做 live branch detach/kill 清理，带 `atRecordId` 时直接返回原始结果；成功返回 HTTP 201。
- 该提交处的 `packages/sdk-typescript/src/daemon/DaemonClient.ts`：`branchSession()` 三个重载，`HistoricalBranchSessionRequest`（携带 `atRecordId`）返回 `DaemonPersistedBranchedSession`，不带锚点返回 `DaemonBranchedSession`；实现以 `fetchWithTimeout(..., 120_000)` 请求 `POST /session/:id/branch`，请求体为 `{ name, atRecordId? }`。
- v0.21.13 发布说明（2026-08-17T02:11Z，标签 `d959015974302fb60ebd99adb81a68c2f482eaa3`）：Highlights 列出 “Users can now fork conversations from any specific Assistant response using durable checkpoints to ensure branch accuracy. (#8817)”；该窗口内无其他稳定版发布（无稳定 v0.21.12），v0.21.13 为首个包含该提交的稳定版。
- 该标签处的 `docs/users/features/commands.md`：`/branch` 仍描述为 “Fork the current conversation into a new session”，无参数，未提及历史分支；`/fork` 仍为 “Spawn a background agent that inherits the full conversation”。该标签处的 `docs/users/qwen-serve.md` 未描述历史分支 UI，仅在会话槽位与 `branchSession` 序列化处提及 branch/fork 会话。
- Claude Code 官方 Sessions 文档（2026-08-18 复核）：`/branch` “copies the transcript and switches the running Claude Code process to write to it”，历史复制到 “up to the point you ran `/branch`”，未提供历史消息级分支点；检查点回退属于同会话 Checkpointing。
- Qoder TypeScript SDK 参考（2026-08-18 复核，docs.qoder.com/cli/sdk/references-typescript）：`resume` 为 “Session ID to resume”，`forkSession` 为 “Fork into a new session ID when used with `resume`”（默认 `false`），`resumeSessionAt` 为 “Resume from a specified message UUID”；未说明 `forkSession` 与 `resumeSessionAt` 组合可从历史消息分支。
- 其余三家：Codex `/fork` 与 `codex exec fork`、Kimi `/fork` 的既有记录以当前对话或会话状态为分支点，本次未改动。
