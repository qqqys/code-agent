# 审批自动审查：Claude Code v2.1.302 的 `CLAUDE_CODE_AUTO_MODE_MODEL` 与服务端 classifier 审查，Qwen Code 两阶段裁决与破坏性命令阻断并入计数器

Claude Code 官方仓库于 2026-10-16 发布 v2.1.302（[Release](https://github.com/anthropics/claude-code/releases/tag/v2.1.302)，2026-10-16T20:53:06Z；[更新日志](https://github.com/anthropics/claude-code/blob/c017428c8c27e604840435048d5bce6a9a22c040/CHANGELOG.md)固定到提交 `c017428c8c27e604840435048d5bce6a9a22c040`，“chore: Update CHANGELOG.md and feed.xml”，2026-10-16T20:52:45Z），其中与本字段直接相关的一条逐字为 “Added `CLAUDE_CODE_AUTO_MODE_MODEL` to choose the model the client-side auto mode classifier uses; it does not change the model for server-side auto mode”。这是本仓库 `security-auto-review` 字段此前完全没有记录的一手确认新配置项：旧记录的 Claude 列只写了「独立 classifier 模型在动作执行前审查」，既没有写这个模型默认是哪个、按什么顺序解析，也没有写用户可以换它。

同版另有三条与本字段相关的条目：服务端 classifier 遇到长到做不了安全检查的对话改为先压缩（“Improved auto mode with the server-side classifier: a conversation too long for the safety check is now compacted, instead of every checked tool call being denied”）、`tool_decision` 遥测属性修复，以及 `claude -p` 与 Agent SDK 无权限模式时的启动模式改动（“Changed `claude -p` and Agent SDK sessions with no permission mode to start in `default` mode on third-party providers, with telemetry off or on a fresh install; `--permission-mode auto` keeps auto”）。最后这一条与官方权限模式页当前的起始模式表格直接冲突——表格仍写不 fetch feature flag 的会话「`auto` with Claude Code v2.1.285 or later and `default` on earlier versions」，本次按更新日志记录并注明文档未同步。v2.1.301（更新日志固定到提交 `03b5892ee77de289bcd5dfa39f541525ade74aff`）则给 OpenTelemetry `tool_decision` 事件加了 `classifier_verdict`、`permission_mode` 与 `OTEL_LOG_TOOL_DETAILS=1` 下的 `classifier_category`，官方 Monitoring usage 页的属性表在核对日期还没有这三个。

顺着这条新配置项复核官方 Permission modes、Configure auto mode、Auto mode classifier request charges、Environment variables、Model configuration、Settings reference 与 Monitoring usage 七页后，发现 Claude 列还有一整块机制从未记录：auto 模式的分类器其实分**客户端**与**服务端**两条执行路径，`CLAUDE_CODE_AUTO_MODE_SERVER` 控制走哪条，两者的计费方式不同，`/status` 有 **Auto mode server** 行显示当前会话走哪条。`CLAUDE_CODE_AUTO_MODE_MODEL` 的说明里那句 “it does not change the model for server-side auto mode” 只有在这条分界的语境下才讲得通，因此本次一并补录。Configure auto mode 页的 `autoMode` 四张表（`environment`、`allow`、`soft_deny`、`hard_deny`）、四层优先级、`"$defaults"` 语义、三个读取作用域、`/auto-mode-setup` 命令与 `claude auto-mode` 的四个子命令，此前也全都没有记录。

复核另外四家时发现 Qwen Code 一列有一处实质变更和一批从未记录的细节。变更来自 2026-10-10 合入的 “fix(permissions): escalate repeated destructive-command denials to manual approval”（[PR #13636](https://github.com/QwenLM/qwen-code/pull/13636)，提交 `a238b91e7c6fc2b0e36e23436b0e4ced5296617b`，随 v0.25.2 于 2026-10-15 发布）：破坏性命令的确定性阻断此前永久硬阻断，现在并入分类器的同一组拒绝计数器，官方文档相应从「连续 3 次策略阻断」改成 “After **3 consecutive blocks** — classifier policy blocks and deterministic destructive-command blocks both count — the call that reaches the third block falls back to the standard manual-approval prompt.”；同一提交把这次升级标为 `requiresHumanDecision`，Hook 的 `allow` 因此不能豁免它，非交互 STREAM_JSON 会话则改为直接拒绝。v0.25.2、v0.25.2-preview.1、v0.25.3-preview.0 与各 nightly 的发布说明里都没有 auto 模式分类器条目，这条改动是随变更列表静默发布的。

Qwen 列此前还漏了三件事：分类器用哪个模型（官方逐字 “The classifier uses your configured fast model (`/model --fast`). If no fast model is configured, the main session model is used instead.”）、裁决分两阶段（Stage 1 只输出 `{ shouldBlock }` 约 300 毫秒，Stage 2 只在 Stage 1 判阻断时跑、可以把阻断降级为放行），以及 `permissions.autoMode.hints` 的实际键名是 `allow`/`softDeny`/`hardDeny`——旧记录只写了 `hints.allow` 与 `hints.deny`，而 `hints.deny` 现在只是按 `softDeny` 处理的向后兼容写法。会话累计 20 次拒绝的上限只在源码 `denialTracking.ts` 里、官方文档没有写，本次一并记下并注明证据层级。

Codex 与 Qoder 两列本次只补细节、结论不变。Codex 的熔断阈值此前只有文档口径，本次固定到 rust-v0.163.0 标签（指向提交 `83086188ae0614bd882818ff1aa23f3194962012`，2026-10-15T18:57:08Z 打标签）下的 `circuit_breaker.rs` 常量，并发现同文件另有一组阈值为 1 与 1 的 Cyber 变体；审查用哪个模型官方文档始终不点名，配置参考里也不存在选模型的键，解析逻辑只在 `guardian-reviewer/src/model.rs` 的 `select_review_model` 里。Qoder 列补录了两阶段裁决、三类不经分类器的动作、失败关闭与熔断的逐字表述、`general.defaultPermissionMode` 与顶层 `autoMode` 的类型与默认值，以及 1.1.63（2026-09-24）“Approval requests in Auto permission mode now follow the BYOK model” 这条唯一的模型线索；1.1.64 到最新 1.1.72（2026-10-15）九条发布说明里没有任何 auto 模式、审批、分类器或权限条目。Kimi Code 列结论与证据不变：复核 main HEAD `18c6d64272952503baccf706bff455bb6a2c488e` 下的英文交互文档（11,371 字节），全文没有 classifier、LLM、AI 或 review agent 字样，`model` 只出现在 `/model` 切换与多模态描述里，审批仍完全由用户交互、静态权限模式与内置危险命令 guard 处理。

本次只处理 `security-auto-review` 一个字段，能力字段总数维持 115。五行的核对日期都更新到 2026-10-17，其中 Claude 与 Qwen 两列的结论与证据发生实质变化，Codex 与 Qoder 两列补录细节，Kimi 列不变。
