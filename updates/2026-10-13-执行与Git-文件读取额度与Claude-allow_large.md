# 文件读写：单次读取的额度口径与超限行为逐项核对，补录 Claude Code v2.1.296 的 `allow_large` 并改正 Kimi Code 两处过期记法

Claude Code v2.1.296（2026-10-09T19:28:59Z 发布）的更新日志有一条本仓库尚未记录的一手确认新功能，逐字为 “Added an `allow_large` option to the Read tool so Claude can read a text file past the usual size limits in one call when it needs the whole file and the context has room”（更新日志固定到 `2301018b1f61073c501a8e7a4813ef48c239163b`）。官方工具参考的 “Read tool behavior” 与 “Large files” 两段已经跟进，写明了默认额度、`allow_large` 的计量口径与两类超限结果；官方环境变量页也写明 `CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` 与 `allow_large` 的关系。仓库此前只在读后再改要求里顺带提过 `PARTIAL view`，完全没有记录读取额度本身。

顺着这条核对五个产品后发现，`execution-files` 字段在五家都缺「单次读取上限」这一层，而且其中两家的既有记法已经过期：Kimi Code 记的「`Read` 最多返回 1000 行或 100 KB」取自 0.38.0 中文工具文档，而 2.1.1（2026-09-24 发布，也是核对日期最新的 Release）与 main `afd95f64a544` 的同一页早已改成字符额度记法，参数从三个扩到五个并新增 `[read]` 配置块；同一页还已经记录了 `Write` 与 `Edit` 的写前读与磁盘变化拒绝，因此仓库里「staleGuard 在 main 分支、尚未发布、官方工具文档尚未同步」的记法同样过期。Codex 一栏写的「内置读取」也不准确：固定到 main `f82e36592278` 的工具 handler 目录里没有任何专用文本读取工具，文本读取走统一执行工具 `exec_command` 与 `write_stdin`，额度就是命令输出额度。

因此本次按深化既有字段处理，只处理 `execution-files` 一个能力字段，能力字段总数仍是 115。五行的核对日期都改为 2026-10-13，因为五个产品在这一层的证据都是本次新取得或新改正的。Claude Code 没有新的更新日志（最新仍是 v2.1.296），Codex 的证据坐标是 2026-10-13 的 main 分支（最新 Release 仍是 rust-v0.163.0-alpha.5 与 rust-v0.162.1），Qwen Code 固定到标签 v0.25.1，Kimi Code 固定到标签 2.1.1 并对照 main，Qoder CLI 是文档站核对日期加 CLI 1.1.66 至 1.1.69 的发布说明。
