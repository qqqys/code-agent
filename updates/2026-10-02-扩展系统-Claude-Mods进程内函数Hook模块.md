# 生命周期 Hooks：Claude Code v2.1.287 新增进程内 JS/TS 函数 Hook 模块（Mods）

Claude Code 更新日志在 v2.1.287 记录 `Added Claude Mods: plugins may now modify deeper behavior`（该版本标题由提交 `816ec211a648f17a411f63a45cfd44ddf8db00d9` 于 2026-10-01T17:59:57Z 写入 `CHANGELOG.md`），官方文档同时上线 `plugins/mods/` 一整套页面（overview、interface、events、api、create、test、troubleshoot、admin、reference），Plugin components 页也把 `hooks/hooks.json` 的 `modules` 键列为插件组件。Mods 不是新的一类扩展包，而是 Hook 的一种新 Handler：插件在 `hooks/hooks.json` 顶层用 `modules` 数组（官方示例 `{ "modules": ["./register.js"] }`，只放一个相对该文件的路径）声明一个 ES module 入口，导出的 `register(on, options)` 注册的 JS/TS 函数在 Claude Code 自己的进程里被调用，带这种模块的插件官方称为 mod。矩阵 `extension-hooks`（生命周期 Hooks）字段 Claude 列此前只写 `/hooks` · 多类 Handler，未覆盖进程内函数模块这一类，本次补录。其余四家复核后无同类变化：Codex 公开 Handler 仍为 `command`（可 `async: true`）与 `mcp_tool`，`prompt`/`agent` 可解析但运行时跳过；Qwen Code 公开可配置 Handler 为 command、HTTP 与 prompt，文档虽列 `function` 但注明由 Skill 系统内部使用、当前不作为面向终端用户的公开 API；Kimi Code 独立 Hook 只有 `[[hooks]]` 的 `command`；Qoder CLI 为 command/HTTP/prompt/agent。四家都没有可绘制界面的 Hook，矩阵结论保持不变。

## 修正

- `extension-hooks`（生命周期 Hooks）矩阵 Claude Code 列由 `` `/hooks` · 多类 Handler `` 更新为追加“v2.1.287 起插件 `hooks/hooks.json` 的 `modules` 注册进程内 JS/TS 函数 Hook（mod），可改写事件并绘制界面”。证据状态维持“官方确认”。其余四家矩阵结论不变。
- Claude Code 详情（入口与配置）补录：mod 走插件入口，`/plugin install token-chart@your-org` 或 `claude plugin install token-chart@your-org` 安装、`/plugin` Installed 页签禁用或卸载、shell 安装后在已开会话执行 `/reload-plugins`，`/plugin` 页签下方以 `1 mod active · first-mod` 暗色行报告已加载 mod，`claude plugin validate ./some-mod` 输出的 `hooks:` 与 `calls:` 两行用于安装前审计，开发时 `--plugin-dir` 按会话加载。
- Claude Code 详情（文件与目录）补录：`hooks/hooks.json` 顶层除 `hooks`（形状与 `settings.json` 的 `hooks` 对象一致）外可写 `modules`；manifest 仍是 `.claude-plugin/plugin.json` 且 mod 不新增强制字段；用 `$.state` 或追加 mods API 命名空间时按 manifest 的 `types` 键提供 `types/index.d.ts`；`.test.ts`/`.test.tsx` 由 `claude plugin test` 运行。
- Claude Code 详情（具体行为）补录：入口模块为 ES module、导出 `register(on, options)`，`options` 为 manifest `userConfig` 字段值并填充默认值；Hook 形如 `async ($, e, next) => next(e)`，`$` 是 mods API、`e` 是深度冻结的事件输入、`next(e)` 为中间件式后续 Handler；`turn.step` 与 `process.spawn` 是 async generator，其余是 async function；逐个列出 `tool.*`、`prompt.*`、`skill.prompt`、`attribution.text`、`command.*`、`config.*`、`turn.*`、`session.*`、`agent.*`、`ui.*`、`plugin.register`、`engine.create`、`telemetry.*`、`classic.<Event>` 与每个 mods API 方法自身（`<namespace>.<method>`）；一个 Hook 可观察、改写或直接给出答案而不执行原动作。
- Claude Code 详情（作用域与优先级）补录：mod 只能由插件携带，不能写在 `settings.json` 里；组织可用 `allowManagedModsOnly` 只放行托管来源的 mod。
- Claude Code 详情（扩展构成）补录：settings Hook 的 Handler 仍是 command、HTTP、MCP Tool、prompt 与 agent，mod 增加进程内 JS/TS 函数模块一类，入口后缀可为 `.js`/`.mjs`/`.cjs`/`.jsx`/`.ts`/`.mts`/`.cts`/`.tsx`；mod 可画 transcript 旁的 pane、提示词上方的 band（含页签、按钮、文本框），可替换或重绘工具调用行、spinner 与对话框，可新增不经 Claude 回合的 `/command`，同一文件内变量在各 Hook 间共享；v2.1.288 增加 `$.ui.selection()`。
- Claude Code 详情（加载与刷新）补录：`plugin.register` 在模块即将加载时触发，`engine.create` 在为该 mod 构建 mods API 时触发，`session.start` 对每个已加载 mod 在首条提示词前触发一次、重载后再触发一次，`session.end` 在会话结束或 `/clear`、`/resume`、`/branch` 时触发。
- Claude Code 详情（适用界面）改为逐 Surface 记录：settings Hook 事件在终端、IDE 扩展、桌面端与云会话一致触发；mod 的 Hook 在终端（含编辑器集成终端与 JetBrains 插件）、桌面端 Code 页签、VS Code 聊天面板、`claude -p` 与 Agent SDK、Remote Control 本机会话以及能带入云会话的插件中执行，而界面绘制只出现在终端与桌面端 Code 页签，桌面端 WSL 会话不加载插件因此 mod 完全不生效。
- Claude Code 详情（权限与信任）补录：mod 以用户权限在进程内运行且不进沙箱，即使开启 Bash 沙箱其启动的进程也在沙箱外，可读写文件、启动程序、发起网络请求、读取环境变量与 API Key、查看并改写提示词与工具调用、不询问就行动，也能批准工具调用从而绕过 `ask` 规则或 `PreToolUse` 阻断，并消耗账号用量；官方要求只装可信来源并用 `claude plugin validate` 审查。
- Claude Code 详情（条件与边界）补录：需 v2.1.287 及以上且默认开启，`CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` 被忽略、设为 `0` 也关不掉；四种关闭方式为 `--safe-mode`、`~/.claude/settings.json` 的 `"disableAllHooks": true`、组织设置 `allowManagedModsOnly`、`/plugin` Installed 页签；权限提示不可重绘；逐项列出执行时间与容量限额（单事件 Hook 自身 10 秒、`.catch` 1 秒、全部 `session.end` 合计 1.5 秒、`$.process.run` 默认 30 秒上限 10 分钟、`$.model.complete` `maxTokens` 默认 1024 上限 64000 或模型输出上限、`$.fs.read`/`write` 单文件 4 MiB、`$.store` 4 MiB JSON、`$.session.messages()` 最新 4096 条、`Text` 单字符串子节点与 `Code`/`Markdown` 各 10000 字符、`Svg` 131072 字符、`Raster` `columns`≤512 与 `rows`≤256、`Image` ≤2 MiB、`$.ui.invalidate('ui.render')` 每秒 10 次（终端可见区域 30 次）、`$.ui.toast` 默认 4 秒、名称字符集与 64 字符上限、`claude plugin test` 单测 5 秒），并记录官方未给 mod 数量上限与六个内置 mod 名称。
- 能力定义由“执行外部逻辑”改为“执行外部或进程内逻辑”，“本页包含”增加“插件内进程执行的 JS/TS 函数 Hook 模块（mod）与其界面绘制”。
- 跨产品事实新增两条：一条对比五家 Handler 的执行位置（只有 Claude Code 有进程内函数模块，只有 mod 能绘制界面；Qwen 的 `function` Handler 仅供 Skill 系统内部使用）；一条补充 mod 的信任边界与 `claude plugin validate` 审计方式。
- `site/data.js`：`updatedAt` 由 2026-10-01 更新为 2026-10-02；新增来源 `claude-plugins-components`、`claude-mods-overview`、`claude-mods-reference`、`claude-v21287-mods-changelog`（提交 `816ec211a648`）与 `claude-v21288-mods-changelog`（提交 `1c229fcd1e1e`）；能力字段总数不变（112 个）。
- `docs/09-版本与证据.md`：Claude Code 核对日期由 2026-09-30 更新为 2026-10-02，主要材料追加 Mods 条目；官方来源表“扩展系统”列 Claude Code 追加 Plugin components、Mods overview、Mods reference 与两条固定到提交 SHA 的更新日志链接。
