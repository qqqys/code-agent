# 增加权限与沙箱能力独立详情页

## 本次更新

- 为交互审批、Plan、自动接受编辑、跳过审批、文件系统隔离、网络隔离、项目目录信任和非交互审批增加 8 个独立详情页。
- 每页固定对照五家的入口、默认状态、具体行为、规则、技术边界、保存范围、非交互行为、条件和官方来源。
- 主矩阵中的 8 个能力名称可直接进入 Markdown 详情；网页对应行可进入完整能力页面。
- 明确区分工具审批与 OS 沙箱，避免把 Allow/Deny 规则当作进程隔离。

## 字段修正

- Qoder CLI Plan 改为独立工作状态；未信任目录会回退到 `default` 权限模式。
- Kimi Code `-p` 改为固定使用 Auto 权限策略，静态 deny 规则继续生效。
- Kimi Code 没有被写成“仅自动接受编辑”：`/auto` 的范围包含全部工具审批。
- Codex 的 `approval_policy = "never"` 与 `danger-full-access` 分开记录，避免把关闭提示等同于移除沙箱。
