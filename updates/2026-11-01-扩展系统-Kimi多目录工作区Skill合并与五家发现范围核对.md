## 本次改动

本次以 Kimi Code 一个已合入 main 的新功能为起点，把「项目级 Skill 的发现范围是否跨多个工作区目录」与「同名 Skill 如何取舍」在五家全部重新核对，结果修正了两条旧结论（Qoder 的优先级方向、Kimi 多 Skill 激活的发布状态），并补齐了 Claude 与 Codex 此前记浅的部分。

**Kimi Code 把每个已配置源目录的项目级 Skill 合并进同一列表**（PR #4520 “feat: merge skills across workspace directories”，合并提交 `3ed0e68f3bbfb3d9ef5bfad0e7b0de2c497e3d00`，2026-10-30T05:24:06Z 合入 main，28 个文件、+1022/−77）：

- 中英文文档在同一提交同步，不存在滞后。中文段（`docs/zh/customization/skills.md`，main `a2afdbc7d1fa` 下 7,812 字节，与合并提交逐字节相同）逐字为「当工作区包含多个已配置的源目录时，Kimi Code CLI 会按上述项目根规则发现每个源目录的项目级 Skills，并合并到同一个 Skill 列表中。出现同名 Skill 时，主目录优先；附加目录之间按工作区中的目录顺序决定优先级。任意源目录中的 Skill 发生变化时，列表都会自动刷新。仅当前会话临时添加的目录不参与合并；如需使用其中的 Skills，请将该目录记住到工作区。」，英文段（8,671 字节）为 “For a workspace with multiple configured source directories, Kimi Code CLI discovers project-level Skills for every source directory using the project-root rules above and merges them into one Skill catalog. The primary directory wins duplicate Skill names; additional directories follow their workspace order. Skill changes in any source directory automatically reload the catalog. Session-only additional directories are excluded; remember a directory in the workspace to include its Skills.”
- 实现（与父提交 `3a0b86ea06e7` 逐行对比）：`rootFileSkillSource.ts`（5,959 字节，父提交 4,746）新增 `workDirs` getter，逐字为 `[primaryByWorkspace[workspaceId] ?? cwd, cwd, ...sharedAdditionalDirs]`，发现调用由 `projectRoots(cwd)` 改为 `skillRoots.ts`（5,425 字节，父提交 5,011）新增的 `projectRootsForDirs`——逐 workDir 以 `findUpwardRoot(workDir, '.git', …)` 求项目根、按 realpath 去重并保留首次出现顺序，这就是「主目录优先、附加目录按工作区顺序」的来源；watcher 由单个改为每个去重后的项目根一个，候选目录 `[.kimi-code/skills, .agents/skills]`、防抖仍是 `WATCH_DEBOUNCE_MS = 200`，签名由 `scannedDirectories.join('\0')` 改为 `JSON.stringify({ watches, scannedDirectories })`，因此共享目录增减与主目录变化都会重挂，单个 watcher 失败只 `log.warn('project skill watcher failed for …')` 并继续；构造函数新增订阅 `workspaceDirs.onDidChange`，`watchReady` 先 `await workspaceDirs.ready`。
- 目录集合的边界：`IWorkspaceDirs`（`workspaceDirs.ts`，1,155 字节，父提交 1,038）新增 `sharedAdditionalDirs` 与 `primaryByWorkspace`；`workspaceDirsService.ts`（12,227 字节）给出 `sharedAdditionalDirs = fileDirs ∪ registryDirs`、`additionalDirs = sharedAdditionalDirs ∪ ephemeralDirs`、`addDir` 的 `persist ?? true`，因此「记住到工作区」的目录才贡献 Skill，仅本次会话添加的目录只扩大文件访问。用户侧入口为 `/add-dir [<path>]`（「添加时可选择是否将目录记入工作区注册表（持久保留）」）与 `--add-dir <dir>`，注册表在 `~/.kimi-code/projects.json`，`local.toml` 的 `additional_dir` 已是只读存量兼容字段。
- 未变的部分：`load()` 开头 `if ((this.bootstrap.args.skillDirs?.length ?? 0) > 0) return { skills: [] };` 保留，即 `--skills-dir` 仍整体**替换**自动发现（CLI 参考逐字区分 `--skills-dir`「**替换**自动发现的用户和项目目录，仅对本次启动生效」与 `extra_skill_dirs`「**叠加**到自动发现的目录之上，长期生效」）；`merge_all_available_skills`（默认 `true`）决定每个项目根扫全部品牌目录还是只取第一个存在的。PR 说明段逐字写 “The existing catalog remains the single source for listing, slash activation, and model invocation. No REST response schema or Skill source type was added.”，受影响者记为 “Desktop/Web multi-directory projects and TUI/SDK workspaces”，单目录与显式 `skillDirs` 场景单列为 Unchanged。信任披露侧改为先 `await this.skills.reloadSources(['workspace'])`、用与会话创建相同的 helper 解析待定目录，并 “disclose session-only directory access without discovering their Skills”；TUI 的 `getWorkspaceTrustInfo` 同步带上 `additionalDirs`、`environmentId`、`environmentCwd`。

**Claude Code 的发现范围此前记浅，本次补齐**：官方 Skills 页（`.md` 变体 118,879 字节）的 `## Choose where skills load` 表有七行，其中 **Additional directory** 行逐字为 “`.claude/skills/<skill-name>/SKILL.md` in a directory you pass with `--add-dir`”、Loads in “That session.”；`### Load skills in monorepos and subdirectories` 逐字为 “Claude Code loads project skills from `.claude/skills/` in the directory where you start it and in every parent directory up to the repository root”，`/cd`（v2.1.246 及以上）会把新目录的项目 Skill 加进来，启动目录**之下**的 `.claude/skills/` 在 Claude 首次读写该子目录文件时才加载、提前加载用 `/add-dir <子目录>`（需 v2.1.257 及以上），worktree 只向上搜到 worktree 根且 v2.1.277 起在 worktree 根没有 `.claude/skills` 时改读主检出；`### Load skills from a directory outside the project` 逐字为 “When you add a directory with `--add-dir` or `/add-dir`, Claude Code loads the skills in that directory's `.claude/skills/`, along with its `.claude/commands/` and `.claude/agents/`. Directories the Agent SDK adds through `additionalDirectories` in TypeScript or `add_dirs` in Python load the same way, because the SDK passes them as `--add-dir`. The `permissions.additionalDirectories` setting in `settings.json` grants file access only and loads none of these.”，Permissions 页（90,325 字节）的加载表把 Skills 记为 “Yes, with live reload”、`.claude/commands/` 与 `.claude/agents/` 记为 “Yes, without live reload”，CLI 参考（51,769 字节）`--bare` 行仍写 “Skills in a directory you pass with `--add-dir` still load.”；热更新与 `/reload-skills`、“Live change detection covers `SKILL.md` text only.” 均逐字补录。`### Resolve skills that share a name` 表给出九种情形，其中 added directory 的 Skill 与前三种位置同名时改用前缀名（“The added directory's folder name, then the skill directory name. When two added directories share a folder name, the prefix starts with the parent folder's name. Requires v2.1.309 or later”，示例 `--add-dir ../cli` 下 `/verify` 跑项目里的、`/cli:verify` 跑 `../cli` 里的），两个 added directory 之间先加入者胜，项目根与嵌套同名时 “Both load.”。版本时间线取自官方更新日志（固定到 main `80c6959d28c4c30ecd14fc1cdf172f19d9adad81`，1,130,515 字节，最新段 `## 2.1.316`，核对日期最新 Release 为 v2.1.316／2026-10-31T01:01:35Z）：v2.1.32 “Skills defined in `.claude/skills/` within additional directories (`--add-dir`) are now loaded automatically.” 是这条能力的起点，v2.1.152 加入 `/reload-skills`，v2.1.257 “Fixed `/add-dir` rejecting a directory inside the current working directory; it now loads that directory's skills, commands, and agents like `--add-dir` does at startup” 与文档里「提前加载子目录需 v2.1.257 及以上」互相印证，v2.1.271 修 `/reload-skills` 在 `/cd` 后数量与斜杠菜单不一致，v2.1.282 “Fixed repository, user and `--add-dir` skills, commands and skills-directory plugin manifests pre-approving their own tools via `allowed-tools` under managed `allowManagedPermissionRulesOnly`”，v2.1.299 与 v2.1.304 调整压缩后的 Skill 列表重发（v2.1.304 起 `/reload-skills` 只发送新增或变更的 Skill），v2.1.309 “Fixed a skill in an `--add-dir` folder being unreachable when another skill already held its name; it is now offered as `<folder>:<name>`” 即前缀名规则所要求的版本；`/reload-skills` 的官方命令描述在命令参考页（57,789 字节）逐字为 “Re-scan skill and command directories so skills added or changed on disk during the session become available without restarting. Reports how many skills are available and how many were added or removed”。另记一条边界差异：官方五页文档都没有 multi-root／workspace source directory 一类词汇，模型是「一个主工作目录 + 若干附加目录」，而唯一能跨会话持久化附加目录的键 `permissions.additionalDirectories` 明确不加载 Skill，因此 Claude 侧没有文档化办法把「加载 Skill 的附加目录」持久化到下一次会话——这与 Kimi「把目录记住到工作区即成为共享源目录」正好相对。

**Codex 的仓库层是逐级扫描，不是命中即停**：官方文档 `https://learn.chatgpt.com/docs/build-skills`（`.md` 变体 11,035 字节）逐字为 “Codex reads skills from repository, user, admin, and system locations. For repositories, Codex scans `.agents/skills` in every directory from your current working directory up to the repository root. If two skills share the same `name`, Codex doesn't merge them; both can appear in skill selectors.”，位置表把 `REPO` 拆成 `$CWD/.agents/skills`、`$CWD/../.agents/skills` 与 `$REPO_ROOT/.agents/skills` 三行；源码 `codex-rs/ext/skills/src/host_roots.rs`（rust-v0.166.0 标签提交 `6ff1e1ca3b30fc8b914720681fcf5fe62e95f856` 下 14,342 字节、403 行）用 `find_project_root` 求最近的项目根 marker（marker 集合可由配置层覆盖、回落 `default_project_root_markers()`，为空时项目根即 cwd），`dirs_between_project_root_and_cwd` 收集 cwd 到项目根含两端的全部祖先后 `reverse()`，再对每级并发探测 `<dir>/.agents/skills`，**每个存在的目录都成为一个 `SkillScope::Repo` 根**，最后按路径去重保留首次出现者。该页只列位置、不给层级优先级顺序；`allow_implicit_invocation`（默认 `true`）与 `[[skills.config]]` 的 `enabled = false` 都逐字复核。坐标说明：官方仓库 `docs/skills.md` 在标签与 main 下都只有 115 字节、仅指向 `https://developers.openai.com/codex/skills`，后者以 308 跳回 `build-skills`，而 `https://learn.chatgpt.com/docs/skills` 是 404。

**Qwen Code 是五家里唯一项目层只认单一项目根的**：官方 `docs/users/features/skills.md`（v0.26.5 标签提交 `db0e4e24a0d89b211b2a15f4af2be22adac71dfc` 下 26,272 字节，与 main `7b4b35375071` 逐字节相同）列出五类来源与同名规则 “When two Skills share a name, the first one found wins: project, then personal (including custom directories), then extension, then bundled.”；源码 `packages/core/src/skills/skill-manager.ts`（48,340 字节）的 `getSkillsBaseDirs('project')` 只用 `this.config.getProjectRoot()`，`getSkillsBaseDirs('user')` 才追加 `getCustomSkillDirs()`，watch 只覆盖 project 与 user 两层。**确认 `skills.directories` 归 user 层**：`settingsSchema.ts`（243,865 字节）的描述逐字为 “Additional directories to scan for skills (SKILL.md files). Skills from these directories are loaded at user level, after the default user skill directories; a custom skill with the same name as one in the default user directories will not override it.”，`requiresRestart: true`、UNION 合并；其余四个键的 `requiresRestart` 与合并策略一并补录（`disabledLevels` 为 `true`，`disabled`／`defaultDisabled`／`enabled` 为 `false`）。全页 0 次出现 `--include-directories`／`additionalDirectories`，官方设置参考仍无任何 `skills.*` 行。
