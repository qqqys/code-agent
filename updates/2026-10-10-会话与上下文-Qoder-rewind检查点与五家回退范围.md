# 检查点与回退：Qoder CLI `/rewind` 的三种恢复范围与 `general.fileCheckpointing.enabled` 默认 `true`，五家回退锚点、保留期与 Shell 边界补齐

Qoder CLI 官方 [Undo and Restore](https://docs.qoder.com/cli/undo-restore) 页与 [Slash 命令参考](https://docs.qoder.com/cli/slash-reference) 都确认 `/rewind` 是 CLI 会话内的一等命令：命令参考把它列在 “Sessions and Conversations” 分组、描述逐字为 “Roll back to a specific checkpoint.”，且不在 Conditional Commands 说明里；Undo and Restore 页记录它以对话中发送过的用户消息为检查点，恢复范围可在“对话与文件”（默认）、“只对话”、“只文件”之间选择，确认前显示 “Rewinding now will revert 3 files (+42 -17)” 一类影响提示。[设置参考](https://docs.qoder.com/cli/settings-reference) 另给出 `general.fileCheckpointing.enabled`：boolean、默认 `true`、描述逐字为 “Enable file checkpoints (code rollback).”、写入 `settings.json`、改动需重启、没有对应环境变量。

这是本仓库漏记并写错默认值的一手确认能力，不是产品新增：`cmd-rewind`（回退或检查点）的 Qoder 列此前写 `—`，Qoder 命令目录里也没有 `/rewind`；`session-checkpoint`（检查点与回退）的 Qoder 列只写 “SDK 条件：`rewindFiles()`”，详情还写“功能默认关闭”，与设置参考的默认 `true` 冲突。Release Notes 的 CLI 1.1.23（2026-08-15）小节标题已含 “Session Resume, Rewind, and Tool-Call Fixes”、CLI 1.1.29（2026-08-24）记 “Fixed being unable to fork and rewind history messages after compaction”，说明该命令至少自 2026-08 起存在，但官方没有写明引入版本。

本次只处理“检查点与回退”一个能力，即 `session-checkpoint` 与它在命令矩阵中的镜像行 `cmd-rewind`，把五家的回退锚点、恢复范围、保留期与 Shell/副 Agent 边界逐项核对到当前一手资料。
