# 终端、代码与任务执行

[返回总矩阵](./02-功能总矩阵.md) · [下一篇：模型、Provider 与认证](./04-模型Provider与认证.md)

这一层回答最基本的问题：把一个真实代码仓库交给它，它能不能找到代码、修改文件、
执行命令，并把一个多步骤任务做完。

## 五方表现

| 能力 | Claude Code | Codex | Qwen Code | Kimi Code | Qoder CLI |
| --- | --- | --- | --- | --- | --- |
| 主要入口 | 成熟终端 TUI，也有 IDE、Desktop、Web | CLI、IDE、Codex App、Cloud | CLI、IDE、Desktop、Web Shell、IM | 以轻量终端 TUI 为主 | CLI，可把任务送往 Qoder Cloud |
| 读与搜代码 | 文件读取、Glob、Grep、语言服务和 Agent 探索 | 仓库搜索、文件读取、命令执行 | 文件/目录搜索、LSP、代码工具 | 官方确认可搜索和读取代码 | 面向仓库理解与任务执行 |
| 修改文件 | Edit/Write，可完成跨文件任务 | 在工作区与沙箱边界内编辑 | Edit/Write、Notebook、Artifact | 官方确认可编辑代码 | 文件操作受权限规则控制 |
| 执行命令 | Bash，可转入后台 | Shell，受审批和沙箱约束 | Shell、后台执行与进程监控 | Shell | Bash，支持 allow/ask/deny |
| 外部信息 | Web Search、Web Fetch | Web Search，网络能力受策略控制 | Web Search、Web Fetch、MCP | 可抓取网页 | Web Search、Web Fetch 与 MCP |
| 多模态 | 图片、PDF 等能力取决于入口与模型 | CLI 可附图，App 提供更完整视觉入口 | 图片理解、Computer Use、图片工具 | 官方突出视频输入 | 当前公开 CLI 文档信息不足，标记待验证 |
| 长任务体验 | 计划、Todo、后台 Shell/Agent | CLI 长任务，App/Cloud 适合并行和异步 | Plan、Todo、Workflow、后台 Agent/Shell | 强调快速启动和长会话 TUI | Cloud Mode 可在本地终端关闭后继续 |

## 差异怎么看

Claude Code 的优势不是“能改文件”本身，而是终端交互、Git 工作流、扩展系统和多端
入口已经形成一套连贯体验。Codex 把任务执行与系统沙箱、桌面多 Agent、云任务结合，
更像一个从本地延伸到云端的 Agent 工作台。

Qwen Code 的覆盖面最宽：它既是终端 Agent，也提供 Daemon、SDK、IDE、Desktop 和
IM Channel。优势是可组合，代价是用户需要更清楚地理解“当前在哪个入口、哪些能力
在这个入口可用”。

Kimi Code 当前更强调轻量、快速 TUI、单文件分发和视频输入。它是新产品，不能把旧
Kimi CLI 的每项能力直接算到新版头上。Qoder CLI 的特点是把本地 CLI 和 Cloud
Mode 放在同一条任务链路里，适合把耗时工作交给云端。

## 选择建议

- 只想装好就用、日常在终端里高频编码：先试 Claude Code。
- 需要较强的本地隔离，或想同时管理多个长任务：优先看 Codex。
- 要接不同模型、嵌入自有平台或改造运行时：优先看 Qwen Code。
- 看重启动速度、轻量终端和视频输入：试 Kimi Code。
- 已经使用 Qoder，或需要云端任务继续运行：看 Qoder CLI。

## 对 Qwen Code 的启示

Qwen Code 不缺工具数量，最值得补的是一致性：同一个“后台任务”“图片输入”或
“代码审查”能力，在 CLI、IDE、Desktop、Web Shell 和 IM 入口中应该有一致的名字、
状态和失败提示。用户应先看到任务是否完成，再看到它由哪个运行时完成。
