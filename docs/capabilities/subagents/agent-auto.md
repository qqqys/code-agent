# 自动委派

[返回 Subagent 详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=agent-auto)

> 核对日期：2026-10-27

## 定义

主 Agent 在用户没有点名 Subagent 时，依据什么信息选择并派发 Subagent，以及「派发」这个动作本身是否还要先被授权。

## 比较边界

### 本页包含

- 自动匹配依据与描述字段语义
- 派发是否需要先获得授权
- 项目指令、Skill 与多代理模式对委派的影响
- 关闭或限制自动委派的开关与描述长度告警

### 本页不包含

- 用户显式点名与 @ 提及
- 模型路由质量评价
- 并发调度算法与并发上限

## 跨产品事实

1. 五家都把 `description` 作为主 Agent 挑选 Subagent 的依据：Claude Code 的字段表写 “When Claude should delegate to this subagent”，Codex 写 “Human-facing guidance for when Codex should use this agent.”，Qwen Code 的示例注释写 “Brief description of when and how to use this agent”，Kimi Code 写 “Agent 的用途。main agent 挑选 subagent 时会看到，请围绕委派决策来写”，Qoder CLI 写 “Description of when to use this Subagent. Qoder CLI uses it for selection.”。
2. Kimi Code 另有可选的 `whenToUse`（“补充说明何时应使用该 Agent”）；源码里 `buildProfileDescriptions()` 把 `description` 与 `whenToUse` 过滤空值后用空格拼成 `- <name>: <details>` 一行，两者都只出现在 “Available agent types (pass via subagent_type):” 清单里。
3. 默认行为在核对日期分成两组：Claude Code、Qwen Code 与 Qoder CLI 的官方文档都把「按描述主动委派」写成默认行为，Codex 与 Kimi Code 都要求先有请求或指令。Codex 的官方措辞是本地版本 “delegate when you ask directly or when applicable `AGENTS.md` or skill instructions request it”，Kimi Code 自 2.3.2 起改为 “Do not launch a subagent unless the user explicitly asks for one.”。
4. 授权的落实方式分两层：提示词层是工具描述与系统提示词文本（Kimi 的 `agent.md` 与 `system.md`、Codex 的 `AGENTS.md` 与 Skill 指令），代码层是硬门禁（Kimi 的 `AgentSwarm` 在 swarm mode 关闭时由 `resolveExecution()` 直接返回 `isError: true` 的结果，不启动任何 subagent）。
5. 描述长度只有两家给出数字：Claude Code 是全部 Subagent 的 `description` 合计 15000 token 的启动告警且仍加载全部定义，Qwen Code 是单个 `description` 超过 1000 字符、系统提示词超过 10000 字符的软告警且官方写明 “no hard limits are enforced”。Codex、Kimi Code 与 Qoder CLI 的 Subagent 文档没有公布描述长度上限。
