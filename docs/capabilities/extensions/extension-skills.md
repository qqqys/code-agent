# Agent Skills

[返回扩展系统详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=extension-skills)

## 定义

以 SKILL.md 为入口，把可复用指令、脚本和参考材料按需加载到 Agent，并比较发现目录、调用方式与优先级。

## 比较边界

### 本页包含

- 用户级、项目级和插件级 Skill 目录
- 显式 Slash 或名称调用与模型自动匹配
- SKILL.md 及同目录脚本、模板、参考资料

### 本页不包含

- 仅有一段提示词的内置 Slash 命令
- 项目长期指令文件
- MCP Server 提供的 Prompt

## 跨产品事实

1. 五家当前都采用包含 `SKILL.md` 的目录结构，并允许把辅助文件与入口指令放在同一 Skill 包内。
2. Codex 使用通用 `.agents/skills` 目录和 `$skill` 显式引用；Kimi Code 的明确命名空间是 `/skill:<name>`；其余三家支持 `/<skill-name>`。
3. Skill 可被模型自动选择不代表一定执行；描述匹配、可用路径、禁用配置和同名优先级都会改变最终加载结果。
4. 项目级 Skill 的发现宽度差别很大：Claude Code 从启动目录一路向上到仓库根都加载 `.claude/skills/`，启动目录之下的嵌套目录在 Claude 首次读写该子目录文件时才加载，`--add-dir`／`/add-dir`（以及 Agent SDK 的 `additionalDirectories`／`add_dirs`，因为它们以 `--add-dir` 传入）目录也加载并带 live reload，而设置键 `permissions.additionalDirectories` 只给文件访问；Codex 仓库层 “scans `.agents/skills` in every directory from your current working directory up to the repository root”；Qoder CLI 自 CLI 1.1.28（2026-08-21）起 “Added automatic loading of skills in a directory added with `/add-dir`”；Kimi Code 在 main 分支把每个已配置源目录的项目级 Skill 合并进同一列表（尚未发布）。只有 Qwen Code 的项目层始终只认单一 `getProjectRoot()`，`skills.directories` 是显式清单且按 user 层加载。持久化边界也不同：Kimi Code 把目录「记住到工作区」后它就长期作为共享源目录贡献 Skill，而 Claude Code 唯一能跨会话持久化附加目录的键 `permissions.additionalDirectories` 明确不加载 Skill，官方文档没有把「加载 Skill 的附加目录」持久化的办法。
5. 同名处理有五种口径：Claude Code “Enterprise over personal, and personal over project”，与 added directory 的 Skill 冲突时后者改用前缀名（如 `/cli:verify`，需 v2.1.309 及以上）、两个 added directory 之间先加入者胜；Codex 明确不合并——“If two skills share the same `name`, Codex doesn't merge them; both can appear in skill selectors.”；Qwen Code “the first one found wins: project, then personal (including custom directories), then extension, then bundled”；Kimi Code 按 Project > User > Extra > Built-in，多目录时主目录优先、附加目录按工作区顺序；Qoder CLI 按 built-in < plugins < project-level < user-level，即用户级压过项目级。
6. 禁用粒度不对齐：Qwen Code 用 `skills.disabledLevels` 整体关闭某个发现层级（`project`/`user`/`extension`/`bundled`），Claude Code 用 `disableBundledSkills` 只关内置层并以 `skillOverrides` 逐个控制，Codex 按 `SKILL.md` 路径在 `[[skills.config]]` 逐个禁用，Kimi Code 只在 frontmatter 逐个关闭模型自动调用（层级侧仅 `builtin_product_skills` 能关掉介绍自身的那部分内置 Skill），Qoder CLI 现行文档没有任何 Skill 软禁用键、更新日志提到的 `settings.skills.disabled` 在设置参考里没有对应行。
7. Kimi Code 支持一条提示词引用多个 Skill 并同时激活：空白字符后输入 `/` 插入 Skill token，全部引用与提示词作为同一轮次运行、一次 `/undo` 整体撤销，该行为已随 0.37.0（2026-08-18）发布并存在于当前稳定版 2.4.1；其余四家已固定的一手文档没有描述等价的单条提示词多 Skill 显式激活行为。
