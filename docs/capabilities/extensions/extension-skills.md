# Agent Skills

[返回扩展系统详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=extension-skills)

> 核对日期：2026-11-26

## 定义

以 SKILL.md 为入口，把可复用指令、脚本和参考材料按需加载到 Agent，并比较发现目录、调用方式、优先级，以及是否存在文件系统以外的 Skill 来源。

## 比较边界

### 本页包含

- 用户级、项目级和插件级 Skill 目录
- 显式 Slash 或名称调用与模型自动匹配
- SKILL.md 及同目录脚本、模板、参考资料
- MCP Server 作为 Skill 来源时的命名、审批、可用界面与关闭入口

### 本页不包含

- 仅有一段提示词的内置 Slash 命令
- 项目长期指令文件
- MCP Server 提供的 Prompt（走各自的命令通道，不计入 Skill 来源）
- MCP 工具、MCP 资源与 MCP 异步任务本身

## 跨产品事实

1. 五家当前都采用包含 `SKILL.md` 的目录结构，并允许把辅助文件与入口指令放在同一 Skill 包内。
2. Codex 使用通用 `.agents/skills` 目录和 `$skill` 显式引用；Kimi Code 的明确命名空间是 `/skill:<name>`；其余三家支持 `/<skill-name>`。
3. Skill 可被模型自动选择不代表一定执行；描述匹配、可用路径、禁用配置和同名优先级都会改变最终加载结果。
4. **由 MCP Server 提供 Skill 目前只有 Claude Code 一家**：官方称之为 “Skills over MCP”，Server 实现 MCP Skills 扩展（`https://modelcontextprotocol.io/extensions/skills/overview`）后即可与工具一起下发 Skill，客户端把它命名为 `<server>:<skill>`。文档三处（MCP 页、Skills 页、设置参考）都写 “require Claude Code v2.1.331 or later”，而更新日志到 `## 2.1.332` 才出现该条，v2.1.331 段没有任何 MCP Skill 条目，故按「文档写 v2.1.331、更新日志 v2.1.332 宣布」记录。其余四家在 2026-11-26 核对日期都没有该来源，而且四家的 Skill 来源枚举里都没有 MCP 一档——Qwen Code `SkillLevel = 'project' | 'user' | 'extension' | 'bundled'`（v0.28.6）、Kimi Code `SkillSource = 'project' | 'user' | 'extra' | 'builtin'`（2.8.0）、Codex 的六行位置表为 REPO／USER／ADMIN／SYSTEM、Qoder CLI 的位置表只有用户级与项目级两行。
5. 四家「MCP 与 Skill 的关系」各不相同，不能互相套用：Claude Code 是 Server 在运行时列出并下发 Skill、辅助文件按 MCP 资源读取；Codex 的插件包可以同时装 Skill 与 MCP 连接（“Plugins can include one or more skills. They can also optionally bundle registered MCP server connections…”），但 Skill 仍是包内文件而不是 Server 下发；Qwen Code 只把 Server 的 **Prompt** 注册成 Slash 命令（`McpPromptLoader`，命令名用裸 prompt 名、不加 `<server>:` 前缀，`sourceLabel` 为 `MCP: <server>`），Skill 侧没有 MCP 通道；Kimi Code 的 MCP 客户端在源码与文档层面都只承载工具（`mcpCore/connection-manager.ts`，2.8.0，38,088 字节，对 prompt／resources／skills 的命中数为 0）；Qoder CLI 的 Skills 页对 `mcp`、MCP 两页对 `skill` 命中数也都是 0、SDK Skills 页穷举的来源值只有 plugin／user／project／local 加内置，但其更新日志 CLI 1.1.77 有一条 “failed to fetch the prompts or resources list”，说明客户端握手时也会取这两类列表，取到后是否呈现给用户官方没有写。
6. MCP 来源的 Skill 在能力上被刻意削弱，与本地 Skill 不同层：Claude Code 明确忽略 MCP Skill 的 11 个 frontmatter 字段（`allowed-tools`、`disallowed-tools`、`hooks`、`model`、`effort`、`context`、`agent`、`background`、`shell`、`paths`、`metadata`），`!` 命令不执行、`@` 引用不附加、`${CLAUDE_PROJECT_DIR}` 与 `${CLAUDE_SESSION_ID}` 不替换，并逐字写 “With a skill from an MCP server, Claude gets no `allowed-tools` grant.”；这与本地 Skill「`allowed-tools` 在调用该 Skill 的那一轮预授权工具、下一条消息发出后失效」形成对照。
7. 关闭 MCP Skill 的入口只在组织侧：`disableDirectMcpSkills` 的 Scope 是 `Managed`，用户设置、项目设置与 `--settings` 都不是它的作用域，claude.ai 连接器则改由 Organization settings > Connectors 的 **Skills over MCP** 开关控制；四家里没有一家给出「用户级一键关闭整个 Skill 来源层」的等价键——Qwen Code 的 `skills.disabledLevels` 只覆盖 project／user／extension／bundled 四个文件系统层，Claude Code 的 `disableBundledSkills` 只关内置层。
8. 项目级 Skill 的发现宽度差别很大：Claude Code 从启动目录一路向上到仓库根都加载 `.claude/skills/`，启动目录之下的嵌套目录在 Claude 首次读写该子目录文件时才加载，`--add-dir`／`/add-dir`（以及 Agent SDK 的 `additionalDirectories`／`add_dirs`，因为它们以 `--add-dir` 传入）目录也加载并带 live reload，而设置键 `permissions.additionalDirectories` 只给文件访问；Codex 仓库层 “scans `.agents/skills` in every directory from your current working directory up to the repository root”；Qoder CLI 自 CLI 1.1.28（2026-08-21）起 “Added automatic loading of skills in a directory added with `/add-dir`”；Kimi Code 自 2.5.0（npm 发布 2026-11-04T11:59:13Z）起把每个已配置源目录的项目级 Skill 合并进同一列表、自 2.6.0（npm 发布 2026-11-12T10:11:33Z）起把同名 Skill 保留为独立 Skills 分组里的可选变体（**此前记录的「main `3ed0e68f3bbf`，尚未发布」已作废**）。只有 Qwen Code 的项目层始终只认单一 `getProjectRoot()`，`skills.directories` 是显式清单且按 user 层加载。持久化边界也不同：Kimi Code 把目录「记住到工作区」后它就长期作为共享源目录贡献 Skill，而 Claude Code 唯一能跨会话持久化附加目录的键 `permissions.additionalDirectories` 明确不加载 Skill，官方文档没有把「加载 Skill 的附加目录」持久化的办法。
9. 同名处理有五种口径：Claude Code “Enterprise over personal, and personal over project”，与 added directory 的 Skill 冲突时后者改用前缀名（如 `/cli:verify`，需 v2.1.309 及以上）、两个 added directory 之间先加入者胜，MCP 来源则一律带 `<server>:` 前缀因而「other skills keep their names」；Codex 明确不合并——“If two skills share the same `name`, Codex doesn't merge them; both can appear in skill selectors.”；Qwen Code “the first one found wins: project, then personal (including custom directories), then extension, then bundled”；Kimi Code 按 Project > User > Extra > Built-in，多目录时同名 Skill **全部保留为变体**、只有裸名调用才按主目录优先与目录顺序取默认项；Qoder CLI 按 built-in < plugins < project-level < user-level，即用户级压过项目级。
10. 禁用粒度不对齐：Qwen Code 用 `skills.disabledLevels` 整体关闭某个发现层级（`project`/`user`/`extension`/`bundled`），Claude Code 用 `disableBundledSkills` 只关内置层并以 `skillOverrides` 逐个控制、MCP 来源另走 `Skill(mcp__<server>__*)` 权限规则，Codex 在 `[[skills.config]]` 里按 `path` 或 `name` 逐个禁用（“Use exactly one selector per entry… When more than one entry matches a skill, the last matching entry wins.”）并以 `[skills.bundled] enabled = false` 整层关掉内置 Skill，Kimi Code 只在 frontmatter 逐个关闭模型自动调用（层级侧仅 `builtin_product_skills` 能关掉介绍自身的那部分内置 Skill），Qoder CLI 现行文档没有任何 Skill 软禁用键、更新日志提到的 `settings.skills.disabled` 在设置参考里没有对应行。
11. Kimi Code 支持一条提示词引用多个 Skill 并同时激活：空白字符后输入 `/` 插入 Skill token，全部引用与提示词作为同一轮次运行、一次 `/undo` 整体撤销，该行为已随 0.37.0（2026-08-18）发布并存在于当前稳定版 2.8.0；其余四家已固定的一手文档没有描述等价的单条提示词多 Skill 显式激活行为。

To use a skill, ask Claude, or type its name as a command.”，更新日志同口径写 “They show as `server:skill` in the `/` menu; other skills keep their names”，即只有 MCP 来源加前缀。 |
| 文件与目录 | 官方 `## Choose where skills load` 表有七行：Enterprise（managed settings 目录下的 `.claude/skills/<skill-name>/SKILL.md`）、Personal `~/.claude/skills/`、Project `.claude/skills/`、Nested `<subdir>/.claude/skills/`、Additional directory（“a directory you pass with `--add-dir`”，作用范围 “That session.”）、Plugin `<plugin>/skills/`（以 `/plugin-name:skill-name` 出现）与 claude.ai account 同步的 Skills。**该七行表在 2026-11-26 核对日期没有为 MCP 来源新增第八行**，MCP Skill 只写在 MCP 页的 “Use skills from MCP servers” 一节与 Skills 页的 “Skills from MCP servers” 一节；它不落在任何本地目录里，官方逐字为 “With Skills over MCP, a server can provide skills alongside its tools. This works for claude.ai connectors, servers you add, and servers from plugins.”，服务端要实现 MCP Skills 扩展（“implement the Skills extension, an extension to MCP that defines how servers list and deliver skills”，规范地址 `https://modelcontextprotocol.io/extensions/skills/overview`）才能列出并下发 Skill。 |
| 具体行为 | 先发现名称和描述，需要时再读取完整 SKILL.md，并可继续打开同目录脚本、参考资料和模板。MCP Skill 的辅助文件不走本地文件系统，官方逐字为 “Claude reads a skill's supporting files from the server as MCP resources.”，因此关掉 MCP Skill 的 `deny` 规则不影响普通资源读取——“With `deny` rules, normal resource reads from the server are still allowed. To stop Claude from reading any server's resources, including allowed skills' supporting files, deny `ReadMcpResourceTool`.”。 |
| 作用域与优先级 | 项目层不止一个目录：“Claude Code loads project skills from `.claude/skills/` in the directory where you start it and in every parent directory up to the repository root”，`/cd` 移动会话（v2.1.246 及以上）会把新目录的项目 Skill 加进来；启动目录**之下**的 `.claude/skills/` 启动时不加载，“They load the first time Claude reads or edits a file in that subdirectory and stay available for the rest of the session.”，要提前加载可用 `/add-dir <子目录>`（需 v2.1.257 及以上）。项目外目录也贡献 Skill：“When you add a directory with `--add-dir` or `/add-dir`, Claude Code loads the skills in that directory's `.claude/skills/`, along with its `.claude/commands/` and `.claude/agents/.”，Agent SDK 的 `additionalDirectories`（TS）与 `add_dirs`（Python）因为以 `--add-dir` 传入所以同样加载；但设置键 `permissions.additionalDirectories` “grants file access only and loads none of these”，Permissions 页的加载表把 Skills 记为 “Yes, with live reload”、`.claude/commands/` 与 `.claude/agents/` 记为 “Yes, without live reload”。这些加载依赖默认开启的 `project` setting source，`strictPluginOnlyCustomization` 策略、bare mode 与 `--safe-mode` 会进一步收紧（`--bare` 行仍写明 “Skills in a directory you pass with `--add-dir` still load.”）。Worktree 会话只向上搜到 worktree 根，v2.1.277 起当 worktree 检出根没有 `.claude/skills` 时改读主检出的项目 Skill。版本时间线取自官方更新日志：v2.1.32 “Skills defined in `.claude/skills/` within additional directories (`--add-dir`) are now loaded automatically.”，v2.1.257 让 `/add-dir` 接受当前工作目录之内的目录并 “loads that directory's skills, commands, and agents like `--add-dir` does at startup”，v2.1.309 “Fixed a skill in an `--add-dir` folder being unreachable when another skill already held its name; it is now offered as `<folder>:<name>`”。官方五页文档都没有 multi-root／workspace source directory 一类词汇，模型是「一个主工作目录 + 若干附加目录」；由于唯一能跨会话持久化附加目录的键 `permissions.additionalDirectories` 明确不加载 Skill，**没有文档化的办法把「加载 Skill 的附加目录」持久化到下一次会话**，这一点与 Kimi Code「把目录记住到工作区即成为共享源目录」不同。 |
| 扩展构成 | `SKILL.md` 前置元数据、正文指令，以及可选脚本、资源和嵌套目录。企业、个人与项目位置的 `<skill-name>` 可以是指向别处的符号链接，多处指向同一目标时只加载一次。MCP 来源的 Skill 只有 Server 下发的 `SKILL.md` 文本与作为 MCP 资源读取的辅助文件，官方在 `#### Skill features that don't apply` 里逐字写 “Because the server supplies the content, you can't use these features of local skills in an MCP skill:” 并列出四条——“**Frontmatter fields**: Claude Code ignores `allowed-tools`, `disallowed-tools`, `hooks`, `model`, `effort`, `context`, `agent`, `background`, `shell`, `paths`, and `metadata`”（共 11 个字段）、“**`!` commands**: they don't run”、“**`@` references**: the files aren't attached”、“**`${CLAUDE_PROJECT_DIR}` and `${CLAUDE_SESSION_ID}`**: they aren't substituted”。 |
| 加载与刷新 | 官方逐字为 “Claude Code watches skill directories for file changes, except in bare mode. When you add, edit, or remove a skill under `~/.claude/skills/`, the project `.claude/skills/`, or a `.claude/skills/` inside an `--add-dir` directory, Claude Code picks up the change within the current session, without a restart.”；会话启动后才创建的顶层 skills 目录要用 `/reload-skills`——命令参考页的描述是 “Re-scan skill and command directories so skills added or changed on disk during the session become available without restarting. Reports how many skills are available and how many were added or removed”，且此后每次改动都要再跑一次；“Live change detection covers `SKILL.md` text only.”，同时是插件的 Skill 文件夹改 `hooks/`、`.mcp.json`、`agents/`、`output-styles/` 需 `/reload-plugins`；`--add-dir` 目录的 `.claude/commands/` 与 `.claude/agents/` 不被监听，改后要重启会话。Skills 与旧式 `.claude/commands` 在 Slash 命令界面合并呈现。MCP Skill 的刷新口径不是文件监听而是版本审批：官方写选 **Allow this version** 后 “skip the prompt and the classifier until the server changes the skill's files”，即 Server 改动该 Skill 的文件后审批自动失效；`/reload-skills` 的官方描述只提 “skill and command directories”，命令页的 `/skills` 行也只写 “List available skills. Type to filter the list by name, description, or source.”，两页都没有说明 MCP 来源是否随之刷新，故记为未确认。MCP 页排障表另给两条与加载有关的处置——“`Unknown command`, or Claude treats the command as text”→“Send it again.”、“No **Protocol** row on a connected server's `/mcp` page”→“Confirm the server supports MCP revision 2026-07-28 or later, over HTTP or stdio. If a stdio server takes over 3 seconds to start, change its command from `npx` to the installed program, then select **Reconnect**.”。 |
| 适用界面 | 以 Claude Code CLI 为准；VS Code 扩展、桌面端或 Headless 中不同的入口会单独注明。MCP Skill 另有一张明确的界面清单：可用的是 “a terminal, including in JetBrains IDEs, and in local sessions you start in the Desktop app”，VS Code 扩展 “they're rolling out and turn on without a setting”，Remote Control 下 “ask Claude to use a skill instead of sending its command”；不支持的会话逐字为 “cloud sessions, `claude -p`, `claude remote-control` server mode, GitHub Actions, and the Agent SDK”，桌面端里不支持的 Server 是 “connectors, Desktop extensions, and servers from `claude_desktop_config.json`”，不支持的连接方式是 “cloud providers, a custom `ANTHROPIC_BASE_URL`, `apiKeyHelper`, and `ANTHROPIC_AUTH_TOKEN`”，另有合规设置一类 “organizations with a setting such as HIPAA or zero data retention. For connectors, this includes customer-managed encryption keys.”。 |
| 权限与信任 | Skill 只是指令与资源包；其中要求调用的工具仍经过 Claude Code 权限规则。v2.1.282 起修掉了仓库、用户与 `--add-dir` 三类 Skill（以及 commands 与 skills 目录型插件 manifest）在托管 `allowManagedPermissionRulesOnly` 下用自带 `allowed-tools` 自我预授权的问题。MCP Skill 走另一套：官方逐字写 “With a skill from an MCP server, Claude gets no `allowed-tools` grant.”，且不能用 Skill 名的 `allow` 规则免询问——“For a skill from an MCP server, set a rule for its server instead. You can't skip its prompt with an `allow` rule for the skill's name.”；按 Server 的规则表五行为 `deny` `Skill(mcp__docs__*)`（“Block its skills, including typed commands”）、`deny` `Skill(docs:pdf)`（“Block only its `pdf` skill”）、`deny` `mcp__docs`（“Block its skills and tools”）、`ask` `Skill(mcp__docs__*)`（“See a prompt each time Claude loads one”）与 `allow` `Skill(mcp__docs__*)`（“Approve all versions of its skills”），其中 `allow` 规则限定 “Add the `allow` rule to user or managed settings.
