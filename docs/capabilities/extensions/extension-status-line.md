# 自定义状态行

[返回扩展系统详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=extension-status-line)

> 核对日期：2026-11-20

## 定义

记录终端界面底部那条常驻状态行（各家用语不同：status line、状态栏、Status Bar、footer）的可定制程度——能不能挑选和排序内置条目、能不能把整行交给用户 Shell 命令或 MCP Server 渲染、内容从哪里来、什么时候刷新、失败时怎么办，以及配置写在哪个作用域、在哪些界面生效。

## 比较边界

### 本页包含

- 状态行的内容来源：内置条目清单、用户脚本、MCP Provider
- 脚本或 Provider 的输入契约（stdin JSON 或 resource read 的 meta 载荷）、输出行数、超时、失败回退与刷新触发
- 配置键名、默认值、作用域与持久化位置，以及关闭或清空状态行的入口
- 生成脚本的辅助入口（`/statusline` 一类命令、对话框、子代理）
- 与状态行绑定的信任、沙箱或托管设置门控

### 本页不包含

- 终端窗口或标签标题：Codex `tui.terminal_title`、Qoder `ui.dynamicWindowTitle`、Qwen `ui.showStatusInTitle` 是另一条能力
- 发给终端或复用器的会话状态协议，例如 Qoder 的 OSC 7501 与 Codex 的 `activity` 标题项
- 主题、语法高亮与输出风格，只有影响状态行配色的那个开关计入本页
- 会话内一次性的进度提示、spinner 文案、工具执行状态行与 VS Code 面板、Cloud、Remote Control 界面自己的状态条

## 跨产品事实

1. 五家都在终端底部有一条常驻状态行，但「可自定义」分三档：Claude Code、Qwen Code、Kimi Code 与 Qoder CLI 都能把整行交给用户 Shell 命令，Codex 已发布版本只能挑选并排序内置条目、不执行用户脚本。
2. 只有 Codex 走 MCP。main 分支新增 `tui.status_line_provider`，MCP 工具用 `tool.meta["openai/ui"].entrypoints` 里 `type` 为 `statusline` 的入口给出一个 `ui://` 资源 URI，Codex 读该资源并把线程状态快照放在请求 `meta` 的 `com.openai/codex-statusline-state` 键下，返回内容要过 JSON UI 树校验；整条路径由 `features.tui_extensions_statusline`（`Stage::UnderDevelopment`、`default_enabled: false`）门控，2026-11-17 的六个提交（PR #61979、#61981、#61985、#61986、#61988、#61990）都晚于当日最新的 `rust-v0.171.0-alpha.11`，尚未随任何 Release 发布。
3. 默认状态相反。Qwen Code 未设置 `ui.statusLine` 时自动套用内置预设（v0.19.3 起），要显式写 `null` 才关闭；Claude Code 官方写 “**Default**: unset, so no status line”；Codex 未设置时用三个默认条目；Kimi `items` 为 `null` 时用七个默认槽位；Qoder 不写 `statusLine.command` 时显示内置默认状态栏。
4. 内置条目数量差一个数量级：Codex 33 个 kebab-case id（另有一批别名，如 `model-name`→`model`、`session-id`→`thread-id`、`context-usage`→`context-used`）、Qwen 16 个 id、Kimi 8 个槽位；Claude Code 与 Qoder CLI 不提供内置条目清单，内容完全由脚本决定。
5. 脚本输入契约都是「JSON 进、文本出」，但字段面差别很大。Claude 的载荷最宽，覆盖 model、workspace、cost、context_window、effort、thinking、rate_limits、prompt_cache、session、output_style、vim、agent.name、pr 与 worktree；Qwen 次之，含 `metrics` 与 `worktree`，源码注释明写字段名对齐 claude-code 以便两个 CLI 共用脚本；Kimi 只有 10 个字段；Qoder 官方只写 “including Session ID, Working Directory, model, context usage, Git branch, Vim mode, etc.”，没有字段表。
6. 输出与超时三套口径。Claude 不限行数（每条 `echo` 一行）、没有公布超时，靠「新触发到来就取消在跑的脚本」兜底；Qwen 最多 2 行、5 秒超时、`maxBuffer` 10 KB；Kimi 只取 stdout 首行、300 ms 上限、每秒最多重跑一次、64 KiB 截断；Qoder 与 Codex 的内置条目都没有公布上限。
7. 失败行为分两类。Kimi 明确「失败回退内置布局」，spawn 异常、超时、非零退出与空首行都返回 null；Claude 与 Qwen 是清空——Claude 只在脚本退出码 0 且有 stdout 时显示（“Scripts that exit with non-zero codes or produce no output cause the status line to go blank”），Qwen 报错或空输出把状态行清成空数组。
8. 只有 Claude Code 把状态行与权限体系显式绑定：`statusLine` 执行 Shell 命令，因此走与设置文件里 Hooks 相同的工作区信任规则，未接受信任对话框前保持空白（debug 日志 `Status line command skipped: workspace trust not accepted`），并被 `disableAllHooks`、`allowManagedHooksOnly` 与 `--safe-mode` 三道门收窄到托管设置的值。Qwen 的门禁是另一条：`getShellExecutionSandbox()` 为真时 command 模式静默失效，官方文档没有提到。
9. 生效面全部限定在交互式终端，五家都没有把自定义状态行扩展到 headless、ACP/IDE、Web 或 SDK。代码级证据分别是 Qwen `statuslineCommand.ts` 的 `supportedModes: ['interactive'] as const` 与 `nonInteractiveCli.ts` 的 0 命中、Kimi `FooterComponent` 的引用点全在 `src/tui/**` 且 acp-server／kap-server／vscode／cli 全部 0 命中、Codex `read_only_history` 下直接返回空选择。
10. 生成脚本的方式三家三路：Claude 的 `/statusline` 由主对话按自然语言生成脚本文件并自动更新设置，无参数时按用户 Shell 提示符自动配置；Qwen 的 `/statusline <文本>` 转交内置子代理 `statusline-setup`（工具只有 read_file／write_file／edit），无参数才开对话框；Qoder 的 `/statusline` 官方描述是「读你的 Shell 配置自动生成脚本」；Codex 的 `/statusline` 只是条目选择器，Kimi 没有 Slash 命令、只能改文件后用 `/reload-tui`。
11. 按段配色只有一家。Qoder 提供 `statusLine.colors` 给内置默认状态栏按段配色，取值可以是十六进制、ANSI 名或自然语言色名（如 `ocean blue`），上下文进度条忽略自定义颜色、按用量自动变绿/黄/红；Codex 与 Qwen 各用一个布尔（`tui.status_line_use_colors`、`useThemeColors`）决定是否套用主题色；Claude 与 Kimi 没有配色键，颜色只能由脚本自己输出 ANSI。
12. 文档滞后在三家同时出现。Kimi 中文配置文档的字段表只列 7 个槽位、缺源码里 2.5.0 新增的 `environment`，而自动生成的 `tui.toml` 模板列的是 8 个；Qwen 的 “Example output” 写 5 项且顺序不符合规范序（源码默认是 4 项），“Removal” 一句说删掉键会恢复 `? for shortcuts`（实际回落到默认预设）；Codex 的 Configuration reference 只收录 `tui.status_line`，`tui.status_line_provider`、`tui.status_line_use_colors` 与 `tui_extensions_statusline` 命中数均为 0。

| 扩展构成 | 一个设置对象 `statusLine`：必填 `type: "command"` 与 `command`（脚本路径或内联 Shell 命令，`command` 在 Shell 里跑，官方示例直接用 `jq -r` 内联），可选 `padding`（水平间距字符数，默认 0，是在界面自带间距之上的相对缩进）、`refreshInterval`（每 N 秒额外重跑，最小 1）、`hideVimModeIndicator`（脚本自己渲染 `vim.mode` 时抑制内置 `-- INSERT --`）。周边组件：`footerLinksRegexes` 与 footer badges 是不写脚本就把会话里的 ID 变成可点击徽章的替代路径，官方写明二者 “render alongside a custom status line when one is configured; neither replaces the other”；曾有 `subagentStatusLine` 让 Subagent 行用独立脚本，v2.1.323 起移除。 |
| 加载与刷新 | 会话开始（含恢复）跑一次，之后在新 assistant 消息到达、`/compact` 结束、权限模式变化、Vim 模式切换、`statusLine` 里的 `command` 被改动、`refreshInterval` 计时到点、上次收到的数据里某个 rate-limit 窗口到达 `resets_at`、某个 warm prompt cache 到达 `expires_at` 时再跑。节流是 “Claude Code debounces updates at 300ms, so rapid changes batch together and your script runs once after the changes stop.”，改 `command` 本身跳过去抖立即执行；新触发到来时取消在跑的脚本。官方提醒主会话空闲（例如协调者等后台 Subagent）时事件触发会安静下来，需要 `refreshInterval` 兜底；保存设置文件后 Claude Code 自动重载并立即运行脚本。 |
| 适用界面 | 以交互式终端为准。官方专页对 `desktop`、`VS Code`、`SDK`、`non-interactive`、`-p`、`web` 的命中数均为 0，命令参考里 `/statusline` 行也没有同页其他命令常带的 “Also available in non-interactive mode (`-p`)” 标注，因此 `-p`、Agent SDK、VS Code 面板、桌面端与 Cloud 会话是否渲染自定义状态行记为未确认。需要区分三处同名但不同的东西：更新日志里 `claude remote-control` 的状态行、agent view 里后台会话的 “live status line”、以及 VS Code 面板把后台 Subagent 收成 “one status line under their Agent card”，都不是 `statusLine` 脚本。 |
| 权限与信任 | 因为执行 Shell 命令，`statusLine` 走与设置文件里 Hooks 相同的工作区信任规则：“Until you accept the workspace trust dialog, the status line stays blank.”，接受该文件夹或某个父目录的信任即可，未接受时 `claude --debug` 记录 “Status line command skipped: workspace trust not accepted”。更新日志里有一条对应的安全修复：“Fixed a security issue where `statusLine` and `fileSuggestion` hook commands could execute without workspace trust acceptance in interactive mode.”。组织侧的门控见「作用域与优先级」；`disableAllHooks` 的官方描述就是 “Turn off hooks, a custom status line, and a custom `@` file suggestion command at once”。 |
| 条件与边界 | 默认 “unset, so no status line”。只在脚本退出码 0 且有 stdout 时显示，非零退出或无输出即空白，慢脚本会阻塞刷新直到跑完，官方因此建议脚本保持轻快并缓存 `git status` 一类慢操作。Windows 上装了 Git Bash 走 Git Bash、否则走 PowerShell；Git Bash 会把未加引号的反斜杠当转义字符，`C:\Users\username\script.mjs` 这种路径会丢掉分隔符且失败时没有可见错误，`command` 里的路径要写正斜杠（`~` 可用），跑 PowerShell 脚本要写 `powershell -NoProfile -File C:/Users/username/.claude/statusline.ps1`。首次 API 响应完成前字段可能是 `null`，脚本要自己给回退值；状态行的上下文百分比取自上一次 API 响应，`/context` 会额外估算此后新增的消息因而可能更高。复杂转义序列偶尔与其他 UI 更新重叠导致花屏，多行加转义比单行纯文本更容易出问题。自定义状态行自 v1.0.71 引入（更新日志逐字 “Customizable status line: add your terminal prompt to Claude Code with /statusline”），`refreshInterval` 自 v2.1.97，`padding` 与 `hideVimModeIndicator` 在更新日志里没有对应条目、引入版本未确认；`subagentStatusLine` 在 v2.1.323 移除（“subagent rows always use the default look, and settings files that still hold the key load as before”）；核对日期最新 Release v2.1.326（2026-11-16T22:11:05Z）含三条状态行渲染修复（Ctrl+C／`!` Shell 模式／粘贴图片时消失与跳屏、终端缩放或 `/cd`／`/rename` 后保留旧宽度旧目录旧会话名、自定义状态行旁缺 “esc to interrupt”）。 |
