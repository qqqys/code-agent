# 工具延迟声明与按需发现

[返回扩展系统详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=extension-tool-discovery)

> 核对日期：2026-10-26

## 定义

把部分工具的完整声明从每轮请求的函数列表里撤下，只留下名称级线索，模型需要时用一个发现工具取回完整 schema 再调用，用来压低常驻上下文占用。

## 比较边界

### 本页包含

- 哪些工具默认延迟、哪些始终常驻、哪些可以逐个豁免
- 发现工具的名字、查询形式、参数、返回内容与排序或打分方式
- 打开或关闭延迟声明的配置键、环境变量、默认值与是否需要重启
- 延迟声明对提示词缓存前缀、Subagent、恢复会话与中途连上的 Server 的影响

### 本页不包含

- 工具本身的执行行为、审批规则与沙箱边界
- MCP Server 的传输、认证、连接状态与工作区信任
- Skills 的渐进披露与按需加载正文
- 上下文占用统计命令、压缩阈值与记忆调度

## 跨产品事实

1. 五家都把「声明」和「可用」拆开：被延迟的工具仍然注册、仍然可以调用，只是不在首轮请求的函数列表里；发现工具取回的是 schema 而不是执行权限，调用仍走各自的审批与沙箱。
2. 延迟范围分两档：Codex、Kimi Code 与 Qoder CLI 的官方资料只覆盖 MCP 工具，Claude Code 官方文档也只写 MCP 工具；只有 Qwen Code 把延迟扩到内置工具，v0.25.1 起 `agent`、`list_agents`、`get_goal`、`update_goal` 与 `propose_goal` 也默认延迟，`task_stop`、`monitor`、`computer_use__*` 与 cron/loop 工具同样按需加载。
3. 默认状态分三档：Codex 始终开启且 `tool_search` 与 `tool_search_always_defer_mcp_tools` 两个特性开关都已移除、没有用户关闭入口；Claude Code 与 Qwen Code 默认开启但可以关（`ENABLE_TOOL_SEARCH=false`、`tools.toolSearch.enabled: false`）；Kimi Code 与 Qoder CLI 默认关闭，Kimi 还要实验标志加模型能力两个前提。Kimi 在 2026-10-14 的 main 上多了 `[mcp] default_deferred` 这个全局默认，可以一次把所有 Server 翻成按需加载，但取值仍是 `false`，默认档位没有变。
4. 发现工具的形态分四类：Codex `tool_search` 用 BM25 排序、参数是 `query` 与 `limit`（默认 8）；Qwen Code `tool_search` 支持 `select:Name1,Name2` 精确取名、关键词打分（默认最多 5 条、硬上限 20）与 `+must-word` 必含词；Kimi Code `select_tools` 只接受精确工具名数组、不做关键词检索；Qoder CLI 拆成 `mcp_list`、`mcp_get`、`mcp_call` 三个 Meta Tools。Claude Code 的 `ToolSearch` 在官方工具参考里只有一句描述，没有公开查询参数与排序方式。
5. 对失败查询的处理粒度不同：Kimi Code 的 `select_tools` 把名字分成六类分别回话，还按名字累计失败次数（阈值 `STOP_RETRY_THRESHOLD = 2`）与整轮连续失败次数（达到 3 触发警告）主动劝模型停止猜名字；其他四家的官方资料没有记录同类计数或劝退文案，Codex 与 Qwen Code 只给出空结果或查询格式错误，Qoder CLI 的三个 Meta Tools 连参数与返回内容都未公开。
6. 调用路径分两类：Claude Code、Codex 与 Kimi Code 在加载后由模型直接按本名调用工具；Qwen Code 要求经 `tool_call` 桥调用仍未声明的工具，官方给出的理由是让声明列表逐字节稳定、保住提示词缓存前缀。Qoder CLI 的 `mcp_call` 从名字看像是第三条路径，但官方没有写明它与直接调用的关系。
7. 豁免入口各不相同：Claude Code 有 Server 级 `alwaysLoad` 与工具级 `_meta["anthropic/alwaysLoad"]` 两层，Qwen Code 有 `tools.visible` 与 `tools.toolSearch.threshold` 预载预算，Kimi Code 是双向的——`[mcp] default_deferred = true` 全局开启后单个 Server 仍可写 `deferred: false` 排除，Server 字段始终优先于全局默认；Codex 没有任何豁免键（MCP 工具始终延迟），Qoder CLI 的 `mcp.lazyLoad` 与 `QODER_MCP_LAZY` 都是全局开关，官方资料没有给出单个 Server 或单个工具的豁免方式。
