# 手动压缩

[返回会话与上下文详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=session-compress)

> 核对日期：2026-10-27

## 定义

把较长的会话历史替换或折叠为摘要，使后续模型请求释放更多上下文窗口。

## 比较边界

### 本页包含

- 手动压缩命令
- 自定义压缩指令
- 自动压缩触发与阈值配置
- 空闲触发的自动压缩与缓存过期处理
- 自动压缩触发线前对工具结果的动态收缩

### 本页不包含

- 清空会话
- 删除磁盘上的原始记录
- 与压缩触发无关的单条工具结果静态截断额度

## 跨产品事实

1. 五家都提供手动压缩；自动压缩的可配置项只有 Claude Code、Codex、Qwen Code 和 Kimi Code 公布，Qoder CLI 只在术语表定义 Compaction 而没有公开阈值或开关。
2. 阈值语义分三类：Claude Code 与 Codex 配置绝对 token 数（压缩窗口或触发阈值），Qwen Code 配置上下文窗口占比（`context.autoCompactThreshold`，默认 0.85），Kimi Code 配置为模型输出预留的 token 数（`loop_control.reserved_context_size`）。
3. Qwen Code 与 Kimi Code 的实际触发点都是「占比」与「绝对余量」两者取较早的一个，而两家的公式都只写在源码里：Qwen 的 `computeThresholds()` 算 warn/auto/hard 三级，`auto = min(0.85 × window, window − 20000 − 13000)`、`hard = min(window, max(window − 20000 − 3000, auto + 3000))`，1M 窗口得 auto 850,000 与 hard 977,000；Kimi 的 `shouldCompact()` 为 `usedSize >= W × 0.85 || usedSize + 50000 >= W`，即 `min(0.85W, W − 50000)`，`W` 取 `max_input_tokens ?? max_context_tokens`。
4. 写法上只有 Claude Code 接受多种文本形式并公布越界处理：命令与旗标认纯 token 数（`200000`）、`k`/`M` 后缀（`500k`、`1M`）与 100–1000 的裸数字（按千计），`CLAUDE_CODE_AUTO_COMPACT_WINDOW` 自 v2.1.304 起也认后缀但不带后缀时按字面 token 数读，取值越界或不可用时告警并夹到 100K/1M 或整个忽略；Codex 的 `model_auto_compact_token_limit` 只是 `number`，官方没有公布后缀写法、取值范围或越界告警。
5. Claude Code v2.1.296 起 Subagent frontmatter 与 `--agents` 定义可写自己的 `autoCompactWindow`（100000–1000000 的纯整数），使该 Subagent 比它本来会继承的窗口更早压缩；v2.1.312（2026-10-27 发布）起该字段还能下调 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 设的窗口，此前在这种会话里完全无效，但仍然不能把它抬高。其余四家已固定的一手资料没有 Subagent 级压缩阈值配置。
6. 只有 Claude Code 会因空闲而自动压缩：`idleCompaction` 默认开启，在交互式终端会话、走一小时提示词缓存、能取到 feature flag、上下文达到 200000 token 与约 54 分钟没有请求且机器唤醒五个条件同时满足时，赶在缓存过期前压缩，目的是让下一条消息发送摘要而不是重算整段历史。
7. Qwen Code 与 Kimi Code 都盯着同一段空闲时间但都不做摘要压缩：Qwen Code 的 `context.clearContextOnIdle` 在空闲 60 分钟后清理旧工具结果并保留最近 5 条，理由同样是让后续回合继续复用 Provider 提示词缓存；Kimi Code 的 `cache_expiry_hint` 只在 resume 或长时间空闲后发消息时提醒缓存可能过期，压缩或新建会话都由用户决定。
8. Codex 与 Qoder CLI 的公开资料没有基于空闲时间或缓存过期的触发：Codex 配置参考的压缩键只有 token 阈值、统计口径与提示词覆盖，`features.prevent_idle_sleep` 只防止机器休眠；Qoder CLI 的设置参考没有任何压缩键，发布说明的压缩条目都是失败重试与显示修复。
9. Qwen Code 另有 `/compress-fast`，它不调用模型，只移除旧工具输出和思考内容，因此与摘要压缩不是同一种处理。
10. 压缩触发线前的工具结果收缩只有 Qwen Code 有：v0.26.3-preview.0 起，聊天发送边界按「（auto − 上次用量报告的 prompt+output token − 该预算缩不了的新增输入）÷ 1.5 × 4 字符」算出整批工具结果的字符预算，只在低于该批静态容量（单工具门限 × 可缩减结果数）时生效，官方设计文档写明它 “is a complement to compaction, not a replacement”；静态默认值仍是 25,000 字符 / 1,000 行，显式设置 `truncateToolOutputThreshold` 时整条机制不启用。Kimi Code 的预裁剪裁的是压缩请求自身的历史，不是工具结果。
11. 两家的实现与官方文档不同步：Claude Code 官方 Subagents 页在 v2.1.312 之后仍逐字写设了环境变量时 Subagent 窗口 “has no effect”；Kimi Code 官方配置文档的 `[loop_control]` 表只列四个键、`reserved_context_size` 的默认值列写 “—”，既没有 0.85 触发比例也没有源码默认值 50000，而可取 0.5–0.99 的 `compaction_trigger_ratio` 整键未列。
12. Kimi Code 在 main 分支修掉了自动压缩打断提示词缓存的两处成因（PR #4410 停止从压缩请求剥离动态工具上下文、PR #4456 只在请求真的超出「窗口 − 输出预留」时才预裁剪历史），两者都还没进 Release；修复前窗口大于约 195k 的模型每次自动压缩都会从 `history[0]` 断开缓存前缀。
13. 压缩通常是有损的上下文变换；磁盘会话记录是否保留原始消息由各产品的会话格式决定。

| 自动行为 | `context.autoCompactThreshold` 是触发自动压缩的上下文窗口占比，取值须大于 0 且不超过 1，默认 0.85；它是上限语义——大窗口时约 85% 就是实际触发点，较小窗口可能提前触发以留出摘要空间。内部按模型窗口用 `computeThresholds()` 算 warn/auto/hard 三级阈值，源码常量为 `DEFAULT_PCT = 0.85`、`SUMMARY_RESERVE = COMPACT_MAX_OUTPUT_TOKENS = 20_000`、`AUTOCOMPACT_BUFFER = 13_000`、`WARN_BUFFER = 20_000` 与 `HARD_BUFFER = 3_000`，算式逐字为 `effectiveWindow = Math.max(0, window - SUMMARY_RESERVE)`、`auto = absoluteCeiling > 0 ? Math.min(proportional, absoluteCeiling) : proportional`（`proportional = effectivePct * window`、`absoluteCeiling = effectiveWindow - AUTOCOMPACT_BUFFER`）、`warn = Math.max(0, auto - WARN_BUFFER)` 与 `hard = Math.min(window, Math.max(hardEdge, auto + HARD_BUFFER))`（`hardEdge = effectiveWindow - HARD_BUFFER`），因此 1,000,000 窗口的 auto 是 850,000、hard 是 977,000；源码注释把三个缓冲量写成对齐 claude-code 的 `AUTOCOMPACT_BUFFER_TOKENS`、`WARNING_THRESHOLD_BUFFER_TOKENS` 与 `MANUAL_COMPACT_BUFFER`。旧键 `model.chatCompression.contextPercentageThreshold` 已移除并被静默忽略。另有截图触发：`model.chatCompression.enableScreenshotTrigger`（默认 `true`）开启后，历史中工具返回的图片数达到 `screenshotTriggerThreshold`（默认 20）即触发一次自动压缩，与 token 占用无关，压缩会重置该计数因而不会立刻再次触发。官方设置文档没有 Subagent 级压缩阈值键，同版本 Subagent 文档也未描述 Subagent 的压缩行为。空闲一侧走的是另一条路径：`context.clearContextOnIdle` 一节（设置文档描述为 “Settings for clearing stale or oversized tool result context.
