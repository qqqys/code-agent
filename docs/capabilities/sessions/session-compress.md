# 手动压缩

[返回会话与上下文详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=session-compress)

> 核对日期：2026-10-22

## 定义

把较长的会话历史替换或折叠为摘要，使后续模型请求释放更多上下文窗口。

## 比较边界

### 本页包含

- 手动压缩命令
- 自定义压缩指令
- 自动压缩触发与阈值配置
- 空闲触发的自动压缩与缓存过期处理

### 本页不包含

- 清空会话
- 删除磁盘上的原始记录
- 仅裁剪一条工具结果

## 跨产品事实

1. 五家都提供手动压缩；自动压缩的可配置项只有 Claude Code、Codex、Qwen Code 和 Kimi Code 公布，Qoder CLI 只在术语表定义 Compaction 而没有公开阈值或开关。
2. 阈值语义分三类：Claude Code 与 Codex 配置绝对 token 数（压缩窗口或触发阈值），Qwen Code 配置上下文窗口占比（`context.autoCompactThreshold`，默认 0.85），Kimi Code 配置为模型输出预留的 token 数（`loop_control.reserved_context_size`，窗口剩余量低于它即压缩）。
3. 写法上只有 Claude Code 接受多种文本形式并公布越界处理：命令与旗标认纯 token 数（`200000`）、`k`/`M` 后缀（`500k`、`1M`）与 100–1000 的裸数字（按千计），`CLAUDE_CODE_AUTO_COMPACT_WINDOW` 自 v2.1.304 起也认后缀但不带后缀时按字面 token 数读，取值越界或不可用时告警并夹到 100K/1M 或整个忽略；Codex 的 `model_auto_compact_token_limit` 只是 `number`，官方没有公布后缀写法、取值范围或越界告警。
4. Claude Code v2.1.296 起 Subagent frontmatter 与 `--agents` 定义可写自己的 `autoCompactWindow`（100000–1000000 的纯整数），使该 Subagent 比它本来会继承的窗口更早压缩，设了 `CLAUDE_CODE_AUTO_COMPACT_WINDOW` 时该字段无效；其余四家已固定的一手资料没有 Subagent 级压缩阈值配置。
5. 只有 Claude Code 会因空闲而自动压缩：`idleCompaction` 默认开启，在交互式终端会话、走一小时提示词缓存、能取到 feature flag、上下文达到 200000 token 与约 54 分钟没有请求且机器唤醒五个条件同时满足时，赶在缓存过期前压缩，目的是让下一条消息发送摘要而不是重算整段历史。
6. Qwen Code 与 Kimi Code 都盯着同一段空闲时间但都不做摘要压缩：Qwen Code 的 `context.clearContextOnIdle` 在空闲 60 分钟后清理旧工具结果并保留最近 5 条，理由同样是让后续回合继续复用 Provider 提示词缓存；Kimi Code 的 `cache_expiry_hint` 只在 resume 或长时间空闲后发消息时提醒缓存可能过期，压缩或新建会话都由用户决定。
7. Codex 与 Qoder CLI 的公开资料没有基于空闲时间或缓存过期的触发：Codex 配置参考的压缩键只有 token 阈值、统计口径与提示词覆盖，`features.prevent_idle_sleep` 只防止机器休眠；Qoder CLI 的设置参考没有任何压缩键，发布说明的压缩条目都是失败重试与显示修复。
8. Qwen Code 另有 `/compress-fast`，它不调用模型，只移除旧工具输出和思考内容，因此与摘要压缩不是同一种处理。
9. 压缩通常是有损的上下文变换；磁盘会话记录是否保留原始消息由各产品的会话格式决定。
