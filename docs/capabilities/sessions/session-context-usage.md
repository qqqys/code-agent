# 上下文占用

[返回会话与上下文详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=session-context-usage)

> 核对日期：2026-11-28

## 定义

查看当前会话已经占用和仍可使用的模型上下文窗口，而不是只查看账号套餐或计费配额。

## 比较边界

### 本页包含

- 上下文 token 占用
- 剩余窗口
- 占用内容分类

### 本页不包含

- 账号套餐用量
- API 账单
- 仅设置模型最大上下文窗口

## 跨产品事实

1. Claude Code、Qwen Code 和 Qoder CLI 都有名为 `/context` 的专门视图（`/context [all]`、`/context` 与 `/context detail`、`/context` 面板）；Codex 与 Kimi Code 的 CLI 都没有 `/context` 命令，Codex 走 `/status` 加状态栏字段，Kimi 走 `/usage`。
2. 把占用拆到内容构成的只有三家：Claude Code 给彩色网格与优化建议，Qwen Code 的 `/context detail` 给逐条目分解，Kimi Code 合入 main 的实验性「上下文用量」按 `system`／`tool-<i>`／`message-<i>` 列出模型下一次请求会收到的每一条。Codex 的 `/status` 只给总量与剩余比例，Qoder 的 `/context` 面板在官方文档里只有 “Manage context.” 一句说明。
3. Kimi Code 自 0.37.0（2026-08-18 发布）起把 token 计数台账写进会话 wire journal，归档或关闭再 resume 后显示的上下文大小保持实测值而不回落为估算；其余四家已固定的一手资料没有描述等价的实测占用恢复机制。
4. 五家的占用数字本身都是实时会话状态、不落盘为独立文件；能保存的只是显示方式——Codex 的 `tui.status_line` 字段列表、Qoder 的 `statusLine.colors`／`statusLine.command`，以及 Kimi 桌面端与 `kimi web` 各自的 localStorage 开关 `kimi-web.context-inspector`。
5. Kimi 的实验性构成视图属桌面端与 `kimi web` 这个 Surface，CLI TUI 不在其改动范围内；把它记成 CLI 能力会跨越 Surface 边界。
