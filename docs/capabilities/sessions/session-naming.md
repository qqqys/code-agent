# 会话命名

[返回会话与上下文详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=session-naming)

> 核对日期：2026-10-28

## 定义

为持久会话设置可读名称或标题，便于在历史列表中识别和按名称恢复。

## 比较边界

### 本页包含

- 显式名称或标题
- 自动生成的触发时机与开关
- 生成引擎、输入与尝试上限
- 名称在恢复列表或 CLI 子命令中的用途

### 本页不包含

- 终端窗口标题的显示项配置
- Git 分支名
- 后台任务名称

## 跨产品事实

1. 五家都有会话命名入口：Claude Code 用 `-n`/`--name`、`/rename` 与选择器 `Ctrl+R`，Codex 用 `/rename` 与 `/new <name>`，Qwen Code 用 `/rename`（别名 `/tag`），Kimi Code 用 `/title`（别名 `/rename`），Qoder CLI 用 `-n`/`--name` 与 `/rename`。此前记录的「Qoder CLI 的 TUI 命令表未列出用户命名命令」已过期：官方 Slash 命令参考的会话管理表与 Session Management 页现在都列出 `/rename`。
2. 自动生成有三种触发方式：Qwen Code 在每记录一个助手回合后自动触发，Kimi Code 自 2.3.0 起在回合以 `completed` 结束后自动触发，Claude Code 为未命名的交互会话生成标题；Codex 的官方命令资料没有承诺自动生成，Qoder CLI 只在用户运行不带参数的 `/rename` 时生成。
3. Qwen Code 与 Kimi Code 的自动标题都是尽力而为，而且上限数字相同：每会话 3 次尝试（`AUTO_TITLE_ATTEMPT_CAP` 与 `MAX_AUTO_TITLE_ATTEMPTS`）、失败静默、后续回合可在上限内重试、都不覆盖用户手工设的名称。两家区分来源的字段名不同——Qwen Code 用 `titleSource` 的 `auto`/`manual`，Kimi Code 用 `titleKind` 的 `replaceable`/`generated`/`custom`。
4. 生成引擎各不相同：Qwen Code 用配置的 fast model 做 schema 强制的句子式标题（3–7 个词、要像 git commit subject），Kimi Code 调托管平台的 `chat_title` 工具因而要求 Kimi OAuth 登录，Claude Code 用 small/fast 模型（通常 Haiku 级）后台摘要首个提示，Qoder CLI 只写“基于当前对话自动生成”而没有公布模型或端点，Codex 没有该机制。
5. 关闭方式只有两家公布：Qwen Code 用环境变量 `QWEN_DISABLE_AUTO_TITLE`（只关自动触发，`/rename --auto` 仍可用），Kimi Code 用 `tui.toml` 与 `config.toml` 两个默认 `true` 的 `auto_session_title` 键（前者只关 TUI 的触发）；Claude Code、Codex 与 Qoder CLI 都没有公布关闭自动标题的开关。
6. 长度上限只有两家给出数字：Qwen Code 的 `SESSION_TITLE_MAX_LENGTH` 与 Kimi Code 的 `/title` 及生成标题都是 200 字符（Kimi Code 把会话标题镜像成终端窗口标题时另截到 32 字符），Qoder CLI 只写 “length-limited” 而没有数字，Claude Code 与 Codex 未公布上限。
7. 名称能当句柄用的范围只有 Claude Code 与 Codex 公布：Claude Code 的用户名称与 AI 生成标题都能传给 `claude --resume` 或 `/resume`（默认显示名不能），Codex 的名称可用于 `codex archive`、`codex unarchive` 与 `codex delete`，Qoder CLI 的恢复只认会话 ID。
8. Codex 的 `/title` 配置终端窗口标题显示项，Kimi Code 把会话标题镜像成终端窗口标题，两者都不是独立的命名入口；本字段不计终端窗口标题。
