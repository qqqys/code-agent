## 定义

查看和控制当前会话里的后台 Shell、监视器、MCP 调用、Subagent、Workflow 或定时任务等长时间工作。

## 跨产品事实

1. 四家用 `/tasks`，Codex 用 `/ps` 加 `/stop`；别名各家不同——Claude 另有 `/bashes`、Kimi 是 `/task`、Qoder 是 `/bg` 与 `/background`、Codex 的 `/stop` 是 `/clean`。
2. Claude Code v2.1.329 起把本会话的定时任务、`/loop` 唤醒、目标与本会话分支并进 `/tasks`，表头与页脚后台计数合并成一个覆盖 shells、monitors、MCP calls、agents、workflows 与 scheduled tasks 的数字。
3. Kimi Code 2.7.0 起 `/tasks` 除后台任务外还列出运行中的前台 subagent 及其活动；Qwen Code 的 `/tasks` 只输出文本清单，条目为 agent、shell、monitor 三类，交互式对话框要从页脚 Background tasks 胶囊进入。
4. 停止粒度不同：Claude 在列表里按 `x` 先询问再停止一项，Codex `/stop` 一次停掉当前会话的全部后台终端（必要时先确认），Qwen 在对话框内取消，Kimi 与 Qoder 的官方文档没有给出停止操作。
5. 可用时机与前置条件也不同：Claude 的 `/tasks` 在模型回复期间立即执行、Qwen 带 `canRunDuringStreaming: true`、Kimi「随时可用」列为「是」，而 Codex 的后台终端只在使用 `unified_exec` 时出现、否则 `/ps` 列表可能为空。

### Qwen Code

| 字段 | 记录 |
| --- | --- |
| 主命令 | `/tasks`、`/workflows p <runId>` |
| 别名 | 无公开别名 |

| 执行行为 | `/tasks` 输出后台任务文本清单：标题为 `Background tasks (<N> total)`，每条是 `[<id>] <状态>  <运行时长><pid>  <标签>` 并附可选的 `output: <路径>` 行，没有条目时输出 `No background tasks.`，交互式模式再追加一条指向页脚胶囊的提示；条目只有 agent、shell、monitor 三类，状态含 running、paused、paused (resume blocked)、completed (exit <码>)、failed 与 cancelled 并可附事件数。交互式 Background Tasks 对话框从页脚的 Background tasks 胶囊进入（空输入框按 ↓ 再按 Enter），提供逐项详情与实时更新；Workflows 开启时对话框内按 `p` 或用 `/workflows p <runId>` 协作暂停/恢复后台 Workflow 运行：暂停后不再启动新 Agent，已派发的 Agent 继续运行到收敛，Agent 调用之间的脚本代码继续执行，恢复后释放暂存结果并继续队列派发。 |
