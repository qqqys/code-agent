# 跨工具导入

[返回 Slash 命令详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=cmd-import)

> 核对日期：2026-11-11

## 定义

把其他 Agent 产品留在本机的指令文件、设置、扩展、记忆或会话数据导入当前产品，让已有的工作方式不必重建。

## 命令对照

| 产品 | 命令摘要 | 证据状态 |
| --- | --- | --- |
| Claude Code | `/import [codex\|gemini\|cursor] [--dry-run] [--yes]`、`claude import [source]` | 条件项 |
| Codex | `/import` | 官方确认 |
| Qwen Code | `/import-config [all\|claude-code\|claude-desktop] [--scope user\|project]`、`qwen memory import codex`、`qwen extensions install` | 官方确认 |
| Kimi Code | `/import-sessions`、`kimi import-sessions`、`/import-from-cc-codex` | 官方确认 |
| Qoder CLI | 无对应命令 | 未确认 |

## 比较边界

### 本页包含

- 可作为来源的其他产品
- 可导入的对象类型
- 导入入口与参数
- 数据落地位置
- 跳过或不导入的内容

### 本页不包含

- 同产品旧版本数据迁移（如 Kimi 的 `kimi migrate`）
- 产品内部配置格式升级
- 安装原生格式的扩展或插件
- 把其他产品当作后端 Agent 驱动的互操作

## 跨产品事实

1. 四家（Claude Code、Codex、Qwen Code、Kimi Code）有跨产品导入入口，只有 Qoder CLI 没有；Codex 与 Claude Code 互为导入源，形成对称关系。
2. 导入对象范围差异极大：Codex 覆盖十类对象（指令、配置、Skills、插件、MCP、Subagent、Hooks、命令、记忆、会话），Claude Code 覆盖五类且不含会话，Qwen Code 拆成 MCP、记忆、插件三条互不相通的通道，Kimi Code 拆成会话与配置两条。
3. 只有 Codex 与 Kimi Code 能导入会话历史，上限分别是最近 30 天 50 个与最近 15 天（可选 30 天）100 个，两者都在本地转换且不修改源文件。
4. 会话导入的实现路线相反：Kimi Code 把整段历史压成一条用户消息、另存完整历史附件，并明确不做 LLM 摘要；Codex 把源会话写成本地会话并在源更新后同步而不产生重复。
5. 记忆导入的来源各家只有一个且互不相同：Codex 只从 Claude Code 取项目级记忆，Qwen Code 只从 Codex 取记忆。
6. Claude Code 的 `/import` 只见于官方文档站，v2.1.322 的 `CHANGELOG.md` 对 `/import`、`claude import`、`codex` 与 `gemini` 的命中数都是 0，版本段还缺 `## 2.1.213` 一节。
