# 项目目录信任

[返回权限与沙箱详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=security-trust)

> 核对日期：2026-10-23

## 定义

把当前工作目录标记为可信或不可信，并据此决定是否加载项目配置、启用高权限模式或扩展可访问目录。

## 权限结论

| 产品 | 结论 | 证据状态 |
| --- | --- | --- |
| Claude Code | Workspace Trust；未信任时项目 `allow` 与 `additionalDirectories` 不生效 | 官方确认 |
| Codex | `projects.<path>.trust_level`；未信任时跳过项目 `.codex/` 层 | 官方确认 |
| Qwen Code | 条件：`security.folderTrust.enabled` 默认关闭，开启后才有 `/trust` | 条件项 |
| Kimi Code | 启动 `Trust this folder?` 弹窗；未信任时跳过项目层 | 官方确认 |
| Qoder CLI | Trust Directories；未信任时回退 `default` | 官方确认 |

## 比较边界

### 本页包含

- 首次目录信任与弹窗内容
- 项目层配置加载门禁
- 高权限模式与非交互入口门禁
- 信任记录保存位置与覆盖方式

### 本页不包含

- Git Safe Directory
- TLS 证书信任
- MCP Server 单独审批
- Hook 与插件来源单独信任

## 跨产品事实

1. 五家都把目录信任用作项目层加载门禁：Claude 只在信任后应用项目 `permissions.allow` 与 `additionalDirectories`，Codex 未信任项目跳过项目作用域的 `.codex/` 层（项目本地配置、Hooks 与 Rules），Qwen 未信任目录不加载项目 `.qwen/settings.json`、项目 `.env` 与项目 Hooks，Kimi 未信任工作区不加载项目层 MCP 与项目本地配置，Qoder 未信任目录强制回退 `default` 权限模式。
2. 总开关默认值相反：Qoder 的 `security.folderTrust.enabled` 默认 `true`，Qwen 的同名键默认 `false` 且关闭时一律视为受信任；Claude、Codex 与 Kimi 没有等价总开关，信任检查恒生效。
3. 信任记录五家各自保存：Claude 写 `~/.claude.json` 的 `projects["<path>"].hasTrustDialogAccepted`，Codex 写 `~/.codex/config.toml` 的 `[projects."<path>"] trust_level`，Qwen 写 `~/.qwen/trustedFolders.json`，Kimi 写应用级原子文档存储的 `workspace-trust` 作用域（官方数据位置页没有列出该文件），Qoder 写用户级 `permissions.trustDirectories`。
4. 高权限模式门禁只有三家写明：Qwen 源码在未信任目录对非 `DEFAULT`/`PLAN` 的审批模式抛 `TrustGateError`，Qoder 文档写非默认模式只在受信目录生效、否则回退 `default`，Claude 不改权限模式而是不应用项目 allow 规则；Codex 由 `trust_level = "untrusted"` 派生更严格的命令审批，Kimi 弹窗页脚明确写工具审批仍按权限设置执行。
5. 非交互入口各自处理：Claude 的 `claude -p` 与 SDK 从不弹信任对话框，`claude ultrareview`、`claude rc` 与后台会话在无法弹窗时以退出码 1 失败，`--trust-workspace` 只信任本次运行；Kimi 用 `KIMI_CODE_TRUST_WORKSPACE=1` 按进程信任且不落盘；Qwen 的 `/trust` 只在交互模式注册；Codex 与 Qoder 的官方 CLI 参考都没有目录信任旗标。
