# 浏览器账号登录

[返回模型与认证详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=auth-browser)

> 核对日期：2026-11-08

## 定义

通过浏览器或设备码完成产品账号授权，并区分账号登录与仅配置模型 Provider。

## 能力结论

| 产品 | 结论 | 证据状态 |
| --- | --- | --- |
| Claude Code | `/login` | 官方确认 |
| Codex | `codex login` · Device Code | 官方确认 |
| Qwen Code | `/auth` 首选 Qwen Account with Subscription（Qwen OAuth 设备码 + 浏览器授权，需 chat.qwen.ai Plus/Pro 订阅，v0.26.8 起）· 条件：仅交互式，非交互改用 API Key | 条件项 |
| Kimi Code | `/login` · `kimi login` | 源码确认 |
| Qoder CLI | `/login` · `qodercli login` | 官方确认 |

## 比较边界

### 本页包含

- 浏览器 OAuth、设备码与账号登录命令
- 登录结果的 CLI 使用范围
- 无浏览器登录时的明确替代入口

### 本页不包含

- 静态 API Key 的全部注入方式
- 企业 SSO 管理细节
- IDE 自身的独立登录 UI

## 跨产品事实

1. 五家现在都有产品账号登录流程；Qwen Code 的账号登录自 v0.26.8（2026-11-05 发布）起步且要求付费订阅。
2. Qwen Code 的 `/auth` 首选入口是 Qwen Account with Subscription（Qwen OAuth 浏览器授权，需 chat.qwen.ai 的有效 Plus 或 Pro 订阅）；旧免费层 Qwen OAuth 已于 2026-04-15 停止，属另一条 `qwen-oauth` 遗留通道，与新的 `qwen-subscription` 分开存储。
3. Kimi Code 的 `kimi login` 可用设备码完成 Headless 登录，Codex 另有 `--device-auth`；Qwen 订阅登录同样走 OAuth 设备码授予，但入口只在交互式 `/auth`，官方让非交互环境改用 API Key 认证。
