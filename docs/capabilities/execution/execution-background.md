# 后台任务

[返回任务执行与 Git 详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=execution-background)

> 核对日期：2026-11-26

## 定义

让 Shell、Agent 或监视器脱离当前阻塞调用继续运行，并提供查看输出、停止和完成通知。

## 比较边界

### 本页包含

- 后台 Shell 与前台转后台
- 后台 Agent、任务列表和输出读取
- 精确停止、超时与完成通知

### 本页不包含

- 跨会话定时任务
- 云端异步任务平台
- 仅把命令末尾加 `&` 的非托管进程

## 跨产品事实

1. 五家都能管理后台工作，但对象不同：Codex 公开的是后台终端，Claude、Qwen、Kimi、Qoder 还把 Agent 或任务输出纳入统一面板。
2. Qwen Code 支持 `Ctrl+B` 把已经运行的前台 Shell 提升为后台任务；Kimi Code 的前台 Bash 超时默认也会转后台继续。
3. 后台不等于无人监管：TaskOutput、任务日志、完成通知、超时和精确停止共同决定任务是否可控。
4. Kimi Code 的后台 Agent 输出原在任务终态时一次性捕获，完成前输出视图显示 `[no output captured]`；0.35.0 起 `/tasks` 预览窗格改为实时显示步骤级活动，活动记录只保存在内存、上限最近 20 步，不落盘。
5. Kimi Code 0.38.0 起提供 `WaitFor` 工具：模型在当前回合内挂起等待后台任务（子 Agent、后台 Bash、后台提问）结束，而不是结束回合等待重新调用；其余四家当前一手资料未列出同类专门的回合内等待工具。
6. Kimi Code `WaitFor` 的 `timeout` 上限由 600 秒收紧为 90 秒、并让新输入（终端 `Enter`/`Ctrl-S` steer 或等待前已排队消息）立即结束等待，这两项已随 2.2.0（2026-10-14T15:31:16Z）正式发布：2.1.1 的工具文档逐字写“上限 600”，2.2.0 与 2.7.2 逐字写“上限 90”，GitHub compare 显示 PR #4061 的提交 `20a2cea72f5d` 到 2.2.0 标签为 `behind_by: 0`。本仓库此前记录的“main 分支（尚未发布）”已作废。
7. 后台命令的墙钟上限只有三家给出数字：Claude Code 在无人值守会话里默认 30 分钟、上限 2 小时，Kimi Code 后台 Bash 默认 600 秒、硬上限 86400 秒（24 小时），Qoder CLI 自 1.1.94 起默认 10 分钟；Codex 与 Qwen Code 的后台命令都没有存活时限，Codex 的 `background_terminal_max_timeout` 只是空 `write_stdin` 轮询窗口上限，Qwen 的 `tools.shell.defaultTimeoutMs` 官方明确只管前台。
8. 「只在无人值守时设上限」目前只有 Claude Code 写进官方文档：交互终端、桌面端与 VS Code 会话的后台命令没有时限，`-p`、Agent SDK、CI 与云会话才有，且 `-p` 以文本（而非 `--input-format stream-json`）传提示词时两个默认都降为 10 分钟。Kimi Code 的方向相反——print 模式把 `bash_task_timeout_s`、`[subagent] timeout_ms` 与 `[swarm] timeout_ms` 的默认值都注入为 `0`（无超时）。Qoder CLI 与 Qwen Code 没有区分交互与非交互的公开口径。
9. 600 秒是三家共同的落点：Claude Code 的 `-p` 文本提示词运行、Kimi Code 的后台 Bash 默认（`DEFAULT_BACKGROUND_TIMEOUT_S = 10 * 60`）与 Qoder CLI 1.1.94 的新默认都是 10 分钟；但只有 Kimi Code 同时公开了硬上限（`MAX_BACKGROUND_TIMEOUT_S = 24 * 60 * 60`）与两种关闭方式（`bash_task_timeout_s = 0` 或按调用的 `disable_timeout`）。
10. 可调性分层差异明显：Claude Code 只能用 `BASH_DEFAULT_TIMEOUT_MS`（高于 1800000 才替换 30 分钟默认）与 `BASH_MAX_TIMEOUT_MS`（高于 7200000 才抬高 2 小时上限）向上抬，官方逐字写两者都不能缩短；Kimi Code 有配置键、五个 `KIMI_CODE_BACKGROUND_*` 环境变量与按调用的 `disable_timeout` 三层；Qwen Code 只有前台侧的每次调用 `timeout` 与 `tools.shell.defaultTimeoutMs`；Codex 只有轮询窗口键；Qoder CLI 未给出任何键。
11. 后台任务的数量上限只有 Codex 与 Qwen Code 给了源码常量：Codex `MAX_UNIFIED_EXEC_PROCESSES = 64`，超出按 LRU 淘汰、最近使用的 8 个受保护、持有 interaction lock 的候选被跳过、被淘进程执行 `terminate()`；Qwen Code `MAX_RETAINED_TERMINAL_SHELLS = 32` 只淘汰已终态条目的记录。Kimi Code 的 `max_running_tasks` 自 2.6.0 起从配置文档消失、agent-core-v2 的 `AgentTaskConfigSchema` 也没有该字段，只有 node-sdk 的 `BackgroundConfigSchema` 仍声明 `maxRunningTasks`，两处不一致。
12. Claude Code 的 `Monitor` 观察自 v2.1.271 起一律有截止期（默认 5 分钟、最长 30 分钟、单提示词 `-p` 最长 10 分钟），到点结束并给 Claude 一条通知以便重新布防，取代了此前无超时的 `persistent` 选项；`TaskOutput` 已在 v2.1.277 移除，改为用 `Read` 读后台任务的输出文件，而 Kimi Code 与 Qoder CLI 仍提供名为 `TaskOutput` 的工具。
