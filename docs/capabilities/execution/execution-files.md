# 文件读写

[返回任务执行与 Git 详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=execution-files)

## 定义

读取文本或媒体文件，并通过精确替换、补丁、整文件写入或 Notebook 单元编辑修改工作区内容。

## 比较边界

### 本页包含

- 文件读取、创建、覆盖和局部修改
- Notebook 或媒体文件的专用入口
- 单次读取的大小上限、超限结果与一次读完的入口
- 修改前读取、权限审批与工作区边界

### 本页不包含

- Shell 工具自身的执行、超时与后台进程管理
- 代码搜索和符号导航
- Git 暂存、提交与回退

## 跨产品事实

1. 五家都提供模型可直接调用的文件读写能力，不需要先拼接 Shell 命令。
2. Claude Code、Qwen Code 和 Qoder CLI 单独提供 Notebook 编辑工具；Kimi Code 的当前工具表把媒体读取与文本读取分开。
3. 工具名称相近不代表审批相同：只读工具通常可直接运行，写入和编辑仍受各自权限模式、工作区边界与沙箱约束。
4. 换行处理不同：Codex `apply_patch` 自 rust-v0.162.0 起无条件保留原换行（旧的归一为 LF 模式与 `apply_patch_preserve_line_endings` opt-in 开关已移除）；Qwen Code `edit` 默认检测并保留原换行风格。Claude Code、Kimi Code 与 Qoder CLI 的官方工具文档未列同类换行保留或规范化配置。
5. 写前读与过期写入保护不同：Claude Code 官方工具参考记录读后再改要求——当前会话先读取才能编辑，Claude Opus 4.6、Haiku 4.5 及更早模型始终要求先读，较新模型在读取无需权限提示且 Read 工具可用时可编辑未读文件；Kimi Code 的 staleGuard 已由 2.1.1 官方中文工具文档记录（`Write` 与 `Edit` 段各写明目标文件必须先在本会话用 `Read` 读过、文件自上次读取后在磁盘上变化即拒绝、新建文件不受限），不再是只存在于 main 分支的未发布行为；Qwen Code `edit` 以 `checkPriorRead` 强制读后再改并在写入前复核过期；Codex 与 Qoder CLI 的官方工具文档未列同类写前读强制要求。
6. 单次读取的额度口径五家各不相同：Claude Code 按 token 计（默认一次至多 25,000 token，整文件超过 256 KB 直接拒绝），自 v2.1.296 起模型可在单次调用传 `allow_large: true` 改为按会话剩余上下文窗口计量；Kimi Code 自 2.4.1 起是字符加估算 token 双上限（默认与单次可申请上限都是 100,000 字符，单次调用还在估算 token 达到 `[read] max_chars` 的四分之一即默认约 25,000 时停止，非 ASCII 每字符计 1 token、ASCII 每 4 字符计 1，调高配置 `max_chars` 同时抬高两个上限，旧的「单次可申请到 500,000 字符」作废）；Qwen Code 按行数加字符计（默认 1000 行、25,000 字符，各自设 `-1` 关闭，都需要重启），没有每次调用的放大入口；Codex 没有专用文本读取工具，文本读取走 `exec_command`/`write_stdin` 的 `max_output_tokens`（默认 10000 token）并另有 1 MiB 的保留输出硬上限；Qoder CLI 官方只写「文件过大时读取聚焦片段」，没有公布任何数值上限。
7. 超限后的可恢复性也不同：Claude Code 整文件超 token 上限时返回首页并附 `PARTIAL view` 提示、整文件超 256 KB 或分页读超 token 上限时直接报错并要求改用 `offset`/`limit` 或 Grep；Kimi Code 在状态里给出列范围与 `Next Read` 参数，单行放不下时按片段返回，2.4.1 起指定 `n_lines` 或负 `line_offset` 的范围在 `max_chars` 之内放下后仍超估算 token 上限时直接报错并给出放得下的行数与改用 Grep 的建议、不返回部分内容，一次返回整个文件且没有需要说明的情况时省略状态块；Qwen Code 把超限输出写进会话临时目录并在历史里留预览加指针，模型可用 `read_file` 取回；Codex 对 stdout 与 stderr 各自 `truncate` 到上限，保留开头、丢弃结尾且不报告截断行数。
8. 非文本读取的边界各自独立：Claude Code 拒绝超过 128 MB 的图片源（v2.1.302，更新日志与工具参考同口径）并拒绝 `.xlsx`、`.parquet`、`.heic`、`.zip` 等按二进制处理的扩展名；Kimi Code 图片与视频走 `ReadMediaFile`、官方写明文件大小上限 100 MB；Qwen Code PDF 的 `pages` 一次至多 20 页（`PDF_MAX_PAGES_PER_READ`），自 v0.26.2 起托管 Provider 场景的 `ReadFileTool` 可带 `mediaLimits` 限制内联媒体与结果字节数而标准 CLI 构造不传该参数；Codex `view_image` 声明没有字节或像素上限；Qoder CLI 没有公布媒体数值上限。

### Codex

| 字段 | 记录 |
| --- | --- |
| 矩阵结论 | 无专用文本读取工具，读取经 `exec_command`/`write_stdin`（`max_output_tokens` 默认 10000 token）· 图片用 `view_image` · 保留输出硬上限 1 MiB · `apply_patch` 无条件保留原换行（rust-v0.162.0 起） |
| 入口与工具 | 模型用统一执行工具 `exec_command` 与 `write_stdin` 读取文本文件，用 `apply_patch` 提交修改，图片用 `view_image`。固定到 rust-v0.166.0 标签提交 `6ff1e1ca3b30fc8b914720681fcf5fe62e95f856` 的工具 handler 目录（57 个条目，与此前记录的 main `f82e36592278` 逐项相同、增减均为零）里没有任何专用文本读取工具，只有 `apply_patch`、`current_time`、`get_context_remaining`、`list_available_plugins_to_install`、`mcp`、`mcp_resource`、`multi_agents`、`new_context_window`、`plan`、`request_permissions`、`request_plugin_install`、`request_user_input`、`send_message_to_user_async`、`shell`、`sleep`、`test_sync`、`tool_search`、`unified_exec`、`view_image` 与 `wait_for_environment`。 |
| 核心机制 | 读取没有独立工具，因此读取额度就是命令输出额度：`shell_spec.rs` 里声明为 `exec_command` 与 `write_stdin` 的两个工具都带 `max_output_tokens` 参数，描述逐字为 “Output token budget. Defaults to 10000 tokens; larger requests may be capped by policy.”，`registry.rs` 另按 `"exec_command" \| "shell_command"` 匹配同类调用。写入的核心路径是读取文件后提交结构化补丁；自 rust-v0.162.0 起 `apply_patch` 无条件保留原换行——旧的 `NormalizeToLf`（把更新文件归一为 LF）模式已移除，未改动行保留各自原有结尾（混合换行也能存活），插入行采用文件首个已有换行风格，文件无换行时用 LF。`view_image` 的描述逐字为 “View a local image file from the filesystem when visual inspection is needed. Use this for images already available on disk.”，参数只有必填的 `path`，`detail`（`high` 或 `original`）只在 `can_request_original_image_detail` 为真且未启用 `unified_image_budget` 时才出现。 |
| 执行行为 | 补丁在应用前后仍受当前审批预设和文件系统沙箱控制；只读模式不会允许持久修改。官方 Apply Patch 指南（Responses API harness 说明）列出 `create_file`/`update_file`/`delete_file` 三种 V4A diff 操作并由 harness 应用，未设写前读强制要求；`update_file` 上下文与文件内容不匹配时应用失败并返回如 `Error: Invalid Context` 的错误，模型据此重读文件或简化改动后重试。读取超限的行为由 exec 输出保留逻辑决定：`EXEC_OUTPUT_MAX_BYTES` 取 `DEFAULT_OUTPUT_BYTES_CAP`（`1024 * 1024`，即 1 MiB），源码注释逐字为 “Hard cap on bytes retained from exec stdout/stderr/aggregated output.”，且只有 `ExecCapturePolicy::ShellTool` 返回该上限、`FullBuffer` 一类策略返回 `None`；超限时对 stdout 与 stderr 各自调用 `truncate(max_bytes)`，因此保留开头、丢弃结尾，返回结构里的 `truncated_after_lines` 为 `None`，不报告截断发生在第几行。`MAX_EXEC_OUTPUT_DELTAS_PER_CALL = 10_000` 只限制实时增量事件条数，聚合仍收集完整输出。 |
| 运行范围 | 默认受当前工作区、额外可写目录和所选沙箱边界约束；桌面 App Worktree 会把落盘位置切到隔离目录。 |
| 后台与并发 | 文件编辑随当前 Agent 线程执行；并发 Subagent 仍共享父线程审批与沙箱边界。 |

| 入口与工具 | 模型调用 `Read`、`Write`、`Edit`；图片和视频使用 `ReadMediaFile`（文件大小上限 100 MB）。 |
| 核心机制 | `Read` 按字符加估算 token 双额度返回，参数为必填的 `path` 与可选的 `line_offset`（起始行号，负数从末尾倒数）、`column_offset`（正向读取时起始行内从 0 开始的位置）、`n_lines`（请求读取的源文件行数，省略时向文件末尾读取）与 `max_chars`（结果的字符上限，包含行号与状态信息）；2.4.1 起默认上限和单次调用可申请的最大值都是 100,000 字符，单次调用还会在估算 token 数达到配置 `[read] max_chars` 的四分之一（默认约 25,000）时停止，token 折算为每个非 ASCII 字符计 1、每 4 个 ASCII 字符计 1 并向上取整，因此中文等非 ASCII 字符较多的文本每次返回的字符更少；字符数与列偏移按显示文本的 JavaScript 字符串长度计算（常见字母与汉字各计 1，许多 emoji 计 2），列偏移不含行号前缀。`Write` 支持 overwrite/append；`Edit` 支持唯一匹配或 `replace_all`。 |
| 执行行为 | Read 默认放行，Write/Edit 默认需审批；Grep/Glob 会过滤敏感文件，写入缺失父目录时会自动创建。读取额度由 `[read]` 配置块控制，官方写明它「控制 `Read` 工具的字符额度，包含文件正文、行号和状态信息，不额外叠加行数或 UTF-8 字节数上限」，字段为 `default_max_chars`（integer，默认 `100000`，工具调用未指定 `max_chars` 时的额度）与 `max_chars`（integer，默认 `100000`，2.4.1 起由 `500000` 下调，单次调用可申请的最大额度）；两个值都必须是正整数，调用里的 `max_chars` 覆盖默认值但不会超过配置的最大值（超出时状态提示 “Requested max_chars=… was capped at the configured maximum …”），配置的默认值超过最大值时默认读取也按最大值执行；估算 token 上限只由配置的 `max_chars` 派生（源码 `tokenLimit = Math.ceil(limits.maxChars / 4)`，默认 25,000），调用参数 `max_chars` 不改变它；官方写明想让单次调用返回超过 100000 字符或约 25000 token 需要提高 `max_chars`，想让较大文档默认就一次返回、不用 Agent 主动申请更大额度再同时提高 `default_max_chars`。超额页面在组装时就地收缩而不重读文件：多行时逐行丢弃，单独一行放不下时按 token 权重切片段（ASCII 每字符 0.25、非 ASCII 每字符 1，不拆散代理对），纯 ASCII 文本因 token 折算向上取整通常触不到 token 上限、保持精确的字符分页。`Read` 优先返回完整行，官方逐字为「结果不会再被通用工具输出限制缩短」；除非一次就返回了整个文件且没有需要说明的情况，内容后附带 `<system>` 状态块，状态里给出列范围与 `Next Read` 参数因而不需要提高额度即可续读，不完整页面另附提示 “If the answer may be further on, continue with Next Read or find the section with Grep instead of answering from this page alone.”；调用指定了范围（带 `n_lines` 或负 `line_offset`）而 `max_chars` 之内放得下的行仍超过 token 上限（源码为状态预留 256 token）时，直接返回错误 “Lines X-Y are more than one Read can return (about N estimated tokens).
