# 文件读写

[返回任务执行与 Git 详情目录](./README.md) · [打开网页详情](https://qqqys.github.io/code-agent/capability.html?id=execution-files)

## 定义

读取文本或媒体文件，并通过精确替换、补丁、整文件写入或 Notebook 单元编辑修改工作区内容。

## 比较边界

### 本页包含

- 文件读取、创建、覆盖和局部修改
- Notebook 或媒体文件的专用入口
- 单次读取的大小上限、超限结果与一次读完的入口
- 修改前读取、权限审批与工作区边界

### 本页不包含

- Shell 工具自身的执行、超时与后台进程管理
- 代码搜索和符号导航
- Git 暂存、提交与回退

## 跨产品事实

1. 五家都提供模型可直接调用的文件读写能力，不需要先拼接 Shell 命令。
2. Claude Code、Qwen Code 和 Qoder CLI 单独提供 Notebook 编辑工具；Kimi Code 的当前工具表把媒体读取与文本读取分开。
3. 工具名称相近不代表审批相同：只读工具通常可直接运行，写入和编辑仍受各自权限模式、工作区边界与沙箱约束。
4. 换行处理不同：Codex `apply_patch` 自 rust-v0.162.0 起无条件保留原换行（旧的归一为 LF 模式与 `apply_patch_preserve_line_endings` opt-in 开关已移除）；Qwen Code `edit` 默认检测并保留原换行风格。Claude Code、Kimi Code 与 Qoder CLI 的官方工具文档未列同类换行保留或规范化配置。
5. 写前读与过期写入保护不同：Claude Code 官方工具参考记录读后再改要求——当前会话先读取才能编辑，Claude Opus 4.6、Haiku 4.5 及更早模型始终要求先读，较新模型在读取无需权限提示且 Read 工具可用时可编辑未读文件；Kimi Code 的 staleGuard 已由 2.1.1 官方中文工具文档记录（`Write` 与 `Edit` 段各写明目标文件必须先在本会话用 `Read` 读过、文件自上次读取后在磁盘上变化即拒绝、新建文件不受限），不再是只存在于 main 分支的未发布行为；Qwen Code `edit` 以 `checkPriorRead` 强制读后再改并在写入前复核过期；Codex 与 Qoder CLI 的官方工具文档未列同类写前读强制要求。
6. 单次读取的额度口径五家各不相同：Claude Code 按 token 计（默认一次至多 25,000 token，整文件超过 256 KB 直接拒绝），自 v2.1.296 起模型可在单次调用传 `allow_large: true` 改为按会话剩余上下文窗口计量；Kimi Code 按字符计（默认 100,000，单次调用可申请到 500,000，两个值都能在 `[read]` 配置里改）；Qwen Code 按行数加字符计（默认 1000 行、25,000 字符，各自设 `-1` 关闭，都需要重启），没有每次调用的放大入口；Codex 没有专用文本读取工具，文本读取走 `exec_command`/`write_stdin` 的 `max_output_tokens`（默认 10000 token）并另有 1 MiB 的保留输出硬上限；Qoder CLI 官方只写「文件过大时读取聚焦片段」，没有公布任何数值上限。
7. 超限后的可恢复性也不同：Claude Code 整文件超 token 上限时返回首页并附 `PARTIAL view` 提示、整文件超 256 KB 或分页读超 token 上限时直接报错并要求改用 `offset`/`limit` 或 Grep；Kimi Code 在状态里给出列范围与 `Next Read` 参数，单行放不下时按片段返回；Qwen Code 把超限输出写进会话临时目录并在历史里留预览加指针，模型可用 `read_file` 取回；Codex 对 stdout 与 stderr 各自 `truncate` 到上限，保留开头、丢弃结尾且不报告截断行数。

### Codex

| 字段 | 记录 |
| --- | --- |
| 矩阵结论 | 无专用文本读取工具，读取经 `exec_command`/`write_stdin`（`max_output_tokens` 默认 10000 token）· 图片用 `view_image` · 保留输出硬上限 1 MiB · `apply_patch` 无条件保留原换行（rust-v0.162.0 起） |
| 入口与工具 | 模型用统一执行工具 `exec_command` 与 `write_stdin` 读取文本文件，用 `apply_patch` 提交修改，图片用 `view_image`。固定到 main `f82e36592278` 的工具 handler 目录里没有任何专用文本读取工具，只有 `apply_patch`、`current_time`、`get_context_remaining`、`list_available_plugins_to_install`、`mcp`、`mcp_resource`、`multi_agents`、`new_context_window`、`plan`、`request_permissions`、`request_plugin_install`、`request_user_input`、`send_message_to_user_async`、`shell`、`sleep`、`test_sync`、`tool_search`、`unified_exec`、`view_image` 与 `wait_for_environment`。 |
| 核心机制 | 读取没有独立工具，因此读取额度就是命令输出额度：`shell_spec.rs` 里声明为 `exec_command` 与 `write_stdin` 的两个工具都带 `max_output_tokens` 参数，描述逐字为 “Output token budget. | 执行行为 | 补丁在应用前后仍受当前审批预设和文件系统沙箱控制；只读模式不会允许持久修改。官方 Apply Patch 指南（Responses API harness 说明）列出 `create_file`/`update_file`/`delete_file` 三种 V4A diff 操作并由 harness 应用，未设写前读强制要求；`update_file` 上下文与文件内容不匹配时应用失败并返回如 `Error: Invalid Context` 的错误，模型据此重读文件或简化改动后重试。读取超限的行为由 exec 输出保留逻辑决定：`EXEC_OUTPUT_MAX_BYTES` 取 `DEFAULT_OUTPUT_BYTES_CAP`（`1024 * 1024`，即 1 MiB），源码注释逐字为 “Hard cap on bytes retained from exec stdout/stderr/aggregated output.”，且只有 `ExecCapturePolicy::ShellTool` 返回该上限、`FullBuffer` 一类策略返回 `None`；超限时对 stdout 与 stderr 各自调用 `truncate(max_bytes)`，因此保留开头、丢弃结尾，返回结构里的 `truncated_after_lines` 为 `None`，不报告截断发生在第几行。`MAX_EXEC_OUTPUT_DELTAS_PER_CALL = 10_000` 只限制实时增量事件条数，聚合仍收集完整输出。 |
| 运行范围 | 默认受当前工作区、额外可写目录和所选沙箱边界约束；桌面 App Worktree 会把落盘位置切到隔离目录。 |
| 后台与并发 | 文件编辑随当前 Agent 线程执行；并发 Subagent 仍共享父线程审批与沙箱边界。 |
| Git 与平台联动 | 桌面 App 和 IDE 可展示 Diff；App Review pane 支持对改动进行暂存或回退。 |
| 状态与产物 | 结果是工作区文件修改和可审阅 Diff；不会因为生成补丁自动创建提交。 |
| 条件与边界 | 实际可写范围取决于 Read Only、Auto 等权限预设以及运行时沙箱；Cloud 任务使用远端环境。换行保留自 rust-v0.162.0（2026-10-08 发布，PR #51203 合并提交 `685270a56a96`）起为默认且唯一行为，不再需要任何开关：功能登记册把 `apply_patch_preserve_line_endings` 标记为 `Stage::Removed`（doc comment 逐字为 "Removed compatibility flag.
