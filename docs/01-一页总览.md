# 一页看懂 Claude Code、Codex、Qwen Code、Kimi Code、Qoder CLI

## 最短结论

- **Claude Code**：最像成熟的“终端工程师同事”，日常编码、Git 和扩展工作流完整。
- **Codex**：最像“安全可治理的 Agent 工作台”，CLI、IDE、App 和 Cloud 组合最强。
- **Qwen Code**：最像“开放的 Agent 平台底座”，Provider、Daemon、SDK 和多端入口最宽。
- **Kimi Code**：最像“轻快的新一代终端 Agent”，启动、TUI、视频输入和 MCP 配置有特色。
- **Qoder CLI**：最像“商业 Agent 平台的终端入口”，Subagent、Cloud Mode 和 SDK 是重点。

## 各自最值得关注的能力

### Claude Code

- `CLAUDE.md`、Auto Memory、Skills、Hooks、MCP 形成完整定制链。
- Git 提交、分支、PR 和 CI 工作流成熟。
- Terminal、IDE、Desktop、Web 之间的产品体验统一。

### Codex

- macOS/Linux/Windows 都有明确的系统级沙箱路径。
- CLI、Desktop App、Cloud Task、SDK、Hooks 和 Automations 形成平台。
- 适合并行 Agent、长任务和企业治理场景。

### Qwen Code

- 多协议 Provider 和开源框架，适合定制与私有接入。
- `qwen serve`、SDK、IDE、Desktop、IM Channel 让它不只是 CLI。
- Agent Team、Dynamic Workflow、Arena 等编排能力覆盖很宽。

### Kimi Code

- 单文件分发和毫秒级 TUI 启动是明确产品方向。
- 支持视频输入，适合把录屏或动态效果直接交给 Agent。
- `/mcp-config` 允许用对话方式配置和认证 MCP。

### Qoder CLI

- Subagent 可配置独立上下文、Prompt、工具和权限。
- `--remote` 可把任务交给 Qoder 管理的云端环境继续执行。
- Python/TypeScript Agent SDK 适合把能力嵌入脚本和平台。

## 如果你是 Qwen Code 开发者

最值得持续跟踪的不是“有没有同名命令”，而是四类体验差距：

1. Claude Code 的成熟交互和工作流收口。
2. Codex 的系统沙箱、桌面多 Agent 和企业治理。
3. Kimi Code 的启动速度、TUI 与多模态输入。
4. Qoder CLI 的云端任务、产品化 Subagent 和 SDK 使用体验。

具体建议见 [Qwen Code 产品机会](./12-Qwen-Code产品机会.md)。
