## 四类状态不要混为一谈

| 状态 | 是什么 | 典型风险 |
| --- | --- | --- |
| 当前上下文 | 本轮发给模型的消息和工具结果 | 太长后被压缩，细节可能丢失 |
| 会话历史 | 可以恢复的完整任务记录 | 恢复后工作区可能已经变化 |
| 项目指令 | 仓库长期规则和约定 | 层级冲突或内容过多 |
| 记忆 | Agent 主动保存的长期偏好/事实 | 过期、错误或跨项目污染 |

一个产品说“支持 Resume”，只能说明能重新打开记录，不能自动推出它会校验文件状态、
后台进程、权限或外部系统是否仍然一致。

## 实际使用建议

- 把稳定规则放进项目指令文件，不要依赖聊天里说过一次。
- 长任务分阶段提交或记录检查点，别把回退完全寄托在会话历史。
- 压缩上下文前，让 Agent 先总结当前目标、已验证事实和未完成项。
- 恢复旧会话时先检查分支、工作区、依赖和外部服务状态。
- 团队记忆必须允许查看、纠正和删除。

## 对 Qwen Code 的启示

Qwen Code 在 Resume、Branch、Rewind、Export、Auto Memory 和 Team Memory 上功能丰富，
下一步重点应是让状态关系可见：恢复会话时显示对应仓库、提交、运行时和后台任务；
压缩后显示保留了哪些关键事实；团队记忆显示来源、更新时间和适用范围。

这会把“功能很多”转化为“用户敢继续上次任务”。
