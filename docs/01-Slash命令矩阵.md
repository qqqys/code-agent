`/import [codex|gemini|cursor] [--dry-run] [--yes]`（跨工具导入）于 2026-11-11 补入本目录：官方命令页 `https://code.claude.com/docs/en/commands`（2026-11-11 核对，57,335 字节）第 101 行的描述逐字为 “Bring configuration from OpenAI Codex, Google Gemini CLI, or Cursor on your machine into Claude Code, including instruction files, MCP servers, commands, subagents, and skills. In non-interactive mode with `-p`, `/import` lists what it found and gives you the command that confirms the import. Add `--dry-run` to preview without writing anything, or `--yes` to skip the interactive picker. Not available on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, or Claude Platform on AWS, or through a Claude apps gateway. Also unavailable when you turn off feature-flag fetching. Importing from Cursor requires v2.1.265 or later”；CLI 参考页（51,918 字节）另有启动级子命令 `claude import [source]`，逐字为 “Start an interactive session that runs `/import` to bring configuration from other coding agents into Claude Code. Accepts the same `--dry-run` and `--yes` options as the command. … Requires Claude Code v2.1.213 or later”，官方示例 `claude import codex --dry-run`。记忆页（55,459 字节）“### Migrate instructions from other tools” 一节给出落地方式，逐字为 “You can also run `/import` to bring a supported coding agent's configuration into Claude Code, which appends a one-time copy of instruction files such as `AGENTS.md` to the matching `CLAUDE.md` and carries over MCP servers, commands, subagents, and skills.”，同节还写 `/init` 会读 Cursor 的 `.cursor/rules/` 或 `.cursorrules`、Copilot 的 `.github/copilot-instructions.md`，设 `CLAUDE_CODE_NEW_INIT=1` 后再加 `AGENTS.md`、`.devin/rules/`、`.windsurf/rules/` 或 `.windsurfrules` 与 `.clinerules`；命令页的 `/init` 行也写 “If `/init` finds OpenAI Codex or Google Gemini CLI configuration, it offers to carry it over with `/import`”。环境变量页（189,603 字节）“With fetching off, you can't:” 清单逐字列有 “Run `claude import` or the `/import` command”。这条能力只见于文档站：标签 v2.1.322（提交 `6e1e44f6433bfa17d198e932bff53373aa229eea`）的 `CHANGELOG.md`（1,193,584 字节）对 `/import`、`claude import`、`codex` 与 `gemini` 的命中数都是 0，版本段从 `## 2.1.214` 直接跳到 `## 2.1.212`、缺 `## 2.1.213` 一节，而 npm 上 `2.1.213` 发布于 2026-07-17T22:26:26.753Z、`2.1.265` 发布于 2026-09-08T19:05:16.492Z，因此引入时间只能夹逼到 2026-07-17 前后，不记具体合入提交。对象范围、平台门禁与 `/init` 的区别见[跨工具导入详情](./capabilities/commands/cmd-import.md)。

`/tasks`（后台任务列表）于 2026-11-20 按 v2.1.329 与四页官方文档复核：官方命令页（56,777 字节）该行逐字为 “View and manage background work in the current session, including subagents that have finished. Also available as `/bashes`”，即 `/bashes` 是同一命令的另一个名字，本目录按主命令 `/tasks` 收录、不单列该别名；“Run agents in parallel” 页（9,383 字节）写 `/tasks` “lists each item and lets you check on, attach to, or stop it”，Interactive mode 页（78,865 字节）另写从 `/tasks` 停止任务时 “processes that detached from the task's shell, such as ones started under `setsid` or `timeout`, stop too”（仅 macOS 与 Linux）。v2.1.329（2026-11-19T22:14:41Z 发布，`CHANGELOG.md` 提交 `f9e4d1e5753c`）把列表范围从后台 Shell 与 Subagent 扩到定时任务与目标，逐字为 “Added this session's scheduled tasks, `/loop` wakeups, the goal and this conversation's forks to `/tasks`; x stops one after asking”，并把表头与页脚后台计数合并为 “one number covering shells, monitors, MCP calls, agents, workflows and scheduled tasks”；同版把 “Exit and stop tasks” 改为结束本会话的定时任务使其不在恢复后再运行（在 Claude 回复过程中退出除外）。官方定时任务页（20,380 字节）在核对日期仍未出现 `/tasks`，管理入口写作自然语言与 `CronList`/`CronDelete`，因此列表里的定时任务能否用 `x` 停止记为未确认。列表覆盖范围、`Ctrl+B` 后台化与退出清理见[任务列表详情](./capabilities/commands/cmd-tasks.md)。

`/remote-control`、`/teleport` 与 `/desktop`（远程控制与跨端继续）于 2026-11-20 按官方命令页与 Remote Control 页复核并补上别名与参数：官方命令页 `.md` 变体（56,777 字节）三行逐字为 “Make this session available for Remote Control from claude.ai. Running it while signed out prints that Remote Control requires a claude.ai subscription and tells you how to sign in. Alias: `/rc`”、“Pull a cloud session into this terminal. Opens a picker, then fetches the branch and conversation. Also available as `/tp`. Requires a claude.ai subscription” 与 “Continue the current session in the Claude Code Desktop app. Requires macOS or x64 Windows and a Claude subscription. Alias: `/app`”，即 `/teleport` 的别名 `/tp` 是本目录此前漏记的；页首可见性说明另写 “Not every command appears for every user. Availability depends on your platform, plan, and environment. For example, `/desktop` only shows on macOS and x64 Windows when signed in with a Claude subscription”。Remote Control 页 `.md` 变体（67,871 字节）给出三条 CLI 启动方式（“The CLI offers three invocation modes; the Desktop app and VS Code use the `/remote-control` command.”，即 `claude remote-control`、`claude --remote-control` 与 `/remote-control`）、`/remote-control` 可带会话名（官方示例 `/remote-control My Project`）、首次连接前的一次性确认对话框（选 **Enable Remote Control** 才连接，选 **Never mind** 或按 Esc 则不连接且下次再问）、连接后终端显示 `/rc active` 指示器（终端过窄放不下时隐藏）且再次运行 `/remote-control` 打开状态面板给出会话 URL 与二维码并可在本地会话继续运行的前提下断开；前提为 Pro、Max、Ultra、Team 或 Enterprise 订阅且 “API keys are not supported”，Team 与 Enterprise 需 Owner 先在管理设置里打开 Remote Control 开关，Enterprise 自定义角色缺 cloud sessions 或 “Claude Code remote control” 权限时显示 `Remote Control is disabled by your organization's policy`，使用 Amazon Bedrock、Google Cloud's Agent Platform、Microsoft Foundry、把 `ANTHROPIC_BASE_URL` 指向 `api.anthropic.com` 以外主机或经企业 Claude apps gateway 登录时都不可用；自动连接由 `/config` 的 **Enable Remote Control for all sessions**（`on`／`off`／`default` 三值）或设置键 `remoteControlAtStartup` 控制，项目与 local 设置里的 `false` 生效而 `true` 被忽略；未信任目录里 `claude remote-control` 先问 `Trust <directory>? [y/N]`，标准输入或输出不是终端时以 `Workspace not trusted` 退出；`/resume` 或 `/teleport` 打开另一段对话会断开已连接的 Remote Control（分享链接检查需 v2.1.324 及以上）。同表的 `/remote-env`（“Choose the default cloud environment for cloud sessions you start from the CLI”）选的是云端环境默认值、不迁移当前会话，归[云端仓库任务](./capabilities/surfaces/surface-cloud.md)。订阅门槛、指示器与断开行为见[远程与跨端详情](./capabilities/commands/cmd-remote.md)。

#### 动态命令

动态数量取决于本机和项目内容，不能给出固定总数：

- 用户、项目和扩展 `SKILL.md`：注册为 `/<skill-name>`。
- 用户、项目和扩展 `commands/` 目录中的 Markdown/TOML：注册为对应 `/<command-name>`。
- 保存的 Workflow：功能开启后注册为 `/<workflow-name>`，仅交互式执行。
- MCP Server 暴露的 Prompt：注册为相应 Slash 命令。

实际加载顺序为：MCP Prompt → 硬编码命令 → 随产品提供的 Skill → 用户/项目/扩展 Skill → 保存的 Workflow → Markdown/TOML 命令。普通命令同名时后加载者覆盖前者；扩展命令冲突时改名为 `extensionName.commandName`。`skills.disabled` 只过滤 Skill，不会误伤同名硬编码命令或 MCP Prompt；`slashCommands.disabled` 在合并后过滤最终命令名和别名。
