# 五款 Code Agent 怎么选

[返回首页](../README.md) · [查看完整矩阵](./02-功能总矩阵.md)

没有脱离场景的“最好”。先决定你最在意什么，再看产品。

## 按场景给结论

| 场景 | 首选 | 备选 | 选择理由 |
| --- | --- | --- | --- |
| 个人开发者，想快速进入成熟终端工作流 | Claude Code | Codex | Claude Code 的日常编码、Git 和扩展体验成熟；Codex 的本地隔离更强 |
| 同时推进多个长任务 | Codex | Qwen Code | Codex App/Cloud 的多 Agent 工作台更显式；Qwen 有 Team/Workflow/Arena |
| 要开源、可改造、可自托管 | Qwen Code | Kimi Code | Qwen Code 功能面和嵌入面更完整；Kimi Code 更轻量 |
| 要接多个模型或内部模型网关 | Qwen Code | Kimi Code | Qwen 的多 Provider 是核心定位；Kimi 官方也支持兼容 Provider |
| 企业重视系统隔离和统一治理 | Codex | Claude Code | Codex 原生强调沙箱；Claude Code 有 Managed Policy |
| 要把 Agent 接进自研平台 | Qwen Code | Codex / Claude Code | Qwen 有源码、Daemon 和三种 SDK；另外两家提供官方 SDK/服务入口 |
| 本地关闭后让云端继续任务 | Qoder CLI | Codex | Qoder Cloud Mode 路径直接；Codex Cloud 适合云任务 |
| 喜欢轻量、快速 TUI 或需要视频输入 | Kimi Code | Qwen Code | Kimi Code 明确突出这两点 |
| 已在 Qoder 产品体系中 | Qoder CLI | — | 账号、CLI、Cloud、Subagent 和 SDK 一体化 |

## 按产品看适用人群

### Claude Code

适合把终端作为主工作区、希望编码、Git、MCP、Skills、Hooks 和多端协同都比较成熟的
开发者。主要取舍是模型与账号路径围绕 Claude 生态。

### Codex

适合重视本地沙箱、并行 Agent、桌面工作台和云任务的人。使用时要分清楚某个功能属于
CLI、IDE、App 还是 Cloud，避免把不同入口的能力混在一起。

### Qwen Code

适合需要开源、多 Provider、二次开发、Daemon、SDK 或企业渠道接入的团队。主要挑战
不是能力少，而是多入口、多协议和快速迭代带来的学习成本与一致性。

### Kimi Code

适合想尝试新一代轻量终端体验、单文件分发和视频输入的用户。产品仍快速演进，旧 Kimi
CLI 的资料不能不加核验地沿用。

### Qoder CLI

适合已在 Qoder 生态、需要 Cloud Mode、Subagent、权限和 Agent SDK 的团队。评估时
要关注账号、云资源、组织策略和数据边界。

## 选型时亲自跑这五个任务

1. 在一个不熟悉的中型仓库里解释一条真实业务链路；
2. 修一个有明确复现步骤的 Bug，并跑聚焦测试；
3. 做一次涉及三到五个文件的小功能；
4. 恢复昨天的会话，确认它能识别当前分支和工作区变化；
5. 用非交互模式执行同一任务，检查退出码、日志和权限。

建议记录完成率、人工接管次数、错误恢复、总耗时和实际成本。单次生成代码的观感不能
代替完整任务数据。
